# Tests for design/target-pipelines/spirv

## Intent

Tests in this bundle exercise the SPIR-V direct-emit target pipeline described in
[`docs/generated/design/target-pipelines/spirv.md`](../../../../design/target-pipelines/spirv.md):
the ordered IR-pass and emit sequence that runs when `CodeGenTarget::SPIRV` /
`CodeGenTarget::SPIRVAssembly` is the target and `shouldEmitSPIRVDirectly()` holds. Every claim
in this bundle is observed in emitted SPIR-V assembly, so each file carries a single
`//TEST:SIMPLE(filecheck=CHECK):-target spirv-asm ...` directive; cross-target probes belong to
sibling bundles and are out of scope here.

The coverage strategy walks the doc phase by phase and, for each pass or emit step whose effect
is visible in the assembly, pins the token that proves the step ran:

- **Phase A / B** — the validators that reject a program before any SPIR-V is produced
  (`checkForRecursiveFunctions`, `checkForMissingReturns`, `checkForOutOfBoundAccess`) and the
  type legalization that survives into `OpTypeMatrix`.
- **Phase C** — `legalizeByteAddressBufferOps` with `translateToStructuredBufferOps`,
  `legalizeEntryPointsForGLSL` (system-value to `gl_*` built-in lowering, the conservative-depth
  and geometry-primitive refinements), `legalizeBoolSwitchForTargetsRequiringIntSwitch`,
  `legalizeLogicalAndOr`, `legalizeImageSubscript`, `legalizeConstantBufferLoadForGLSL`,
  `moveGlobalVarInitializationToEntryPoints`, `eliminateMultiLevelBreak`, the SPIR-V-only second
  inlining pass, and `eliminatePhis` with `useRegisterAllocation = true`.
- **Phase D** — the always-emitted front matter, the entry-point and execution-mode shape,
  storage classes and resource decorations, `OpAccessChain` buffer indexing, structured control
  flow, the `OpSwitch` case-literal width rule, `Abort` lowering, the `Flat` rule for integral
  fragment inputs, and the capabilities and extensions the emitter decides on the spot
  (`ImageGatherExtended`, `Shader64BitIndexing`, `NoContraction`).
- **Gates and toggles** — the discard / demote runtime predicate, `VulkanInvertY`, and the debug
  level ladder (`-g0` / `-g1` / `-g2` / `-debug-info-include-source`).

Boundary probes accompany the smoke tests wherever the doc's claims have edges: minimum and
maximum `numthreads` shapes, first and later struct member offsets, `Binding 0` versus an
explicit `[[vk::binding]]`, every storage-buffer element width from `int8_t` to `double`, and the
integer / float constant extremes that flow through the emit path. Downstream-tool steps
(spirv-link, spirv-val, spirv-opt), bindless descriptor-heap lowering, and pass-ordering claims
are recorded under `## Untested claims` rather than approximated with a weakened CHECK.
