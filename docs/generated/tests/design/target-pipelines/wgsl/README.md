# Tests for design/target-pipelines/wgsl

## Intent

This bundle exercises the **WGSL target pipeline** documented in
[`target-pipelines/wgsl.md`](../../../../design/target-pipelines/wgsl.md). That page enumerates four
phases -- A (link and entry-point prep), B (specialization and type
legalization), C (WGSL legalization, lowering, phi elimination),
D (WGSL emit plus the optional Tint downstream) -- together with the
`RequiredLoweringPassSet` gates, the WGSL-specific runtime predicates,
and a set of "notable passes" sections that spell out
`legalizeIRForWGSL`, `legalizeCall`'s `ptr<function, T>` rule,
`specializeAddressSpaceForWGSL`, `legalizeLogicalAndOr`,
`floatNonUniformResourceIndex`, `legalizeByteAddressBufferOps` with the
WGSL option set, `eliminatePhis` with default options, and the
`WGSLSourceEmitter` module-scope-array and policy-override rules.

Almost every claim on that page is observable in **emitted WGSL text**,
so the bundle's default directive is
`//TEST:SIMPLE(filecheck=CHECK):-target wgsl -entry main -stage compute`
and the strategy is one file per claim x dimension: a basic case for each
documented shape, plus boundary probes along the axes the doc's own claims
imply (integer and float literal edges, `@workgroup_size` extremes,
`@binding` / `@group` extremes, array and matrix shapes, byte-address
offsets, atomic element types, nesting depth). Negative cases use
`//DIAGNOSTIC_TEST` and pin the `E####` code. The bundle stays compute-only
because the generation runner has no GPU, no Tint and no Dawn; the single
`-target wgsl-spirv-asm` test is gated with `requires-tool=tint` and runs
only in CI.
