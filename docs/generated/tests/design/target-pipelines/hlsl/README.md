# Tests for target-pipelines/hlsl

## Intent

Tests verify the HLSL target pipeline described in
[`docs/generated/design/target-pipelines/hlsl.md`](../../../../design/target-pipelines/hlsl.md):
the ordered IR-pass sequence run by `linkAndOptimizeIR` and
`emitEntryPointsSourceFromIR` when `CodeGenTarget::HLSL` is
requested, and the HLSL-shaped text the emit phase produces.

The bundle exercises Phase D emit invariants (the
`#pragma pack_matrix(column_major)` prelude header, the conditional
`#ifdef SLANG_HLSL_ENABLE_NVAPI` NVAPI block, `#line` directives,
`register(u|t|b|s N)` resource annotations, `[numthreads(...)]`
entry-point attributes, `SV_DispatchThreadID` semantic survival,
`cbuffer` shape, struct emission, vector spelling, `groupshared`
qualifier survival, HLSL native `AppendStructuredBuffer` /
`ConsumeStructuredBuffer` retention, and entry-point name
preservation), plus the HLSL-specific IR-pass effects
(`legalizeNonVectorCompositeSelect`, `wrapStructuredBuffersOfMatrices`
for both matrix-element StructuredBuffers and cbuffer matrices,
`lowerCombinedTextureSamplers`, `legalizeByteAddressBufferOps`
default options, `legalizeArrayReturnType`, `lowerEnumType`,
`eliminatePhis` default options, atomic-operation survival,
post-specialization `checkStaticAssert` processing, and the
HLSL-vs-GLSL non-Khronos contrast).

It also covers the emitter's named-constant discipline — the doc's
rule that the HLSL backend reconstructs a _name_ wherever HLSL's
source spelling is a name rather than baking in the integer DXC
happens to use today. That is exercised through the work-graph
`Barrier(...)` flag sets (all-bits shorthand and the `\|`-joined
per-bit list), the verbatim `[NodeLaunch("...")]` mode string
alongside the genuinely numeric `[NodeMaxDispatchGrid(...)]`, and
three of the work-graph record type names. The two profile
predicates the doc calls out are pinned at their boundaries: the
shader-model 6.1 edge at which `[shader("<stage>")]` starts being
emitted, and the 6.7 edge at which `[raypayload]` members are filled
out with both `read(...)` and `write(...)` qualifiers. The front-half
of the barrier-flag split — validation diagnosing a flag set the
emit-side name table cannot spell — has its own negative test.

The claim enumeration added below drove a further pass over the
document's concrete spellings. The texture-type composition rule is
treated as an enumeration to expand rather than a sentence to
summarize: the `RasterizerOrdered` and `Feedback` access prefixes and
the `Buffer` base shape each get their own test, as does the
zero-versus-non-zero sample-count carve-out, and the `Gather*` family
is probed on both axes of its name splice. The front matter is now
covered on both sides of its NVAPI branch — the inert guard and the
live `#define SLANG_HLSL_ENABLE_NVAPI 1` — and the `pack_matrix`
argument is pinned at both matrix-layout modes. Both halves of the
`_MatrixStorage_<...>` worked example are checked, including the
`_ColMajor` infix that only appears under `-matrix-layout-row-major`.
Four `reqSet` gate rows that do have an emit-visible consequence
(`bitcast`, `optionalType`, `matrixSwizzleStore`, `glslSSBO`) are
exercised through their lowering's output, `DescriptorHandle<T>` is
pinned as the surface behind the `descriptor_handle` capability gate,
and the two documented CLI toggles that reach the HLSL path get one
positive (`-trace-coverage-counter-width` rejecting a bad bit count
with E45113) and one negative (`-fspv-reflect` changing nothing).

The bundle stops at HLSL text: DXC, fxc, DXIL, and DXBytecode are
out of scope on the no-GPU runner, and the single `-target dxil`
directive is validated only in CI.

Coverage strategy: one test per concrete claim in the doc's Phase
A/B/C/D tables and `## Notable passes` sections that can be observed
in `slangc -target hlsl` text. The default directive is
`//TEST:SIMPLE(filecheck=CHECK):-target hlsl -entry main -stage compute`.
`non-khronos-hlsl-vs-glsl-buffer.slang` carries a second
`-target glsl` directive because its claim is specifically about
HLSL being non-Khronos; the two profile-boundary tests carry two
HLSL directives each so the below-edge and at-edge emissions are
compared in one file.

**`#hlsl-target-pipeline`**

1. Inside `linkAndOptimizeIR` the only target-enum that ever appears is `CodeGenTarget::HLSL`; the downstream binary requests `CodeGenTarget::DXIL` (DXC) and `CodeGenTarget::DXBytecode` (fxc) ride the same IR path.
2. The emitted HLSL text is wrapped into an `IArtifact` in `emitEntryPointsSourceFromIR`, and the downstream-binary requests diverge only in the downstream-compile dispatch.
3. HLSL is detected via `isD3DTarget(targetRequest)` for several internal predicate checks.
4. The sequence is not an unconditional list: a large share of the passes reachable for HLSL run only when the linked IR actually contains the construct the pass handles, as recorded by the 34 `RequiredLoweringPassSet` flags.
5. `calcRequiredLoweringPassSet` is invoked twice — once immediately after `linkIR`, once after specialization — and the flags accumulate rather than reset, so a construct seen by the first scan keeps its flag set even after specialization deletes it.
6. A `reqSet.*` entry in a Gate column means "this pass is skipped entirely on modules that never used the feature", not an optimization hint.

**`#high-level-phase-diagram`**

7. Compilation runs four phases in order: Phase A link and entry-point prep, Phase B specialization and type legalization, Phase C HLSL legalization / lowering / phi elimination, Phase D HLSL emit plus DXC or fxc.
8. Unlike Metal and WGSL, HLSL has no single legalization driver function; its target-specific transformations are spread across individual `SLANG_PASS` calls in Phases B and C.

**`#phase-d-hlsl-emit-and-downstream-tools`**

60. `CodeGenTarget::HLSL` stops at the text artifact.

**`#shape-of-the-emitted-file`**

66. The artifact is stitched together in a fixed order: front matter, then the language prelude, then `emitPreModule`, then the module code.
67. A `#pragma pack_matrix(...)` directive is emitted always, and its argument follows `CompilerOptionSet::getMatrixLayoutMode()`; under `slangc` that resolves to `column_major`.
68. Immediately before the pragma, and only when emit found an `IRRequiresNVAPIDecoration` on some instruction, the front matter emits `#define SLANG_HLSL_ENABLE_NVAPI 1` and `#define NV_HITOBJECT_USE_MACRO_API 1`.
69. `#define NV_SHADER_EXTN_SLOT` and `NV_SHADER_EXTN_REGISTER_SPACE` are added when an `IRNVAPISlotDecoration` supplies them.
70. The HLSL prelude guards its `#include "nvHLSLExtns.h"` behind `#ifdef SLANG_HLSL_ENABLE_NVAPI`, so the include is present in every artifact but inert unless the front matter defined the macro.
71. A global carrying `IRNVAPIMagicDecoration` is wrapped in `#ifndef SLANG_HLSL_ENABLE_NVAPI` so the prelude's NVAPI declarations win when the header is live.
72. Within the module text, resource types keep their HLSL native spellings rather than being renamed.
73. `_emitHLSLTextureType` composes the name from an access prefix (`RW`, `RasterizerOrdered`, `Append`, `Consume`, `Feedback`), a base shape (`Texture1D`, `Texture2D`, `Texture3D`, `TextureCube`, `Buffer`), then `MS`, then `Array`, then `<ElementType>`.
74. The sample count is appended to the composed name when it is non-zero.
75. `Texture2DArray`, `TextureCubeArray`, `Texture2DMS<T, N>` and `RWTexture1D/2D/3D` all fall out of that one composition rather than a per-variant table.
76. Samplers emit as `SamplerState` / `SamplerComparisonState`.
77. `_emitHLSLRegisterSemantic` maps `LayoutResourceKind` to the register class letter: `ConstantBuffer` to `b`, `ShaderResource` to `t`, `UnorderedAccess` to `u`, `SamplerState` to `s`.
78. An unhandled `LayoutResourceKind` is a diagnosed internal error, not a silent fallback.
79. Intrinsic method spellings are not rewritten at emit: `Sample`, `SampleLevel`, `SampleGrad`, `Load`, the `Gather*` family, `SampleCmp` and `SampleCmpLevelZero` are carried through as the `__intrinsic_asm` strings attached to their declarations.

**`#emitting-hlsl-named-constants-rather-than-integers`**

80. The HLSL backend never bakes an integer where the HLSL source spelling is a name: the IR carries the name and the emitter reconstructs the spelling.
81. `emitEntryPointAttributesImpl` writes `[shader("<stageName>")]` for DX profiles at shader model 6.1 or newer.
82. `[shader("<stageName>")]` is written unconditionally for the `node` stage, regardless of the declared profile version.
83. `[NodeLaunch("...")]` copies the string operand of `IRNodeLaunchDecoration` verbatim, so the output reads `[NodeLaunch("broadcasting")]` and never `[NodeLaunch(0)]`.
84. `[NodeMaxDispatchGrid(x, y, z)]` follows from `IRNodeMaxDispatchGridDecoration`, where the operands genuinely are integers.
85. `emitWorkGraphRecordType` emits the HLSL type name followed by an optional `<ElementType>` argument, over a ten-opcode table covering `DispatchNodeInputRecord`, `ThreadNodeInputRecord`, `GroupNodeInputRecords`, `EmptyNodeInput`, `ThreadNodeOutputRecords`, `GroupNodeOutputRecords`, `NodeOutput`, `NodeOutputArray`, `EmptyNodeOutput` and `EmptyNodeOutputArray`.
86. An opcode outside the record-type table is an internal error (`SLANG_UNEXPECTED`) rather than a silent fallback.
87. Barrier flag sets write the all-bits shorthand (`ALL_MEMORY`, `REORDER`) when the value matches it exactly, and otherwise a `|`-joined list of per-bit names.
88. Each barrier-flag helper wraps its own output in parentheses regardless of which form it took, so the flag argument always arrives parenthesised at the call site — `Barrier((ALL_MEMORY), (REORDER));`.
89. Both helpers assert that the emit-side name table covers every known flag bit and that the incoming value is a valid flag set, which is why `validateBarrierFlagsForHLSL` must run first.

**`#profile-predicates-hlsl-specific`**

110. Both profile rows resolve the profile with `getEffectiveTargetProfile(...)` at the gate itself, so a profile set through a command-line option is honored.
111. A DX profile at `ProfileVersion::DX_5_0` or earlier sets `useBitCastFromUInt = true` for byte-address buffers, since fxc and early DXC lack templated `.Load<T>`.
112. A DX profile at `ProfileVersion::DX_6_7` or newer selects `legalizeRayPayloadAccessQualifiersForHLSL`, because shader model 6.7 requires every `[raypayload]` member to carry both a `read(...)` and a `write(...)` qualifier.
113. `[shader("<stage>")]` is emitted when the profile version is `DX_6_1` or newer or the stage is `Node`; the `node` disjunct is defensive rather than reachable, because the public `node` atom already implies shader model 6.8 and the version test decides first.

**`#context-predicates-and-capability-gates`**

114. `!isSpecializationDisabled()` gates `specializeModule`, `shouldTrackLiveness()` gates the liveness markers, and `removeAvailableInDownstreamIR` gates `removeAvailableInDownstreamModuleDecorations`.
115. Target capabilities implying `cooperative_matrix` or `cooperative_vector` gate `collectCooperativeMetadata`.
116. The `descriptor_handle` atom is an alias over `glsl_spirv | _sm_6_6 | cpp | cuda | metal | wgsl`, so on an HLSL target the only disjunct that can fire is `_sm_6_6`: a DX profile at shader model 6.6 or newer turns the gate on and nothing else does.
117. The user-facing construct the `descriptor_handle` gate exists for is `DescriptorHandle<T>`, whose operations carry `[require(glsl_hlsl_spirv_wgsl, descriptor_handle)]`.

**`#hlsl-specific-runtime-predicates`**

118. `isD3DTarget(targetRequest)` gates `validateBarrierFlagsForHLSL`, `legalizeEmptyRayPayloadsForHLSL`, `legalizeNonStructParameterToStructForHLSL`, `legalizeRayPayloadAccessQualifiersForHLSL` and `legalizeLogicalAndOr`.
119. `target == CodeGenTarget::HLSL` gates the nine listed decisions, from `legalizeNonVectorCompositeSelect` through `legalizeUniformBufferLoad`.
120. HLSL, being non-Khronos, emits HLSL-shaped resource declarations where a Khronos target emits GLSL-shaped ones.

**`#loops-in-the-pipeline`**

121. HLSL has no iterative passes in `linkAndOptimizeIR`: there is no `simplifyIRForSpirvLegalization` loop and no HLSL legalization driver function to host one.
122. The two `calcRequiredLoweringPassSet` scans are not a fixed-point iteration; because the flags accumulate rather than reset, the second scan can only ever add flags, so there is nothing to converge.
123. `lowerTaggedUnionTypes` writing `requiredLoweringPassSet.reinterpret` is a forward hand-off to `lowerReinterpret` five lines later, not a re-entry into an earlier phase.

**`#legalizenonvectorcompositeselect`**

124. DXC's `select` intrinsic is only defined on vector operands, so the pass rewrites IR `select` instructions whose result type is a non-vector composite into a form DXC accepts, and an ordinary scalar ternary never triggers the walk.

**`#lowercombinedtexturesamplers`**

125. HLSL has separate `Texture2D` and `SamplerState` declarations, so the pass splits the IR's GLSL-style combined `sampler2D` into the HLSL-style separable pair.

**`#validatebarrierflagsforhlsl`**

126. The pass reports **E31117** (`invalid 'BarrierMemoryTypeFlags' value`) for the memory-type arm and **E31116** (`invalid 'BarrierSemanticFlags' value`) for the semantic arm.
127. The attached message enumerates the spellable bits with their hex values — `UAV_MEMORY` (0x1), `GROUP_SHARED_MEMORY` (0x2), `NODE_INPUT_MEMORY` (0x4), `NODE_OUTPUT_MEMORY` (0x8), `ALL_MEMORY` (0xf) — so the diagnostic doubles as the name table's documentation.
128. `linkAndOptimizeIR` returns `SLANG_FAIL` rather than continuing, because the corresponding emit path asserts validity rather than degrading.

**`#legalizeemptyraypayloadsforhlsl`**

129. The pass adds a dummy field to any empty ray-payload struct.
130. The narrower requirement recorded in the implementation is DXIL/HLSL **with NVAPI**, because the `NvInvokeHitObject` macro expects a payload argument.

**`#legalizenonstructparametertostructforhlsl`**

131. DXC requires the parameters of DXR shader stages to be struct types, so the pass wraps non-struct parameters in single-field struct types and unwraps them inside the entry point.
132. The pass also unwraps `ForceVarIntoRayPayloadStructTemporarily` instructions before `legalizeExistentialTypeLayout` removes empty struct parameters.

**`#legalizeraypayloadaccessqualifiersforhlsl`**

133. The pass walks every `[raypayload]` struct structurally rather than relying on reachability from a `TraceRay`-style call site, because a per-stage compile can otherwise reach emit with a partial qualifier set that DXC rejects.
134. The fill is always the full stage list `caller, anyhit, closesthit, miss`, and a field that already carries both sides is left untouched.
135. `[raypayload] struct HitPayload { float3 readSide : read(caller); };` emits at shader model 6.7 as `read(caller) : write(caller, anyhit, closesthit, miss)`, while at shader model 6.6 the pass does not run and no qualifiers are emitted at all.

**`#wrapstructuredbuffersofmatrices`**

136. fxc — and to a lesser extent DXC — does not respect `#pragma pack_matrix` when a `StructuredBuffer<T>` has a matrix element type, so the pass wraps such buffers in a single-field struct.
137. The wrapper struct is synthesized without a name hint, so it picks up the emitter's `_S<N>` fallback name: `RWStructuredBuffer<float4x4> outBuf;` reaches the text as `struct _S<N> { float4x4 _S<M>; };` followed by `RWStructuredBuffer<_S<N> > outBuf_<K> : register(u0)`, not as a `row_major` / `column_major` keyword on the buffer.
138. The same fallback naming rule applies to every anonymous struct the backend synthesizes, not just this pass.
139. A matrix reached through a _buffer_ element type is instead rewritten by `lowerBufferElementTypeToStorageType` into a storage struct with a single `data` field named `_MatrixStorage_<element><R>x<C>[_ColMajor][_logical]<layoutRule>`.
140. On HLSL the layout rule spells `natural`.
141. The rewrite happens only when the matrix layout differs from the compile's default; a matrix that already matches the default layout is not wrapped at all.
142. A `row_major float3x4` in a `ConstantBuffer` emits as `struct _MatrixStorage_float3x4natural_0 { float4 data_0[int(3)]; };` under the default column-major layout, and the same field declared `column_major` emits as `_MatrixStorage_float3x4_ColMajornatural_0` under `-matrix-layout-row-major`.

**`#legalizeuniformbufferload`**

143. The pass replaces every whole-object load of a `ConstantBuffer` with a struct element type by a per-field `IRFieldAddress` + `IRLoad` sequence recombined by `makeStruct`, and leaves loads whose element type is not a struct alone.
144. `kIROp_MakeStruct` is on the emitter's never-fold list, so the recombined struct materialises as a local declaration whose initializer is a brace-list — `S_0 _S1 = { gCB_0.a_0, gCB_0.b_0, gCB_0.c_0 };` — one member read per field, in field order.

**`#legalizebyteaddressbufferops-for-hlsl`**

145. HLSL uses the default options: none of `scalarizeVectorLoadStore`, `treatGetEquivalentStructuredBufferAsGetThis`, `translateToStructuredBufferOps` or `lowerBasicTypeOps` is set.
146. `useBitCastFromUInt = true` is set when targeting the fxc-era profile family DX_5_0 or earlier, because those compilers lack templated `.Load<T>` on byte-address buffers.
147. HLSL reaches the pass through the `default` arm of the first options switch, which sets nothing unless the target is CPU via LLVM.

**`#legalizelogicalandor`**

148. The pass emits no selects: for a vector operand whose element type is not `bool` it casts the operand to `vector<bool,N>` and, when the result type is likewise a non-`bool` vector, rebuilds the `And` / `Or` with a `vector<bool,N>` result and casts back.
149. A scalar `bool` `And` / `Or` falls through to the shared C-like path, which writes the infix `&&` / `||`.
150. A vector result is written as the HLSL 2021 intrinsic call `and(a, b)` / `or(a, b)` instead, which requires shader model 6.0 or newer _and_ `isTargetHLSL2018`; when either fails the emitter returns `false` and the infix operator is used after all.
151. A lowered matrix reaches emit as the `MakeArray` the pass built, so each row is its own `And` / `Or` inside an array-construction expression, rather than one whole-matrix operator.

**`#eliminatephis-with-default-options`**

152. HLSL accepts the default `PhiEliminationOptions`, so the emitted HLSL uses explicit per-branch assignments to function-local variables, which DXC then re-SSA's during its own optimizations.
153. HLSL calls `eliminatePhis` exactly once; the second call is inside the Metal-only pointer-lowering block.

**`#applyvariablescopecorrection`**

154. A use is "out of scope" when its block is dominated by the loop's break block, and the pass applies one of three repairs.
155. The first two repairs share a function-entry insertion point and surface in the emitted HLSL as a local declaration lifted to the top of the function body, ahead of the loop that computes the value, with no marker of any kind for the repair.
156. The third repair leaves no declaration at all; the instruction is simply duplicated immediately before each use.

**`#downstream-dxc--fxc`**

157. Slang emits HLSL text and delegates all validation, optimization and bytecode generation: DXC is the modern path for shader model 6.0 and newer, fxc the legacy path for 5.x and earlier.
