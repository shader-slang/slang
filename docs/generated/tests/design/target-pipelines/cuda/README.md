# Tests for design/target-pipelines/cuda

## Intent

This bundle exercises
[`docs/generated/design/target-pipelines/cuda.md`](../../../../design/target-pipelines/cuda.md),
which documents the ordered IR-pass and downstream-binary sequence Slang
runs for the CUDA target family (`CUDASource`, `CUDAHeader`, `PTX`).
The doc's claims fall into four phases plus a set of notable passes, and
the bundle mirrors that structure:

- **Phase A** — the entry-point prep arms CUDA takes that other shader
  targets do not: `collectOptiXEntryPointUniformParams` in place of
  `collectEntryPointUniformParams`, the skip of
  `moveEntryPointUniformParamsToGlobalScope` (so uniforms land in a
  `__constant__ GlobalParams` block instead of loose globals), and
  `lowerEnumType`.
- **Phase B** — specialization and type legalization, where CUDA's
  divergence is largest: the CUDA-only
  `lowerBuiltinTypesForKernelEntryPoints` / `removeTorchKernels`
  cluster, the `lowerCooperativeVectors` gate that differs between
  `CUDASource` and `CUDAHeader`, the skip of
  `lowerCombinedTextureSamplers` (CUDA is not a CPU-like artifact), the
  `performTypeInlining` / `checkGetStringHashInsts` pair that runs for
  the same reason, `checkForOutOfBoundAccess`, and
  `checkStaticAssert` running after specialization.
- **Phase C** — the three CUDA-specific passes (`synthesizeActiveMask`,
  `legalizeEntryPointVaryingParamsForCUDA`,
  `lowerImmutableBufferLoadForCUDA`) plus the arms CUDA shares with CPU
  and Metal (`undoParameterCopy`, `transformParamsToConstRef`),
  `legalizeArrayReturnType`, default-option
  `legalizeByteAddressBufferOps`, `floatNonUniformResourceIndex`, and
  default-option `eliminatePhis`.
- **Phase D** — the `CUDASourceEmitter` text contract: the prelude
  include, `extern "C" __global__` kernels, `__device__` helpers,
  `#line` directives, and the two behaviours CUDA inherits from the C++
  emitter (multi-component swizzle bases are never folded; `precise` is
  dropped with a warning).

Every claim the doc makes that is observable in `slangc -target cuda`
text is verified by a `//TEST:SIMPLE(filecheck=CHECK):-target cuda`
emission test; "is rejected" claims use `//DIAGNOSTIC_TEST`. This is a
per-target bundle, so there is no cross-target fan-out: a claim about
what the _CUDA_ pipeline emits is only observable on the CUDA target
family, and the peer targets have their own bundles under
`docs/generated/tests/design/target-pipelines/`. Where the doc names a
type, an index, or a dispatch shape, the bundle instantiates the
boundary axes for it — integer `MIN` / `MAX` / unsigned wrap, float
`0.0` / `+inf` / `NaN`, `half` largest-finite, array index `0` /
`N-1` / `N` / `-1`, `[numthreads]` at 1 and 1024, and array-return
lengths 1 and 16.

Where the doc names a `slangc` flag, the flag is exercised from the
test directive rather than left as a description: the three
coverage-instrumentation options (`-trace-coverage`,
`-trace-function-coverage`, `-trace-branch-coverage`), the two

## Claims

Enumerated per [`_claims.md` §1](../../../_meta/prompts/_claims.md), grouped by
the document's own headings.

**`#cuda-target-pipeline`** (the opening section)

1. The CUDA target family is `CUDASource`, `CUDAHeader`, and `PTX`, spelled `-target cuda` (or `cu`), `-target cuh`, and `-target ptx` on the `slangc` command line.
2. A final `PTX` request does not drive `linkAndOptimizeIR` with `CodeGenTarget::PTX`: `emitWithDownstreamForEntryPoints` maps `PTX` to `CUDASource` first, so the whole IR pipeline sees `CUDASource` and every `CUDASource`-gated arm also applies to `PTX`.
3. `CUDAHeader` is emitted the same way through the `CUDASource` IR pipeline, and all three targets share most of the IR pipeline via `isCUDATarget(targetRequest)`.
4. The backend pass list is not unconditional: a pass runs only when the linked IR contains the construct it handles, as recorded by the `Gate` column of each phase table.
5. `emitEntryPointsSourceFromIR` sets `shouldLegalizeExistentialAndResourceTypes = false` for the CUDA arm, which causes several Phase-B passes to take their `else` branches.

**`#phase-a-link-and-entry-point-prep`**

6. `collectOptiXEntryPointUniformParams` runs for `CUDASource` / `CUDAHeader` instead of `collectEntryPointUniformParams`, handling OptiX Shader Binding Table entry-point uniforms.
7. `moveEntryPointUniformParamsToGlobalScope` is skipped for `CUDASource` / `CUDAHeader`, so a uniform parameter is a field of the collected global block rather than a loose global.
8. `removeTorchAndCUDAEntryPoints` is likewise skipped for `CUDASource` / `CUDAHeader`, because their entry points are valid CUDA kernels.
9. `validateAndRemoveAssumeAddress` is invoked with `validate = false` for CUDA, in contrast with HLSL / Metal / WGSL / SPIR-V which validate.
10. `lowerGLSLShaderStorageBufferObjectsToStructuredBuffers` is gated on `!isKhronosTarget && reqSet.glslSSBO`, and CUDA is non-Khronos.
11. `instrumentCoverage` runs under `reqSet.coverageTracing`, and the coverage buffer is packed into `GlobalParams` for CUDA.
12. Coverage instrumentation is enabled by `TraceCoverage` / `TraceFunctionCoverage` / `TraceBranchCoverage` — slangc `-trace-coverage`, `-trace-function-coverage`, `-trace-branch-coverage`.
13. `finalizeCoverageInstrumentationMetadata` runs after entry-point uniform packing to fill the `uniformOffset` / `uniformStride` fields of the coverage buffer's synthetic-resource record.
14. CUDA is one of only two targets that diagnose a failure there: with no uniform layout and `isCPUTarget || isCUDATarget`, the pass emits `CoverageUniformLayoutUnavailable` — `E45105` — instead of silently leaving the record unset.
15. `lowerLValueCast` is gated on `reqSet.lValueCast`, whose producing opcodes are front-end-only so the flag cannot be a false negative.
16. `lowerEnumType` collapses an `enum` to its underlying integer, and its flag is also set by `kIROp_CastEnumToInt` / `kIROp_CastIntToEnum` / `kIROp_EnumCast`.

**`#phase-b-specialization-and-type-legalization`**

17. `generateDerivativeWrappers` runs for the CUDA / CUDAHeader / PyTorch arm if `reqSet.derivativePyBindWrapper`.
18. `lowerCooperativeVectors` runs for `CUDASource` only if the target caps do not imply `optix_coopvec`, so on OptiX targets with hardware cooperative-vector support Slang preserves the IR-level instruction.
19. `CUDAHeader` is not a named case in that switch and falls through the `default` arm, so it runs `lowerCooperativeVectors` unconditionally.
20. `lowerBuiltinTypesForKernelEntryPoints`, `removeTorchKernels`, and `handleAutoBindNames` all run for the `CUDASource` / `CUDAHeader` arm.
21. `lowerCombinedTextureSamplers` is skipped for CUDA, because a CUDA source or header artifact is `Kind::Source` with payload `CUDA` and the CPU-like predicate accepts only payload `C` or `Cpp`.
22. That same predicate is why `performTypeInlining` and `checkGetStringHashInsts` do run for CUDA.
23. `legalizeExistentialTypeLayout` and `legalizeResourceTypes` are skipped because `shouldLegalizeExistentialAndResourceTypes` is `false`, and the CPU/CUDA fallback `legalizeEmptyTypes` runs instead.
24. `inlineGlobalConstantsForLegalization` is forced for `CUDASource` (and so for a final `PTX` request); only `CUDAHeader` does not match the short-circuit.
25. `wrapStructuredBuffersOfMatrices` and `wrapCBufferElementsForMetal` are both skipped (HLSL / Metal only).
26. `finalizeAutoDiffPass` is gated on `reqSet.autodiff`, with `stripAutoDiffDecorations` running instead on the `else` arm.
27. `lowerSumVectorMatrixInsts` is gated on `reqSet.sumVectorMatrix`, whose opcodes are produced only by the autodiff transpose pass.
28. `lowerTaggedUnionTypes` is gated on `reqSet.taggedUnion`, and when it returns `true` it sets `reqSet.reinterpret`, which selects `lowerReinterpret`.
29. `lowerAppendConsumeStructuredBuffers` runs on `target != HLSL && reqSet.appendConsumeStructuredBuffer`, so it fires for CUDA.
30. `checkForOutOfBoundAccess` runs under `shouldRunNonEssentialValidation()`, rejecting an out-of-bound static array index.
31. `checkForRecursiveFunctions` runs under the same predicate and rejects a recursive function with `E55201`.
32. `lowerResultType` now runs after `lowerOptionalType`, because it depends on accurate `getAnyValueSize()` results.
33. `checkStaticAssert` is a direct call at the end of Phase B, processing `static_assert` after specialization when the information it needs is available.
34. `addUserTypeHintDecorations` has no CUDA-excluding gate and runs for CUDA whenever `VulkanEmitReflection` (slangc `-fspv-reflect`) is set.
35. Under `fastIRSimplificationOptions.minimalOptimization` — slangc `-minimum-slang-optimization` — `applySparseConditionalConstantPropagation` plus `eliminateDeadCode` replace the full `simplifyIR`, cleaning up dead branches revealed by force-inlining so dead `static_assert`s do not falsely fire.
36. `lowerUntypedResourceHandleToUInt` is gated on `reqSet.untypedResourceHandle` and ensures no untyped descriptor-heap handle survives to emit.

**`#phase-c-cuda-legalization-lowering-phi-elimination`**

37. `legalizeByteAddressBufferOps` runs with default options for CUDA, because CUDA is in the `default` arm of both byte-address-buffer switches.
38. `validateAtomicOperations` runs for every non-SPIR-V target with `skipFuncParamValidation = true`.
39. `synthesizeActiveMask` is CUDA-only and replaces implicit active-mask references with an explicit warp-mask parameter, because PTX subgroup intrinsics require an explicit thread-mask.
40. `legalizeEntryPointVaryingParamsForCUDA` is CUDA-only and restructures kernel entry-point parameters so `SV_*` varying parameters become CUDA builtin references such as `threadIdx` / `blockIdx`.
41. `floatNonUniformResourceIndex` runs for every non-SPIR-V target, so it fires for CUDA.
42. `legalizeLogicalAndOr` is filtered out for CUDA: the pass has only a four-way D3D / Khronos / WGPU / Metal arm and CUDA is none of those.
43. `legalizeImageSubscript` is filtered out for CUDA (Metal / GLSL / SPIR-V only).
44. `undoParameterCopy` runs in the CPU / CUDA / Metal arm, rewriting explicit `inout` copy-in / copy-out wrappers as pass-by-pointer.
45. `transformParamsToConstRef` runs for `isCPUTarget || isCUDATarget || isMetalTarget`, converting struct parameters to const-references.
46. `moveGlobalVarInitializationToEntryPoints` and `introduceExplicitGlobalContext` reach CUDA through the Metal/CUDA/CPP fallthrough.
47. `legalizeArrayReturnType` runs for CUDA (`!isMetalTarget && !isSPIRV`).
48. `lowerBufferElementTypeToStorageType` runs with `loweringPolicyKind = Default` for CUDA, which matches none of the WGSL / Khronos / Metal branches.
49. `lowerImmutableBufferLoadForCUDA` is the one pass in `linkAndOptimizeIR` that exists solely for this target family.
50. `eliminatePhis` runs with default options.
51. `applyVariableScopeCorrection` runs for CUDA (`target != SPIRV`).
52. `collectCooperativeMetadata` runs when the target caps imply `cooperative_matrix` or `cooperative_vector`, which the OptiX cooperative-vector capability satisfies.
53. `collectMetadata` receives the `TargetProgram`, and when the target caps imply `descriptor_handle` the preceding block forces `getOrCreateLayout(sink)` first.
54. `checkUnsupportedInst` runs unless `shouldPerformMinimumOptimizations()`.

**`#phase-d-cuda-emit-and-downstream-tools`**

55. The emitter dispatched for CUDA is `CUDASourceEmitter`, which inherits from `CPPSourceEmitter` because CUDA source is a superset of C++.
56. Multi-component swizzle bases are never folded into their use sites, because C++/CUDA has no native `.xyz` read form and the swizzle handler rebuilds the result element by element.
57. `precise` is dropped with a warning: `emitTempModifiers` diagnoses `PreciseQualifierUnsupportedOnTarget` — warning `E56005` — and returns without writing anything, so the qualifier is dropped, the temporary and its value are still emitted, and the compile continues.
58. `simplifyForEmit` runs immediately after `linkAndOptimizeIR` returns.
59. The emitted text is wrapped directly as an `IArtifact`, not through the SPIR-V-only `createArtifactFromIR` helper.
60. The `CUDASource` and `CUDAHeader` targets stop at the text artifact; only `PTX` invokes nvrtc.

**`#adjacent-targets`**

61. `PyTorchCppBinding` is the only emitter that consumes `kIROp_CudaKernelLaunch`, writing it as a `cudaLaunchKernel` call, so `-target torch` emits `AT_CUDA_CHECK(cudaLaunchKernel(...))` and no `<<<`.
62. The CUDA emitter's own kernel-launch syntax comes from `kIROp_DispatchKernel`, produced by the `__dispatch_kernel` expression keyword and by `generateCUDAWrapperForFunc`.
63. A hand-written `__dispatch_kernel` in an ordinary `[shader("compute")]` entry point is not a `[TorchEntryPoint]`, so `removeTorchKernels` never sees it and `-target cuda` emits the launch verbatim as `myKernel_0<<<make_uint3 (1U, 1U, 1U), make_uint3 (32U, 1U, 1U)>>>()`.
64. The operand order inverts: the surface is `__dispatch_kernel(fn, dispatchSize, threadGroupSize)` while `<<<...>>>` takes CUDA's grid-then-block pair.
65. OptiX never has its own `CodeGenTarget` value: it runs through `CUDASource` / `CUDAHeader` / `PTX` and is selected by stage, not by a target switch.
66. The `raytracing` capability alias is `GL_EXT_ray_tracing | _sm_6_3 | cuda`, so a ray-tracing entry point is available on this target family without extra opt-in.
67. Only two `optix_`-prefixed atoms exist and both are feature gates rather than pipeline selectors: `optix_coopvec` and `optix_multilevel_traversal`.
68. CUDA/OptiX stage coverage is narrower than other targets': it supports `anyhit` and `intersection` but not `closesthit` for the ray-object accessors.

**`#requiredloweringpassset-flags`**

69. `RequiredLoweringPassSet` is populated by `calcRequiredLoweringPassSet`, which runs twice — once after `linkIR` and once after specialization — and the flags accumulate rather than reset.
70. A gate can be stale-true (the construct was dead-code-eliminated after a scan) but never stale-false, because no pass between the last scan and the gated call site can synthesize the opcode in question.
71. Each named flag controls exactly the passes listed in the gate table.
72. `nonVectorCompositeSelect`, `existentialTypeLayout`, and `dynamicResource` exist but never gate a CUDA pass.

**`#option-set-toggles-and-emit-side-options`**

73. `ValidateUniformity` (slangc `-validate-uniformity`) gates `validateUniformity`.
74. `EmbedDownstreamIR` (slangc `-embed-downstream-ir`) gates `unexportNonEmbeddableIR`.
75. `TraceCoverageCounterByteWidth` defaults to `kDefaultCoverageCounterByteWidth = 8` and must be 4 or 8, else `linkAndOptimizeIR` diagnoses `CoverageCounterWidthBytesInvalid` (`E45114`) and fails.
76. The slangc spelling `-trace-coverage-counter-width <bits>` accepts only 32 or 64 and rejects anything else as `E45113` before that check, so `E45114` is reachable only from a host that sets the API option directly.
77. `TraceCoverageBoolean` (slangc `-trace-coverage-boolean`, off by default) records whether each entry executed with a non-atomic store of 1 instead of an exact count.

**`#context-predicates-and-capability-gates`** / **`#cuda-specific-runtime-predicates`**

78. `ArtifactDescUtil::isCpuLikeTarget(artifactDesc)` is false for CUDA; negated it selects `performTypeInlining` and `checkGetStringHashInsts`, asserted it would open the combined-texture-sampler fallthrough CUDA never takes.
79. `isCUDATarget(targetRequest)` selects the `validateAndRemoveAssumeAddress` validation skip, the shared `transformParamsToConstRef` arm, and `lowerImmutableBufferLoadForCUDA`.
80. `target == CUDASource` singled out gates the conditional `lowerCooperativeVectors` arm and the `inlineGlobalConstantsForLegalization` short-circuit.
81. The `synthesizeActiveMask` switch is the only arm inside `linkAndOptimizeIR` that names `PTX`, and it is unreachable under the ordinary downstream path.
82. CUDA is not `isD3DTarget` and is non-Khronos, so neither target family's target-specific arms apply to it.

**`#loops-in-the-pipeline`**

83. `linkAndOptimizeIR` invokes no pass more than once for CUDA; the three CUDA-specific passes are each called exactly once and there is no CUDA legalization driver the orchestrator re-runs.
84. `legalizeEntryPointVaryingParamsForCUDA` hosts an internal fixed-point loop in `inlineShaderTerminatingCalleesForRayEntryPoints`, which converges because each iteration strictly decreases the maximum call-nesting depth to a terminate.

**`#the-autodiff-gate`**

85. `finalizeAutoDiffPass` and `lowerDiffTypeInfoInsts` are both gated on `reqSet.autodiff`, a gate that matters most on CUDA because CUDA is where differentiable programming and the PyTorch bindings are used.
86. The flag's coverage is broader than "the module calls `fwd_diff` or `bwd_diff`": direct `DifferentialPair` use and a bare `no_diff` type also set it.
87. The `else` arm is not empty: it runs `stripAutoDiffDecorations` so the following DCE can drop the linked-in `[__AutoDiffBuiltin]` core-module types.

**`#collectoptixentrypointuniformparams`**

88. The pass gathers every parameter that `isVaryingParameter` reports as non-varying into one collected `struct` type and rewrites each use as a field access off `kIROp_GetOptiXSbtDataPtr`.
89. There is no opt-in attribute — the uniform/varying split is the selection rule — and varying parameters are left on the entry point, which on OptiX means exactly the ray payload and the hit attributes.

**`#synthesizeactivemask`**

90. The pass converts IR-level active-mask references into a synthesized mask parameter that flows through call sites, so the emitter need not invent mask values at code-gen time.

**`#legalizeentrypointvaryingparamsforcuda`**

91. The entry function first calls `inlineShaderTerminatingCalleesForRayEntryPoints`, then runs the ordinary `processModule`.
92. The inlining step exists because payload write-backs are inserted only in the entry point's own blocks, so a terminating call buried in an ordinary callee would otherwise terminate the ray before the payload was written back.
93. When a terminate-reaching callee cannot be flattened the pass reports `ShaderTerminatingIntrinsicInNoninlinableCallee` rather than miscompiling silently.
94. The recursive arm is shadowed in practice — a recursive callee is rejected far earlier by `checkForRecursiveFunctions` with `E55201` — so the shape that does reach the diagnostic is a terminate-reaching call `inlineCall` declines to flatten.
95. The shared base class clears `m_param` / `m_paramLayout` at the start of each entry point and routes unsupported-varying diagnostics through a location fallback to the entry-point function's `sourceLoc`.

**`#lowerbuiltintypesforkernelentrypoints-removetorchkernels-handleautobindnames`**

96. All three passes select their work by decoration, not by target, so on a CUDA compile with no `slangpy` bindings they are no-ops.
97. `lowerBuiltinTypesForKernelEntryPoints` rewrites each `[CudaKernel]` parameter whose type is a Slang builtin aggregate into a plain CUDA-representable equivalent, and calls the generated `convertLoweredToOriginal` at the top of the kernel body so the body keeps operating on the original type.
98. `removeTorchKernels` deletes every global function carrying an `IRTorchEntryPointDecoration`, so on the CUDA arm the host-side Torch entry points are dropped and the kernel side survives.
99. `handleAutoBindNames` rewrites an `[AutoPyBindCUDA]` function's `ExternCpp` name to `__kernel__<name>` and removes the autobind decoration.
100. The rewrite touches the `ExternCpp` linkage name only, which an entry point never reaches, so an `[AutoPyBindCUDA] [CudaKernel]` function compiled as the selected entry point for `-target cuda` still emits as `extern "C" __global__ void myKernel(...)` with no prefix — the rename is not observable in CUDA source text.

**`#lowerimmutablebufferloadforcuda`**

101. The pass rewrites a load whose root address `isPointerToImmutableLocation` accepts — both a plain `kIROp_Load` and a `kIROp_StructuredBufferLoad` — into CUDA's `__ldg` read-only-cache load.
102. A scalar (`float`, `half`, `double`, the sized int/uint types, `bool`, `char`) maps straight to `kIROp_CUDALDG`.
103. A vector maps directly only when it has a corresponding CUDA vector type; otherwise the pass emits one `kIROp_CUDALDG` per element and reassembles the vector.
104. Anything larger gets a generated per-type load function, name-hinted `slang_ldg`, which the emitter renders as an ordinary function call.
105. The types `createLoadFuncForType` recognizes are exactly the scalars listed above plus `kIROp_VectorType`, `kIROp_MatrixType`, `kIROp_ArrayType`, and `kIROp_StructType`.
106. Any other type op falls off the end of the switch and yields an empty `LoadMethod`, and an array or struct whose element or field walk hits one discards the half-built load function and returns empty as well.
107. The unrewritten arm therefore belongs to a load of an opaque leaf — a resource handle or a pointer — and in that case `processInst` leaves the original load exactly as it found it, making this a best-effort optimization rather than a legalization.

**`#undoparametercopy-and-transformparamstoconstref`**

108. Slang's front end emits explicit copy-in / copy-out wrappers for `inout` parameters, and `undoParameterCopy` rewrites them as pass-by-pointer, which CUDA C++ accepts directly.
109. `transformParamsToConstRef` converts struct parameters to const-references for performance.

**`#effect-of-shouldlegalizeexistentialandresourcetypes--false`**

110. CUDA's C++-based type system handles existential and resource types directly, so Slang's generic legalization would produce shapes nvrtc does not need and the CUDA emitter is not prepared to handle.
111. The `validateStructuredBufferResourceTypes` call inside the skipped block does not run.
112. The `else` branch runs `legalizeEmptyTypes` to eliminate empty types not part of the public interface, and a later unconditional call runs it again for AD 2.0 needs.

**`#eliminatephis-with-default-options`**

113. The emitted CUDA C++ uses explicit per-branch assignments to function-local variables; nvrtc applies its own SSA optimizations downstream.

**`#inlineglobalconstantsforlegalization-for-cuda`**

114. `CUDASource` always runs the inline-global-constants pass because nvrtc rejects dynamic initialization of `__device__` variables, so the constants must be inlined at every use site before emit.
115. Only `CUDAHeader` does not match the short-circuit and skips the pass.

**`#downstream-nvrtc`**

116. For `CodeGenTarget::PTX`, Slang's downstream compile path invokes nvrtc with the emitted CUDA C++ source.
117. Validation of the CUDA C++ is delegated entirely to nvrtc; Slang does not check for nvrtc-specific syntax errors.
