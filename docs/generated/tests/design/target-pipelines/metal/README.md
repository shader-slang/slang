# Tests for design/target-pipelines/metal

## Intent

This bundle exercises the Metal target pipeline described in
[`docs/generated/design/target-pipelines/metal.md`](../../../../design/target-pipelines/metal.md)
— the ordered IR-pass and emit sequence `linkAndOptimizeIR` and
`emitEntryPointsSourceFromIR` run when `CodeGenTarget::Metal` is
requested. Almost every claim the doc makes is observable in the
**emitted Metal text**, because a bare `-target metal` request stops at
the MSL source artifact and never invokes Apple's toolchain. The bundle
is therefore single-target by design: the default directive is
`//TEST:SIMPLE(filecheck=CHECK):-target metal -entry main -stage compute`,
and a second target directive appears only where the doc's claim _is_
the contrast between Metal and a sibling target
([`array-return-metal-vs-hlsl-rewrites.slang`](array-return-metal-vs-hlsl-rewrites.slang)
is the one such case).

Coverage strategy: one row per documented claim, walked along the
dimensions the doc itself commits to. The claim set is taken from the
doc's four phase sections (A: link and entry-point prep; B:
specialization and type legalization; C: Metal legalization, lowering,
phi elimination; D: Metal emit and downstream tools) plus each
`## Notable passes` subsection, which is where the doc states the
Metal-specific behaviour in enough detail to anchor a test. Boundary
probes attach to the same anchor as their parent claim: the enum
lowering is probed at the signed-`int` MAX edge and at a runtime-selected
value, integer emission at the unsigned MAX wrap, the packed-vector
buffer policy at the smallest square matrix, the literal-suffix rule at
`half`, at negative zero, at the largest finite and smallest normal float,
and at both non-finite values (infinity and NaN), the coverage
counter-width cap at both the exempt (boolean) and the warned (explicit
64-bit) ends, the `groupshared` address-space assignment at a 256-element
array, and the positional binding rule against deliberately colliding
`vk::binding` annotations.

The bundle is larger than the 20-35 files the co-located `_prompt.md`
sketches, because the source doc has grown several new claim-bearing
sections since that number was written (`printf` becoming MSL shader
logging, the `precise` drop, the literal-suffix rule, the coverage
counter-width cap, `DescriptorHandle<T>` binding emission, and the
provenance of the Metal-only opcodes). Following the claim-driven rule —
every enumerated claim ends up either covered or listed as untested —
yields the count below rather than a target being met.

Three groups of claims are covered by something other than a plain
positive emit check. `//DIAGNOSTIC_TEST` files pin the three Metal
warnings the doc names — E45115 (counter width capped), E56005
(`precise` dropped), E56107 (multisampled `SubpassLoad`) — by error
code plus, where the runner reports one, a caret-anchored span. The two
`MetalLib*` downstream steps carry `//META: requires-tool=metal-toolchain`
and are reported _ignored_ on a runner without Xcode; CI validates them.
And one test is a **regression probe against a suspected compiler bug**:
[`append-buffer-params-carry-buffer-slots.slang`](append-buffer-params-carry-buffer-slots.slang)
asserts that the two pointer parameters synthesized for an
`AppendStructuredBuffer` carry `[[buffer(N)]]` slots like every other
resource parameter. They currently do not, so the test is listed in
`_meta/expected-failures.txt` against the pending finding
`metal-append-buffer-params-missing-binding-slot`.

CHECK patterns follow the Metal-specific hygiene the doc's surface
forces: `[[kernel]]`, `[[buffer(N)]]` and friends are matched as bare
substrings because FileCheck reads a literal `[[...]]` as a variable
reference; mangled identifiers use `{{[0-9]+}}` wildcards; and the entry
function is matched as `main_0`, since Slang renames user entry points
on this target.
