# Tests for design/ir-reference/misc

## Intent

This bundle exercises the catch-all opcode catalogue in
[misc.md](../../../../design/ir-reference/misc.md) — the opcodes that no
sibling `ir-reference/` page claims. The doc now names a concrete producer
for every row (a `visit*` in `slang-lower-to-ir.cpp`, a core-module
`__intrinsic_op` declaration, a named IR pass, or **no producer at HEAD**),
so the coverage strategy follows that column: every row whose producer is
reachable from portable Slang source gets a test, and the rows produced only
by an IR pass, only by the host/Torch binding path, or by nothing at all are
enumerated under `## Untested claims` with a reason.

Two observation points are used. Opcodes that exist in the platform-neutral
IR are read out of a `-target <text-target> -dump-ir -o /dev/null` snapshot,
with patterns anchored at a user-named function and operands kept symbolic
(behind a generic, or read from a thread id) so neither the constant folder
nor DCE removes the inst before the CHECK sees it. Claims the doc states in
terms of generated code — the work-graph `Barrier` named constants, the
`base.Get(index)` record accessor, the untyped descriptor-heap casts that
"should never reach target code", and the folded `getStringHash` value — are
read out of the final text emit instead, fanned out over every target that
can express them. Value-level claims (which arm a `PackBranch` selects, what
the type predicates answer, whether two hashes agree) are checked with
`COMPARE_COMPUTE -cpu` or `INTERPRET`, because those are questions about a
result rather than about a spelling.

Sibling boundaries: `cross-cutting/ir-instructions` owns the schema, op-flag
and hoistable conventions this page's rows are described with, and
`pipeline/04-ast-to-ir` owns the general AST-node → IR-construct mapping.
This bundle stays on the specific opcodes `misc.md` catalogues, and defers to
[values.md](../../../../design/ir-reference/values.md) for the four
descriptor-_handle_ conversions that page deliberately does not list.

## Claims

Enumerated per [`_claims.md` §1](../../../_meta/prompts/_claims.md). This page is an
opcode catalogue whose columns interleave user-observable behaviour with C++-level
implementation facts (wrapper class names, builder-versus-Lua operand discrepancies,
which pass constructs a row), so the enumeration is split in two: the **U** list is
what a `//TEST` directive can reach from Slang source, and the **I** list is
internal-source facts whose only consequence is the shape of compiler C++.

### User-observable claims

**System opcodes**

1. U1 — `nop` has **no producer at HEAD**: `kIROp_Nop` occurs in `source/` only as a sentinel in op-mapping tables and comparisons, never as a constructed instruction.
2. U2 — `Unrecognized` is substituted when a serialized module names a stable opcode name this build does not define, and should not appear except immediately after deserialization.

**Capability sets**

3. U3 — A `RequireCapabilityStmt` encodes its capability set in disjunction-of-conjunctions form, with one `capabilityConjunction` built per atom set.
4. U4 — `capabilityConjunction` is an AND of capability atoms, each operand an `int` capability-atom value.
5. U5 — `capabilityDisjunction` is an OR of `capabilityConjunction` operands and is the outer level of the normal form.
6. U6 — A lone conjunction is returned directly with no `capabilityDisjunction` wrapper.
7. U7 — The encoded set is _compacted_: the minimal atom list that re-expands to the same set.
8. U8 — Both capability opcodes produce a `CapabilitySetType` value.

**Tensor and runtime helpers**

9. U9 — `makeArrayList` builds an array-list value and has **no producer at HEAD**; `IRBuilder::emitMakeArrayList` is its only producer and has no callers.
10. U10 — `allocTorchTensor` comes from core-module `TorchTensor<T>::alloc` / `emptyLike`, its operands being the extents or the tensor to imitate.
11. U11 — `TorchTensorGetView` comes from core-module `TorchTensor<T>::getView` and produces a `TensorView` over the Torch tensor in its single operand.
12. U12 — `makeTensorView` and `TorchGetCudaStream` are introduced by the PyTorch host-binding pass, the latter typed `Ptr<void>`.
13. U13 — `allocateOpaqueHandle` comes from core-module `RayQuery::__init` / `HitObject::__init`, and the call site passes exactly one operand, the destination the handle is materialized into.
14. U14 — `allocateOpaqueHandle` is emitted by lowering but never reaches a `-dump-ir` snapshot, because the mandatory `eliminateDeadCode` ahead of the `LOWER-TO-IR` dump always deletes it.
15. U15 — Both `RayQuery<0> q;` and `RayQuery<0> q = RayQuery<0>();` build the inst during lowering, and neither shows it in any dumped pass.

**Pack and expansion**

16. U16 — `Expand` expands a pattern over its captured-pack operands, and the pattern body lives in child blocks rather than in the operand list.
17. U17 — `Each` projects one slot of a pack and is produced only by the `Val`-level forms (`EachType`, `EachIntVal`, per-element witness), never by an `each` written in a value position.
18. U18 — `MakeWitnessPack` bundles witness tables into one witness-pack value typed as the matching `TypePack`.
19. U19 — `PackBranch(pack, emptyValue, nonEmptyValue)` selects between two values by whether the pack is statically empty, so no run-time length test survives.
20. U20 — `ExtractFirstFromPack(pack, witness)` returns the first slot of a non-empty pack.
21. U21 — `ExtractLastFromPack(pack, witness)` returns the last slot of a non-empty pack.
22. U22 — `TrimFirstOfPack(pack, witness)` returns a pack with the first slot removed.
23. U23 — `TrimLastOfPack(pack, witness)` returns a pack with the last slot removed.
24. U24 — `ShapeConcat(leftPack, rightPack, axis)` concatenates two pack shapes along an axis.
25. U25 — `ShapePermute(pack, order)` permutes a pack shape's dimensions, with operand 1 the order pack.
26. U26 — `ShapeSwap(pack, dim0, dim1)` swaps two dimensions of a pack shape.
27. U27 — `ShapeReduce(pack, axis)` drops one axis from a pack shape.
28. U28 — `NonEmptyPackWitness(pack)` witnesses that a pack is non-empty, one built per pack query.

**Type queries and predicates**

29. U29 — Each `__isX<T>()` helper passes `__declVal<T>()`, so the emitted inst carries the queried type in its operand's type.
30. U30 — Peephole folds a type predicate to a boolean constant once the queried type is concrete.
31. U31 — The fold unwraps a vector or matrix operand type to its element type before applying the predicate, so a scalar predicate answers for the element type.
32. U32 — `IsType(value, valueWitness, typeOperand, targetWitness?)` tests whether a value's runtime type is, or conforms to, a target type.
33. U33 — `TypeEquals(type1, type2)` is a boolean test of type equality.
34. U34 — `IsInt` is true for an integer, or for a vector/matrix of integers.
35. U35 — `IsBool` is true for `bool`, or for a vector/matrix of `bool`.
36. U36 — `IsFloat` is true for a floating-point type, or for a vector/matrix of them.
37. U37 — `IsCoopFloat` is true for a floating-point or packed float type (`fp8`, `bf16`), or for a vector/matrix of them.
38. U38 — `IsHalf` is true for `half`, or for a vector/matrix of `half`.
39. U39 — `IsUnsignedInt` is true for an unsigned integer, or for a vector/matrix of them.
40. U40 — `IsSignedInt` is true for a signed integer, or for a vector/matrix of them.
41. U41 — `IsVector` folds to `false` for every concrete type at this commit.

**Size, alignment, count**

42. U42 — `sizeof` / `alignof` emit an inst only when the natural-layout computation cannot already produce a constant; otherwise they fold to an integer literal during lowering.
43. U43 — When the surface call names only a type, the checker fills the `dataLayout` operand with `ScalarDataLayout`, so `sizeof(T)` on a generic `T` prints as `sizeOf(%T, ScalarLayout)`.
44. U44 — The two-argument `sizeof(T, L)` form takes any `IBufferDataLayout` implementation (`DefaultDataLayout`, `DefaultPushConstantDataLayout`, `Std140DataLayout`, `Std430DataLayout`, `ScalarDataLayout`, `CDataLayout`) and prints the matching layout type opcode, e.g. `sizeOf(%T, Std140Layout)`.
45. U45 — `sizeOf(type, dataLayout?)` is the compile-time byte size of the operand type under the given data layout.
46. U46 — `alignOf(baseOp, dataLayout?)` is the compile-time alignment of the operand type under the given data layout.
47. U47 — `countOf(type)` is the element count of a fixed-size array, vector, or type pack; for a value pack the operand is the pack value.
48. U48 — `GetArrayLength(array)` comes from core-module `Array<T>::getCount`, and the `GetArrayLengthExpr` AST node does _not_ produce it.

**Storage-type legalization casts**

49. U49 — `CastStorageToLogical(addr)` retypes a `Ptr<StorageType>` as a `Ptr<LogicalType>` at a buffer boundary.
50. U50 — `CastStorageToLogicalDeref(addr)` is the same conversion fused with a load, equivalent to `load(CastStorageToLogical(addr))`.
51. U51 — The fused deref form lets the pass push a conversion past a `load`, so only the extracted member is translated rather than the whole struct.
52. U52 — `MakeStorageTypeLoweringConfig(addressSpace, layoutRule, lowerToPhysicalType)` is the policy the two casts take, hoistable so identical policies dedupe.
53. U53 — The builders short-circuit to the original value, or to a plain `load`, when the storage and logical types already agree.
54. U54 — Neither cast reaches a backend: every surviving cast is rewritten into a call to a synthesized `unpackStorage` / `packStorage` function.
55. U55 — `CastUIntToUntypedResourceHandle(index)` wraps a `uint` heap index as an untyped resource handle, from `ResourceDescriptorHeap[i]`.
56. U56 — `CastUntypedResourceHandleToUInt(handle)` recovers the `uint` index in an untyped resource handle.
57. U57 — `CastUIntToUntypedSamplerHandle(index)` wraps a `uint` heap index as an untyped sampler handle, from `SamplerDescriptorHeap[j]`.
58. U58 — `CastUntypedSamplerHandleToUInt(handle)` recovers the `uint` index in an untyped sampler handle.
59. U59 — `TreatAsDynamicUniform(value)` marks a value dynamically uniform, from core-module `asDynamicUniform<T>`.
60. U60 — `GetLegalizedSPIRVGlobalParamAddr` is the legalized address of the global parameter in its single operand, for SPIR-V.

**Variable struct-wrapping legalization**

61. U61 — `ForceVarIntoStructTemporarily(var)` forces a variable to be passed as a struct temporary.
62. U62 — `ForceVarIntoRayPayloadStructTemporarily(var)` does the same and also gives the wrapper struct the `RayPayload` decoration and default payload access qualifiers.
63. U63 — The HLSL legalizer either unwraps the argument when its base type is already a `StructType`, or materializes a temporary single-field struct and copies the value back for `out`/`inout` parameters.
64. U64 — Only the payload-argument position of an HLSL ray-tracing intrinsic is rewritten; a wrapper reached any other way is left in place and survives to emit.

**Annotations**

65. U65 — `Annotation` is built with three operands — the annotated inst, an `AnnotationKind` stored as a `uint` literal, and the annotation value — so one target can carry several annotations keyed by kind.
66. U66 — `tryLookupAnnotation(target, kind)` retrieves an annotation by that key rather than by operand position.
67. U67 — Every `AnnotationKind` is differentiability-related, and `cloneAnnotations` in the IR linker skips module-scope annotations entirely for a program that does not use auto-diff.
68. U68 — `WitnessTableAnnotation` attaches a witness table to another inst and has **no producer at HEAD**.
69. U69 — `DifferentiableTypeAnnotation(baseType, witness)` would annotate a type with an `IDifferentiable` witness, but nothing constructs it.
70. U70 — `DifferentiableTypeDictionaryItem(concreteType, witness)` is one entry in autodiff's differentiable-type dictionary and has **no producer at HEAD**.

**Liveness markers**

71. U71 — `liveRangeStart` marks the beginning of a value's live range and `liveRangeEnd(referenced)` marks the end, with possibly several ends per start.
72. U72 — Both concrete children carry the marked value in operand 0.

**String hashing**

73. U73 — `getStringHash` takes exactly one operand typed `IRStringLit` and yields a stable compile-time hash of that literal's bytes.
74. U74 — An operand that did not fold to a literal is reported with `Diagnostics::GetStringHashMustBeOnStringLiteral`.
75. U75 — Because the hash is a compile-time constant, reflection and capability code can key on a string by hash without carrying the bytes to the backend.

**Kernel launch**

76. U76 — `DispatchKernel` carries `baseFn`, `threadGroupSize` and `dispatchSize` plus trailing call arguments that `IRDispatchKernel::getArgsList()` slices off.
77. U77 — `CudaKernelLaunch` is constructed and consumed in a five-operand encoding — function, `dim3` grid, `dim3` block, packed argument array, stream — rather than the six the Lua entry names.

**Work-graph records and barrier flags**

78. U78 — `nodeOutputRecordGetElementPtr(base, index)` addresses one output record as an l-value and is emitted as `base.Get(index)`.
79. U79 — `getEnumBarrierMemoryTypeFlags(flags)` turns a compile-time `BarrierMemoryTypeFlags` value into the HLSL named-constant expression for those bits.
80. U80 — `getEnumBarrierSemanticFlags(flags)` does the same for a `BarrierSemanticFlags` value.
81. U81 — HLSL output for the work-graph `Barrier()` intrinsic reads `Barrier(UAV_MEMORY, GROUP_SYNC)` rather than `Barrier(1, 1)`.
82. U82 — The emitter special-cases the whole-set values `ALL_MEMORY` and `REORDER` and otherwise joins one name per set bit with a bitwise-or.
83. U83 — The bit-to-name mapping release-asserts on an unnamed bit or a value outside the known mask, and nothing on the path derives a name from an operand index or enumerator position.
84. U84 — At emit, `tryEmitInstExprImpl` requires the flags operand to have folded to an `IRIntLit`.
85. U85 — The three work-graph value-level opcodes are HLSL-only.

**Compiler dictionary and late capability requirements**

86. U86 — `CompilerDictionary` is one memoization table that parents a single `CompilerDictionaryScope`.
87. U87 — `CompilerDictionaryScope` scopes a dictionary's entries so entries of different scopes cannot alias after hoisting.
88. U88 — `CompilerDictionaryEntry`'s operands are its key: the dictionary's scope, the memoized inst's opcode as an integer, then that inst's operands.
89. U89 — Because the entry opcode is hoistable, emitting the same key twice returns the same entry inst, so a lookup is an emit plus a check of whether the entry already has a value.
90. U90 — `CompilerDictionaryValue(value)` holds the cached result _weakly_; DCE may rewrite it to `Poison`, which `IRCompilerDictionaryEntry::getValue()` skips.
91. U91 — `LateRequireCapability(capabilitySet)` is a capability requirement checked after linking, specialization and DCE.

**Notable opcodes (callouts)**

92. U92 — An `Expand` is closer to a small nested region than an ordinary value inst: `getCaptureCount()` / `getCapture(i)` read the captured packs and `getBlocks()` the pattern body it owns as children.
93. U93 — `visitExpandExpr` gives the `Expand` region's block an `int` parameter and `visitEachExpr` projects the captured pack with `getTupleElement(pack, index)` against it, which is the form a dump of an expansion body shows.
94. U94 — `PackBranch` is emitted with two different result types: `TypeKind` from `visitPackBranchType` and `WitnessTableType` from `visitPackBranchSubtypeWitness`.
95. U95 — The `pack` operand of `PackBranch` may itself be a type pack or a value pack.
96. U96 — `maybeSpecializePackBranch` replaces the inst with operand 1 on an `Empty` verdict, with operand 2 on `NonEmpty`, and leaves it alone on `Unknown` for a later round of the fixpoint.
97. U97 — A witness pack is a pack _of_ witness tables, not a witness table over a pack.
98. U98 — `emitGetTupleElement` folds an in-range element access on a witness pack straight to the corresponding operand, and peephole rebuilds a narrower pack for the `Trim*` forms.
99. U99 — `IRBuilder::emitIsType` always passes all four operands and types the result `bool`.
100. U100 — Peephole folds the `IsType` test to `true` when the value's data type already equals `typeOperand`.
101. U101 — Every surviving `IsType` is rewritten into an equality between `getSequentialID` of the value witness and `getSequentialID` of the target witness — a witness comparison, not a type comparison.
102. U102 — Insts whose witness conforms to a COM interface type are left for the COM path instead.
103. U103 — Indexing `ResourceDescriptorHeap[i]` yields an `UntypedResourceHandle` whose value _is_ the wrapped `uint` heap index, and the concrete resource type is recovered later from the conversion target.
104. U104 — `lowerUntypedResourceHandleToUInt` forwards each cast to its `uint` operand and removes it, and peephole already folds a wrap immediately followed by an unwrap.
105. U105 — Each emitter answers a surviving untyped-handle cast with `SLANG_UNEXPECTED`, so these opcodes should never reach target code.

### Internal-source facts

106. I1 — Every opcode on this page has an `IRFoo` C++ wrapper; fiddle generates one for each opcode whose struct is not already hand-written.
107. I2 — With no explicit `struct_name` the generated wrapper name is the entry name in PascalCase with an `IR` prefix (`getStringHash` yields `IRGetStringHash`); an explicit `struct_name` wins (`allocTorchTensor` yields `IRAllocateTorchTensor`).
108. I3 — Named operand accessors are generated from the Lua operand list whether or not the struct is hand-written: `IRIsType` is declared by hand with an empty body, and its four accessors are injected into it.
109. I4 — Twelve wrappers on this page are hand-written and carry a trailing `‡`; the abstract parents `IRLiveRangeMarker` and `IRCastStorageToLogicalBase` are hand-written too but appear only in the family hierarchy.
110. I5 — `IRExpand::getBlocks()`, `IRDispatchKernel::getArgsList()` and `IRCompilerDictionaryEntry::getValue()` add behaviour the operand list cannot express, while `IRAlignOf`, `IRIsType` and `IRCompilerDictionaryValue` have empty bodies.
111. I6 — The `slang-ir-*.cpp` passes cited per opcode are deliberately not watched, so a pass newly constructing an opcode recorded as **no producer at HEAD** will not mark the page stale.
112. I7 — Only four opcodes on this page are Lua grouping parents (`CapabilitySet`, `CastStorageToLogicalBase`, `ForceVarIntoStructTemporarilyBase`, `LiveRangeMarker`); everything else is a direct child of `IRInst`.
113. I8 — The `CompilerDictionary` chain is run-time containment rather than Lua nesting: a dictionary parents its scope and an entry parents its value, while an entry reaches its scope through a key _operand_.
114. I9 — `IRCastStorageToLogicalBase` reads its two operands as `getVal()` and `getLayoutConfig()`.
115. I10 — `liveRangeStart` declares `min_operands = 2` in the Lua file while `IRBuilder::emitLiveRangeStart` constructs it with one operand; the builder shape is the one actually produced.
116. I11 — The `Expand` Lua entry names one operand while `emitExpandInst` supplies a variadic capture list, and `emitEachInst` takes an optional explicit index, passing one operand when that index is null.
117. I12 — `Annotation`'s Lua entry declares only `min_operands = 2` while `IRBuilder::addAnnotation` always builds three.
118. I13 — `CudaKernelLaunch`'s Lua entry names six operands while the builder helper and the Torch emitter both use five.
119. I14 — The barrier-flag enums are mirrored by hand in C++ and in Slang and must be kept in sync manually; the C++ `static_assert`s pin only the C++ side, so a Slang-only edit shows up as wrong HLSL output rather than a compile error.
120. I15 — `nodeOutputRecordGetElementPtr` stays on this page even though it sits in the Lua file beside `meshOutputRef`, while `getNaturalAlignment` and `makeValuePack` are deliberately absent because sibling pages own them.
121. I16 — The four descriptor-_handle_ conversions (`CastUInt64ToDescriptorHandle` and friends) are ordinary conversions owned by [values.md](../../../../design/ir-reference/values.md#conversions) and deliberately not listed on this page.
