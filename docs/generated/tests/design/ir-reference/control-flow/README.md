# Tests for design/ir-reference/control-flow

## Intent

This bundle is the per-opcode regression suite for the IR control-flow
catalog in
[`docs/generated/design/ir-reference/control-flow.md`](../../../../design/ir-reference/control-flow.md):
the `block` parent, the `param` block-parameter that stands in for SSA
`phi`, the whole `TerminatorInst` family (`return_val`, `yield`,
`unconditionalBranch`, `loop`, `ifElse`, `switch`, `targetSwitch`,
`missingReturn`, `unreachable`, `GenericAsm`), and the non-terminator
group that follows it in the instruction table (`discard`, `Printf`,
`Abort`, `StaticAssert` and the four `Require*` backend hints).

The strategy is one test per catalog row that a natural Slang surface
construct can reach, plus one test per behavioural claim in the
`## Notable opcodes` prose — in particular the two _degenerate_ `ifElse`
shapes (`falseBlock == afterBlock` for an else-less `if`,
`afterBlock == trueBlock` for a loop-condition test), the
predecessor-carries-the-argument encoding of block parameters, the
never-emitted-by-lowering status of `conditionalBranch`, the
reachability obligation that separates `missingReturn` from
`unreachable`, and the conservative side-effect classification that
keeps `discard` and `Printf` alive through DCE.

Every opcode-shape test observes `-target <text-target> -dump-ir -o
/dev/null`. Note what that snapshot is _not_: it is not the raw output of
AST lowering. `generateIRForTranslationUnit` runs a fixed mandatory pass
block — `lowerErrorHandling`, `lowerDefer`, SCCP, `simplifyCFG` and the
rest — _before_ it prints the `LOWER-TO-IR` dump, so the first snapshot
is already post-normalization. Treating it as "the IR the front end hands
off" produced three false `drift-from-source` gaps against
[control-flow.md](../../../../design/ir-reference/control-flow.md) in the
first intake cycle: `defer` already lowered, `unreachable` already
present, a third `ifElse` shape already introduced by `simplifyCFG`. In
each case the document was right and the observation was reading a later
pipeline stage than it assumed. A claim about what lowering itself
produces cannot be made from this dump; it needs the source, or a
`-dump-ir-before` of the specific pass. Conditions, loop predicates and switch scrutinees
are read from `uniform` globals so constant folding cannot collapse the
structured terminator before it is observed, and results are sunk into an
`RWStructuredBuffer` so DCE cannot remove the surrounding blocks. CHECK
patterns are anchored at `func %main` or a user-named callee to cut
through the IR-dump preamble, and cross-operand identities (break label,
merge block, asm-arm block) are asserted with FileCheck captures rather
than by trusting a literal block id. The two claims about diagnostics use
`DIAGNOSTIC_TEST`, and the two DCE-survival claims use `-O3` target text
emit, because neither is visible in an unoptimised IR snapshot.

### Family hierarchy

6. `UnconditionalBranch`, `ConditionalBranch` and `UnreachableBase` are abstract grouping entries, each becoming a contiguous opcode range so that `as<IRUnconditionalBranch>()` is a single range comparison.
7. `kIROp_FirstTerminatorInst` is `kIROp_Return` and `kIROp_LastTerminatorInst` is `kIROp_Defer`, which is exactly why `discard` — declared one line later in the Lua file — is not a terminator.

### Opcodes: block and parameters

8. `block` is a basic block whose *children*, not its operands, are the instructions it owns.
9. `param` is a block-level parameter, always the first N children of its parent block, and is Slang IR's replacement for SSA `phi` nodes.
10. `param` also originates from the `SelectExpr` / `LogicOperatorShortCircuitExpr` / `TryExpr` result parameters introduced on blocks opened by `startBlock`.

### Opcodes: terminators — returns and yields

11. `return_val(val)` is the function return and always carries exactly one operand, the void value for a `void` return.
12. `yield(val)` terminates the single block inside an `expand` instruction with that iteration's pattern value.

### Opcodes: terminators — unconditional branches

13. `unconditionalBranch(target, args...)` jumps to a target block, and operands after the first are bound to the target's `param`s.
14. `unconditionalBranch` originates from `BreakStmt` and `ContinueStmt`, plus fall-through between lowered statements.
15. `loop(target, breakBlock, continueBlock, args...)` is loop entry with the break and continue labels as explicit operands, and any further operands are target-block arguments.
16. `loop` originates from `ForStmt`, `WhileStmt`, `DoWhileStmt` and `CatchStmt`.

### Opcodes: terminators — conditional branches

17. `conditionalBranch(condition, trueBlock, falseBlock)` is a two-way branch with no structured join operand and no target arguments, and its AST origin is `(synthesized)`.
18. `ifElse(condition, trueBlock, falseBlock, afterBlock)` is the structured two-way branch whose fourth operand records the reconvergence point.
19. `ifElse` originates from `IfStmt`, plus `SelectExpr`, `LogicOperatorShortCircuitExpr`, and every loop condition test.

### Opcodes: terminators — switches

20. `switch(condition, breakLabel, defaultLabel, caseValue/caseLabel pairs...)` is the multi-way switch whose case list is a set of (value, label) pairs reached through `getCaseValue` / `getCaseLabel`.
21. `switch` originates from `SwitchStmt` (`switch`) and `StageSwitchStmt` (`__stage_switch`).
22. `targetSwitch(breakBlock, caseValue/caseBlock pairs...)` is a compile-time switch on the code-generation target whose case values are `CapabilityName` integers, not runtime values.

### Opcodes: terminators — error flow

23. `throw(value)` throws the operand as an error value, terminating the current block, and originates from `ThrowStmt`.
24. `tryCall(successBlock, failureBlock, callee, args...)` calls `callee` and branches to `successBlock` on a normal return or `failureBlock` on a throw, and originates from `TryExpr`.

### Opcodes: terminators — no-continuation

25. `missingReturn` terminates the fall-off-the-end block of a value-returning function so that a later dataflow check can diagnose it.
26. `unreachable` asserts that the block has no reachable continuation and comes from IR passes only, never AST lowering, with `applySparseConditionalConstantPropagation` the one that produces it before the first dump.

### Opcodes: terminators — defer and asm

27. `defer(deferBlock, mergeBlock, scopeBlock)` records a deferred-action block whose body must run before the surrounding scope exits, and originates from `DeferStmt`.
28. `GenericAsm(asmText, args...)` is inline target-specific text whose semantics include terminating control flow, written as the statement `__intrinsic_asm "<text>";`, with `getAsm()` reading operand 0 as a string literal.

### Opcodes: other control-flow opcodes

29. None of the rows in this table is a `TerminatorInst`: they sit outside the `kIROp_FirstTerminatorInst` / `kIROp_LastTerminatorInst` range and appear as ordinary instructions inside a block.
30. `discard` is HLSL `discard` for fragment shaders, ends pixel processing, and originates from `DiscardStmt`.
31. `gpuForeach(device, gridDims, kernel, args...)` is the host-side GPU dispatch loop that pairs with a backend-specific kernel launch, and originates from `GpuForeachStmt`.
32. `RequirePrelude(preludeText)` requires that a target-specific prelude snippet be emitted, and originates from a call to `__requirePrelude`.
33. `RequireTargetExtension(extension)` requires that a named target extension be enabled, and originates from a call to `__requireTargetExtension`.
34. `RequireComputeDerivative` (no operands) marks an entry point as needing compute-shader derivative support, and originates from a call to `__requireComputeDerivative`.
35. `StaticAssert(condition, message)` is a compile-time assertion consumed before emit, and originates from a call to `static_assert`.
36. `Printf(format, args...)` is a runtime print whose format string is operand 0 with the expanded pack following, and originates from a call to `printf`.
37. `Abort(format, args...)` terminates shader execution with a formatted message (`VK_KHR_shader_abort`), and originates from a call to `abort`.
38. `RequireMaximallyReconverges` (no operands) marks an entry point as requiring the maximally-reconverges execution mode.
39. `RequireQuadDerivatives` (no operands) marks an entry point as requiring the quad-derivatives execution mode.

### What a lowering dump shows

40. `-dump-ir` prints its first snapshot under the label `LOWER-TO-IR`, but that snapshot is not the raw output of the statement visitors: a fixed block of mandatory passes runs between the last visitor and the dump.
41. `throw`, `tryCall` and `defer` are emitted by lowering but are already gone by the first dump.
42. `unreachable` is never emitted by lowering but is already present in the first dump.
43. An arm that lowering gave a block of its own may have been folded onto the merge block by the time the first dump is printed.
44. An `AST origin` cell is a claim about which visitor *constructs* an opcode, not a promise that a dump still contains it.

### `block` and `param`

45. The first N children of a block are always `param` instructions — they declare the values that incoming branches must supply — and `IRBlock::getFirstParam` / `getParams` / `getOrdinaryInsts` rely on that ordering.
46. Instead of a `phi` opcode, the predecessor's `unconditionalBranch` carries one argument operand per `param`, and `IRUnconditionalBranch::getArgs` skips the leading label operands to find them: one for `unconditionalBranch`, three for `loop`.
47. The front end already uses this block-parameter convention rather than leaving it entirely to `constructSSA`.
48. A scalar `?:` and a short-circuiting `&&` / `||` each emit an `ifElse`, give both arms an `unconditionalBranch` carrying the arm's value, and then emit a `param` at the top of the after-block to receive it.

### `loop`

49. The leading `loop` operand is the block to enter, `breakBlock` is where control resumes after a `break` and is the structured reconvergence point of the loop, and `continueBlock` is the target of `continue` statements.
50. Any operands beyond the first three are arguments bound to the target block's `param`s.
51. `visitForStmt` registers the break and continue labels keyed by the statement's `uniqueID`, which is how `visitBreakStmt` and `visitContinueStmt` find the right label without walking the CFG.
52. `visitForStmt` creates a dedicated continue block, so target, `continueBlock` and `breakBlock` are three distinct blocks.
53. `visitWhileStmt` uses the loop head itself as the continue label and passes it as both the target and the continue operand, so *every* `while` has `target == continueBlock`.
54. `visitDoWhileStmt` uses the trailing test block instead and inverts the predicate, so a `do`-`while` leaves the loop when the *negated* test is true.
55. A `while (true)` keeps the shared head-and-continue block and leaves its break block without a predecessor, which is why that block carries `unreachable` by the time the loop is dumped.

### `ifElse`

56. The fourth operand is named `mergeBlock` in the Lua comment but `afterBlock` in the C++ wrapper; both mean the block where the two arms reconverge, and downstream consumers read it directly rather than rediscovering it from the CFG.
57. `IRBuilder::emitIf(val, trueBlock, afterBlock)` calls `emitIfElse(val, trueBlock, afterBlock, afterBlock)`, so an `if` with no `else` has `falseBlock == afterBlock`.
58. `IRBuilder::emitLoopTest(val, bodyBlock, breakBlock)` calls `emitIfElse(val, bodyBlock, breakBlock, bodyBlock)`, so a loop-condition test has `afterBlock == trueBlock`.
59. `visitIfStmt` gives an `if`/`else` three fresh blocks however empty its arms are, but the mandatory `simplifyCFG` folds away an arm that does nothing except branch to the merge block, so an `if` whose *then* arm is empty and whose `else` arm is not reaches a dump as `trueBlock == afterBlock`.

### `conditionalBranch` vs `ifElse`

60. `conditionalBranch` is the lower-level form used inside already-flattened control flow and has no structured join operand.
61. Neither opcode can pass block arguments: `IRConditionalBranch` declares exactly the three `IRUse` members `condition`, `trueBlock` and `falseBlock`, and only the `UnconditionalBranch` subfamily implements `getArgs`.
62. A predecessor that must supply a value to a block `param` therefore has to reach that block through an `unconditionalBranch`, which is what forces critical edges (`IREdge::isCritical`) to be split before block parameters can be introduced.
63. Nothing in AST lowering emits `conditionalBranch`; it is introduced by IR passes.

### `switch` and `targetSwitch`

64. `IRSwitch` stores a scrutinee, a break label, a default label and then a flat run of `(caseValue, caseLabel)` pairs that is conceptually an unordered set, so it should be read through the role-based accessors `getCaseCount()` / `getCaseValue(i)` / `getCaseLabel(i)` rather than by operand arithmetic.
65. `getCaseValueUse(i)` and `getCaseLabelUse(i)` exist alongside them because replacing a case key in place needs the `IRUse` slot so that `IRUse::set` can unregister the old operand from its use list and register the new one.
66. `legalizeBoolSwitchForTargetsRequiringIntSwitch` walks every block's terminator and, for each `IRSwitch` whose condition has `IRBoolType`, inserts a bool-to-int cast, points the condition at the cast, and rewrites each case key to the matching `IRIntLit` (`true` to 1, `false` to 0).
67. That pass release-asserts that each case key is a bool-typed `IRConstant`, because a `switch` on an `enum : bool` reaches this point with `IRIntLit` case keys of bool type rather than `IRBoolLit`.
68. The pass is selected per target in `slang-emit.cpp`.
69. `IRTargetSwitch` reads operand 0 as the break block and then `(caseValue, caseBlock)` pairs, where each case value is the integer `CapabilityName` recorded by `visitTargetSwitchStmt`.

### `tryCall` and `throw`

70. `tryCall` dispatches to one of two successor blocks depending on whether the callee returns or throws, and `IRTryCall::getArgs()` skips the three leading operands to reach the call arguments.
71. Lowering emits `tryCall` from `emitCallToVal` when the call has `TryClauseType::Standard`, then puts a `param` at the top of the success block to receive the result value and, if the enclosing code has no `CatchStmt` handler, a `param` plus a `throw` in a synthesized failure block that rethrows.
72. `visitThrowStmt` only emits `throw` when no handler is in scope; if one is, it emits an `unconditionalBranch` to the handler block carrying the error value as a block argument.
73. `lowerErrorHandling`, called before the first `-dump-ir` snapshot, rewrites a throwing function into one that returns a `Result<T, E>` value and turns each `tryCall` into an ordinary `call` plus an `ifElse`.
74. A surface program's error flow therefore reaches every later reader as the `Result` opcodes (`makeResultValue`, `makeResultError`, `isResultError`, `getResultError`, `getResultValue`) rather than as `throw` and `tryCall`.

### `defer`

75. `defer`'s three operands are read by role through `getDeferBlock()`, `getMergeBlock()` and `getScopeBlock()`, and `scopeBlock` is whatever `context->scopeEndBlock` was, which is how the deferred body learns which enclosing scope it belongs to.
76. `lowerDefer` rewrites the construct so that later passes need not be aware of it, and runs ahead of the first `-dump-ir` snapshot, so `defer` is not visible even there.

### `missingReturn` and `unreachable`

77. Both `missingReturn` and `unreachable` are `UnreachableBase` terminators with no operands, and the difference is which one the compiler is allowed to complain about.
78. When a function body's final block is still unterminated, a `void`-returning function gets an implicit `return_val` of the void value, but a value-returning function gets `missingReturn`.
79. `checkForMissingReturns` reports at the `missingReturn`'s own source location, which lands on the function signature rather than on the body.
80. It reports warning 41010 (`missing-return`, "non-void function does not return in all cases") where the target tolerates a missing return, and error 41009 (`missing-return-error`) where it does not.
81. Nothing in AST lowering emits `unreachable` — `slang-lower-to-ir.cpp` never calls `emitUnreachable`.
82. SCCP gives a block that still has uses but has lost all its predecessors a body of exactly one `unreachable`, which is what terminates the synthesized break block of a `switch`, a `__target_switch`, or a `while (true)` whose arms all diverge.

### Unreachable-code diagnostics come from lowering

83. Two `Diagnostics::UnreachableCode` sites live in `slang-lower-to-ir.cpp`, not in the semantic checker.
84. `startBlockIfNeeded` is called before lowering each statement, and if the current block is already terminated it diagnoses and then starts a fresh block anyway.
85. `lowerSwitchCases` diagnoses a statement that appears inside a `switch` body before the first `case` or `default` label, and sets `warnedUnreachableBeforeFirstCase` so that the whole leading run warns once.

### `discard`

86. `discard` is the HLSL fragment-shader instruction that ends pixel processing without running later stages.
87. Although it terminates the pixel's *runtime* processing, `discard` is not an IR terminator: its opcode is one past `kIROp_LastTerminatorInst`, so `as<IRTerminatorInst>` rejects it, and it sits as an ordinary instruction inside a block that ends with whatever real terminator follows.
88. `visitDiscardStmt` emits nothing but the `discard`, so in the common `if (...) discard;` shape the hosting block reads `discard` followed by the `unconditionalBranch` to the post-`if` merge block.
89. Reaching `discard` from a non-fragment entry point is not an IR-level error at all: the capability check rejects the entry point first, with error 36107 ("unavailable features in entry point") reported on the entry-point declaration, so no `discard` opcode is ever built.

### `Abort`

90. `Abort` lowers from the `abort(format, args...)` builtin — an `__intrinsic_op($(kIROp_Abort))` declared in `hlsl.meta.slang` — and backs the `VK_KHR_shader_abort` extension.
91. As emitted by the front end `Abort` carries the format string plus a variadic argument pack, and SPIR-V legalization later repacks that tail into a single message-struct operand.
92. Like `discard`, `Abort` is not an IR `TerminatorInst`: it sits in the post-`TerminatorInst` backend-hint group with `Printf`.

### Moving and deleting control-flow instructions

93. Whether a pass may delete or relocate one of these instructions is governed by `IRInst::mightHaveSideEffects`, which takes two defaulted parameters: a `SideEffectAnalysisOptions options` and a `Dictionary<IRInst*, bool>* calleeSideEffectCache`.
94. Neither the terminators nor `discard`, `Printf` or `Abort` has a case in that function's `switch`, so they land in the conservative `default:` arm and report `true`, which is what keeps dead-code elimination from removing them.
95. The `calleeSideEffectCache` memo exists for the one case that does need analysis, `kIROp_Call`; without it each call-site query re-walks the callee's use list, which is quadratic in the number of call sites to a shared callee.
96. Sharing the memo is valid only while no pass adds an `IRAnnotation` or removes a purity decoration, because both mutations can turn a cached `false` into a wrong answer.
97. `simplifyIR` clears the memo at the top of each outer iteration, so each iteration also picks up the purity facts `propagateFuncProperties` proved in the previous one.
