# Tests for design/ir-reference/structure

## Intent

This bundle is the per-opcode regression suite for the IR structural /
hierarchy family catalogued in
[structure.md](../../../../design/ir-reference/structure.md): the opcodes that
organize a module rather than compute a value — `func`, `generic`, `call`,
`param` in its function-signature role, `global_var`, `global_param`,
`globalConstant`, `global_generic_param`, `global_hashed_string_literals`,
`struct` / `class` with their `field` and `key` children, `indexedFieldKey`,
`interface` with its `interface_req_entry` operands, `witness_table` with its
`witness_table_entry` children, `thisTypeWitness`, `TypeEqualityWitness`,
`lookupWitness` as the structural consumer of a table, and `SymbolAlias`.

Every claim in the catalog is of the form "AST declaration X produces
structural opcode Y in parent/child shape Z", which is a pre-codegen
observation, so the whole bundle uses one directive shape —
`-target spirv-asm -dump-ir -o /dev/null -entry main -stage compute` — and
FileCheck reads the IR dump. There is deliberately **no** per-target emission
fan-out: none of these claims is target-dependent, and repeating the same
`-dump-ir` observation under `-target metal` / `-target wgsl` would assert
identical pre-backend text. CHECK patterns are anchored at user-named
top-level symbols (`func %addPair`, `struct %Point`, `class %Counter`,
`let %gK`, `witness_table %n`) because the dump preamble is large; arithmetic
operands come from `uniform` globals so constant folding cannot collapse the
surface that materializes the declaration, and results sink into an
`RWStructuredBuffer` so nothing is dropped before the dump.

Coverage strategy is one test per observable parent/child pair, plus a
boundary probe at each documented arity edge the catalog implies (zero fields,
zero requirements, zero call arguments, two literals sharing one pool), plus
one test per additional AST origin the catalog names for an opcode (a
`func` from a `ConstructorDecl` / `AccessorDecl` / lambda; a `global_var`
from a function-`static`; a `field` from an `InheritanceDecl`). Sibling
bundles own the neighbouring axes: `cross-cutting/ir-instructions` samples
each family once, `ir-reference/values` owns the value-producing consumers of
`field` / `key`, `ir-reference/control-flow` owns `block` / `param` in its
phi role, and `ir-reference/generics-and-existentials` owns the dispatch-side
semantics of `specialize` and `lookupWitness`.

Source ([#source](../../../../design/ir-reference/structure.md#source)):

- S1 — The structural opcodes are declared in four named regions of `slang-ir-insts.lua`, their C++ wrappers are split between `slang-ir.h` and `slang-ir-insts.h`, and the remaining wrappers are FIDDLE-generated. _(untested — internal-source-fact)_
- S2 — There is deliberately no `IRBuilder` helper for `module`; the root inst is allocated by `IRModule::create`. _(untested — internal-source-fact)_
- S3 — `getInterfaceRequirementKey` returns an `IRInst*`: an ordinary requirement lowers to a `StructKey` given a `key_<mangled>` linkage name, a recognized built-in requirement to a hoistable `BuiltinRequirementKey`. _(`struct-key-has-export-linkage.slang`, `builtin-requirement-key-in-witness-table.slang`)_
- S4 — `findWitnessTableEntry` and `SpecializationOptions::lowerWitnessLookups` are outside the page's `watched_paths` and should be added. _(untested — process-doc)_

Family hierarchy ([#family-hierarchy](../../../../design/ir-reference/structure.md#family-hierarchy)):

- H1 — `GlobalValueWithCode` and `GlobalValueWithParams` are the only abstract intermediates in the family. _(untested — internal-source-fact)_

Opcodes preamble ([#opcodes](../../../../design/ir-reference/structure.md#opcodes)):

- O1 — The `parent` flag is not a containment test: `witness_table` and `global_var` own children without carrying it, and nothing reads the flag back. _(untested — internal-source-fact; the "they do own children" half is covered by `witness-table-entry-pairs.slang` and `global-var-mutable.slang`)_

Module ([#module](../../../../design/ir-reference/structure.md#module), [#module--moduleinst](../../../../design/ir-reference/structure.md#module--moduleinst)):

- M1 — `module` is the top-level container; every other module-scope inst is its child. _(untested — implementation-detail)_

- M4 — A module records the IR semantics version it was built against, in the range 4 .. 28. _(untested — internal-source-fact)_

Functions and generics ([#functions-and-generics](../../../../design/ir-reference/structure.md#functions-and-generics), [#func](../../../../design/ir-reference/structure.md#func), [#generic](../../../../design/ir-reference/structure.md#generic)):

- F1 — `func` is a parent opcode owning blocks; the signature is the inst's own `FuncType`, not an operand. _(`func-entry-point.slang`, `func-helper-signature.slang`)_
- F2 — Any `FunctionDeclBase` lowers through `lowerFuncDecl`: `FuncDecl`, `ConstructorDecl`, `AccessorDecl`, `SynthesizedFuncDecl`, and the synthesized `FuncDecl` checking stores on a lambda. _(`func-from-constructor-decl.slang`, `func-from-accessor-decl.slang`, `func-from-lambda-synthesized.slang`)_
- F3 — The first block is the entry block and its `Param` children are the function parameters in declaration order. _(`func-param-on-entry-block.slang`)_
- F4 — `getFirstParam` / `getParams` forward to the first block rather than to `func`. _(untested — internal-source-fact)_
- F5 — `isDefinition()` tests whether any block exists at all. _(untested — needs-multi-file-test)_
- F6 — Function-level decorations attach to the `func` inst rather than to its body. _(`func-name-hint-decoration.slang`)_
- F7 — `generic` is structurally the same as `func` but its body is type-level computation; it holds a single block. _(`generic-function-parent.slang`)_
- F8 — That block ends with a `return_val` whose operand is the type-level result, which `findGenericReturnVal` reads back. _(`generic-body-yields-func.slang`)_
- F9 — An individual interface requirement can itself be generic; lowering stores a requirement-local `IRGeneric` as the witness-table entry value, so uses read `specialize(lookupWitness(table, key), methodArgs...)`. _(`generic-requirement-specialize-lookup-witness.slang`)_
- F10 — `call` takes a callee plus a variadic argument tail; its result type is the call's own type. _(`func-call-link.slang`, `call-zero-arguments.slang`)_
- F11 — `param` is always a child of a `block`; detail lives in `control-flow.md`. _(`func-param-on-entry-block.slang`)_

Global state ([#global-state](../../../../design/ir-reference/structure.md#global-state)):

- G1 — A module-scope `VarDecl` that is neither a shader parameter nor `static const` lowers to `global_var`, whose type is a `PtrType` with an initializer in child blocks. _(`global-var-mutable.slang`)_
- G2 — A mutable function-`static` local also lowers to `global_var`, via `lowerFunctionStaticVarDecl`. _(`global-var-function-static.slang`)_
- G3 — A module-scope shader-parameter `VarDecl` lowers to `global_param`, which unlike `global_var` _is_ the value rather than its address. _(`global-param-uniform.slang`, `global-param-is-value-not-address.slang`)_
- G4 — A `static const` module-scope `VarDecl` lowers to `globalConstant` with an optional `value` operand. _(`global-constant-value.slang`)_
- G5 — A function-`static` `const` also lowers to `globalConstant`, via `lowerFunctionStaticConstVarDecl`. _(`global-constant-function-static.slang`)_
- G6 — A `globalConstant` with no operand is an `extern` constant defined in another module. _(untested — needs-multi-file-test)_
- G7 — `GlobalGenericParamDecl` / `GlobalGenericValueParamDecl` lower to `global_generic_param`; constraint decls parented by one lower there too. _(`global-generic-param-type-param.slang`)_

Struct internals ([#struct-internals](../../../../design/ir-reference/structure.md#struct-internals), [#key--structkey](../../../../design/ir-reference/structure.md#key--structkey)):

- St1 — `struct` is a parent container owning the struct's `field` children, read back by `getFields()`. _(`struct-parent-with-fields.slang`, `struct-with-many-fields.slang`, `struct-with-no-fields.slang`)_
- St2 — `class` is the same container with a distinct opcode spelling. _(`class-parent-with-field.slang`)_
- St3 — `field` declares one named member and takes `key, fieldType`. _(`struct-parent-with-fields.slang`, `struct-with-many-fields.slang`)_
- St4 — A `field` can also originate from an `InheritanceDecl`, which is how a derived struct embeds its direct base as its leading field. _(`field-key-from-inheritance-base.slang`)_
- St5 — `field`'s operands are unnamed in Lua and its entry declares `min_operands = 2`. _(untested — internal-source-fact)_
- St6 — `key` is the identity of a field or interface requirement and carries `key_<mangled>` linkage so the member is addressable across compilation units. _(`struct-key-has-export-linkage.slang`)_
- St7 — Field-access opcodes use the key as their selector, making structural reorganization a key-rewriting task. _(`struct-key-selects-field-access.slang`)_
- St8 — A `struct` does not own its `key` children: keys are `global` and sit at module scope; a `field` points at its key by operand. _(`struct-key-not-child-of-struct.slang`)_
- St9 — `builtinRequirementKey` is the key variant for a recognized built-in requirement; it is hoistable, its identity is its single `kindOperand`, so it is deduplicated by construction across decls and the precompiled-core-module boundary. _(`builtin-requirement-key-in-witness-table.slang`, `builtin-requirement-key-dedup-two-conformances.slang`)_
- St10 — Because either key kind can appear, the `lookupKey` operand of `lookupWitness`-style dispatch is typed `IRInst`, not `IRStructKey`. _(`lookup-witness-builtin-requirement-key.slang`)_
- St11 — `getInterfaceRequirementKey` tags a `BuiltinRequirementKey` with an `IRBuiltinRequirementDecoration` so consumers find it by role. _(untested — out-of-bundle)_
- St12 — `indexedFieldKey` is a placeholder key for the _n_-th field of a tuple-like type; its only producer is `getIndexedFieldKey` in `lowerTypeLayout`. _(`indexed-field-key-tuple-layout.slang`)_

Interface internals ([#interface-internals](../../../../design/ir-reference/structure.md#interface-internals), [#witnesstableentry-vs-interfacereqentry](../../../../design/ir-reference/structure.md#witnesstableentry-vs-interfacereqentry)):

- I1 — An `interface`'s operands are its `interface_req_entry` rows, counted by `getRequirementCount()`. _(`interface-with-requirement.slang`, `interface-multiple-requirements.slang`, `interface-with-no-requirements.slang`)_
- I2 — `interface_req_entry` takes `requirementKey, requirementVal`. _(`interface-with-requirement.slang`)_
- I3 — The `requirementKey` may be a `StructKey` or a hoistable `BuiltinRequirementKey`. _(untested on the interface side — internal-source-fact)_
- I4 — The requirement list is one entry per requirement-bearing direct member; a property or subscript contributes one entry per accessor. _(`interface-property-entry-per-accessor.slang`)_
- I5 — An `InterfaceDefaultImplDecl` member is skipped entirely. _(`interface-default-impl-not-extra-entry.slang`)_
- I6 — An associated-type bound is a _sibling_ requirement of the associated type rather than a member of it, and its entry carries a `WitnessTableType(bound)` requirement value. _(`interface-associated-type-sibling-bound.slang`)_

Witness tables and witness facts ([#witness-tables-and-witness-facts](../../../../design/ir-reference/structure.md#witness-tables-and-witness-facts), [#witnesstable](../../../../design/ir-reference/structure.md#witnesstable)):

- W1 — `witness_table`'s operand 0 is the concrete type; the interface is carried in the result type, not as an operand. _(`witness-table-parent.slang`)_
- W2 — Its children are `witness_table_entry` insts, one per requirement, mapping `requirementKey` to the satisfying function or value. _(`witness-table-entry-pairs.slang`, `two-impls-share-requirement-key.slang`)_
- W3 — The two entry opcodes are the declaring and satisfying halves of one key-driven dispatch table, joined by the same key; neither side should be indexed positionally. _(`interface-req-key-shape.slang`)_
- W4 — The opcode is hoistable, so one type-and-interface pair shares a single table. _(untested — implementation-detail)_
- W5 — A witness table is an unordered key-to-value map; consumers must read it with `findWitnessTableEntry`, never by child position, and entry order need not match the interface's requirement order. _(untested — implementation-detail)_
- W6 — `specializeModule` resolves a `lookupWitness` against a concrete table, gated on `lowerWitnessLookups`. _(untested — out-of-bundle)_
- W7 — A generic body resolves a requirement on a constrained type parameter through `lookupWitness(witnessTable, requirementKey)`. _(`lookup-witness-in-generic.slang`)_
- W8 — `thisTypeWitness` is a zero-operand placeholder witness whose interface is carried in the result type, valid only inside an interface definition. _(`this-type-witness-in-interface.slang`)_
- W9 — The Lua entry for `thisTypeWitness` declares a `type` operand no producer supplies, leaving `getConstraintType()` a latent out-of-range read that nothing calls. _(untested — internal-source-fact)_
- W10 — `TypeEqualityWitness` takes `subType, superType` and is lowered by `visitTypeEqualityWitness` from the AST `Val` of the same name. _(`type-equality-witness-where-clause.slang`)_

Symbol aliasing ([#symbolalias](../../../../design/ir-reference/structure.md#symbolalias)):
