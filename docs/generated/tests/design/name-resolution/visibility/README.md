# Tests for design/name-resolution/visibility

## Intent

This bundle exercises the declaration-visibility rules described in
[`docs/generated/design/name-resolution/visibility.md`](../../../../design/name-resolution/visibility.md):
which decl/scope pairs `isDeclVisibleFromScope` admits, which pairs are
rejected with `declaration not accessible` (30600) at the lookup boundary or
during overload resolution, which declarations `checkVisibility` rejects
outright (higher-than-parent 30601, invalid-private 30603, less-visible-type
30604, misplaced modifier 36005, duplicate modifier 31202), and how a decl
that carries no visibility keyword is classified.

The strategy is a **positive/negative pair per enforcement claim**: one test
proving access is permitted from the scope the keyword allows, one proving
the same access is rejected from a scope it forbids. Positive cases run under
`//TEST:INTERPRET(filecheck=CHECK):` (or `//TEST:SIMPLE ... -target hlsl`
when the claim needs a `-std` selection, which `slangi` does not accept);
negative cases use `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` with caret columns
copied from the runner's "Suggested annotations". Visibility is resolved at
semantic check before any target lowering, so there is no per-backend
emission fan-out — the one exception is the auto-diff synthesis claim, which
needs a runtime observation and therefore uses `COMPARE_COMPUTE -cpu`.

Two axes new to this revision of the doc get dedicated version-paired tests:
the **Slang 2026 aggregate-inheritance rule** (an unmodified member of an
aggregate inherits the aggregate's effective visibility), tested at both
`-std 2025` and `-std 2026` with the same source so the version gate itself
is the observation, and the **split visibility of synthesized extensions**
(a `private` `[Differentiable]` member's derivative extension must be
`internal`, not `private`).

The bundle is deliberately **single-file**: cross-module claims (`internal`
invisible from another module, `__exported import` re-export, the
`isOwnModuleOrIncludedFileScope` non-transitivity rule) cannot be expressed
in one `.slang` source and are recorded under `## Untested claims`.
`_repro/` holds a non-test reproduction referenced by a filed finding; it
carries no `//TEST` directive and is skipped by the runner.
