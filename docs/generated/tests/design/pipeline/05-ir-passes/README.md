**`## How the passes are ordered`**

1. `linkAndOptimizeIR` in `slang-emit.cpp` is the orchestrator, and every pass call site goes through the `SLANG_PASS` macro so IR dumping and profiling apply uniformly.
2. It links the per-translation-unit IR modules together with `linkIR`, producing the `LinkedIR` that all later passes mutate.
3. It runs a sequence of validations, specializations and legalizations, and inserts target-specific passes when the `TargetRequest` indicates a target that needs them.
4. It returns the linked and optimized module to its caller, which hands it to the chosen emit backend.
5. SPIR-V is the exception: `legalizeIRForSPIRV` is invoked from the SPIR-V emit backend *after* `linkAndOptimizeIR` returns, so it can run after address-space specialization.
6. That call is a direct one rather than a `SLANG_PASS(...)`, so no `BEFORE legalizeSPIRV` / `AFTER legalizeSPIRV` header appears in `-dump-ir` output.
7. `-dump-ir` shows exactly the `SLANG_PASS` call sites of `linkAndOptimizeIR` and nothing else, so a stage invoked as a plain function call is invisible in that stream even though it certainly ran.
8. The pipeline is not a fixed list — different targets, optimization levels, and the presence of differentiation or coverage instrumentation all change the sequence.
9. Most optional passes are gated on a `RequiredLoweringPassSet` flag computed by `calcRequiredLoweringPassSet`, which runs twice and whose flags accumulate rather than reset between the two scans.
10. Compiling for `CodeGenTarget::HostVM` returns early after `performForceInlining` and a final `simplifyIR`, skipping every target-dependent pass below that point.
11. Several passes appear more than once at different points, including `simplifyIR`, `eliminateDeadCode`, `performForceInlining`, `legalizeEmptyTypes`, `eliminatePhis` and `lowerBufferElementTypeToStorageType`.
12. `lowerBufferElementTypeToStorageType` runs in three configurations for Metal.
13. A substantial number of passes run *before* `linkAndOptimizeIR` inside `generateIRForTranslationUnit`; 04b is the authoritative ordering for that region and the per-target pages for the post-link region.
14. `propagateConstExpr` runs only in the pre-link region, while the post-link cleanup uses the `simplifyIR` fixed point (SSA / SCCP / SimplifyCFG / DCE) rather than constexpr propagation.
15. The layout IR module is not independently run through the pass sequence, but its symbols and layout decorations are consumed by `linkIR` at the very start of `linkAndOptimizeIR`.

**`### Entry-point and parameter handling`**

143. The entry-point pass framework is the common scaffold for per-entry-point passes.
144. `checkEntryPointDecorations` validates entry-point output-topology decorations against the stage and target.
145. Entry-point raw-ptr params handles pointer-typed entry-point parameters.
146. `collectEntryPointUniformParams` collects uniform entry-point parameters into one aggregate, and `moveEntryPointUniformParamsToGlobalScope` moves it to global scope for applicable targets.

148. Fix entry-point callsite cleans up callers of entry-point functions.
149. `transformParamsToConstRef` turns `in` parameters into `const&`, and `translateEntryPointInParamToBorrow` runs on every target immediately after linking.
150. Undo param copy undoes pessimistic param copies.
151. No pass in this category lowers `[numthreads(...)]`: AST-to-IR lowering attaches it as an `IRNumThreadsDecoration` and it survives untouched to emit.

**`### Instrumentation`**

188. Coverage instrument synthesizes a `__slang_coverage` buffer, an `RWStructuredBuffer<uint64_t>` by default and `uint` when the caller opts down via the validated `counterByteWidth` of `{4, 8}`, and rewrites marker ops into atomic adds.
189. It honors `-trace-coverage-binding` / `-trace-coverage-reserved-space` for binding-slot control.
190. `-trace-coverage-boolean` records execution as a non-atomic store of `1` instead of an exact count.
191. For Metal targets counting-mode counters are capped at 4 bytes because MSL has no 64-bit atomic fetch-add, and an explicitly requested 64-bit width is capped with a warning.
192. Boolean mode is exempt from that cap because it stores rather than accumulates.
193. Two things have to line up: the linked module must contain coverage marker opcodes, which sets the `coverageTracing` flag, and the pass's `enabled` argument comes from `CodeGenContext::shouldTraceAnyCoverage()`.
194. The surface that picks `counterByteWidth` is `-trace-coverage-counter-width` on the command line, spelled in bits (`32` or `64`), or `CompilerOptionName::TraceCoverageCounterByteWidth` through the API, spelled in bytes; with neither set the width is 8.
195. `finalizeCoverageInstrumentationMetadata` runs after global / entry-point uniform packing to fill in CPU/CUDA uniform-marshaling fields determined by the final post-packing layout.
196. Insert debug value store preserves debug info across optimization, and liveness supplies the liveness analysis it uses.
197. Obfuscate loc performs optional source-loc obfuscation for distributed modules.
