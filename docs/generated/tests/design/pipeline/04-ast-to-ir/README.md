# Tests for design/pipeline/04-ast-to-ir

## Intent

This bundle exercises the AST → IR lowering stage described in
[`docs/generated/design/pipeline/04-ast-to-ir.md`](../../../../design/pipeline/04-ast-to-ir.md).
Coverage follows the doc's own decomposition:

- the **AST-family → IR-construct table** (`FuncDecl` → `IRFunc` with
  `IRBlock`s, `VarDecl` → `IRVar` / `global_param`, `StructDecl` →
  `IRStructType` with `field(...)` children, `InterfaceDecl` →
  `IRInterfaceType` with requirement-key entries, `GenericDecl` →
  `IRGeneric`, structured branches → `ifElse` / `loop` / `switch` with
  an explicit join operand, `ReturnStmt` → `return_val`, `InvokeExpr` →
  `call`, `MemberExpr` → `get_field` / `get_field_addr`, `LiteralExpr`
  → constant inst, `CastOptionalExpr` → an if/else diamond around a
  temporary, `WitnessTable` → `IRWitnessTable`), plus the `(void)expr`
  carve-out that yields the canonical void constant instead of a
  cast inst;
- the **`BuiltinOperatorExpr` fast path** — recognized scalar / vector /
  matrix operators emitted as one pure inst without callable
  resolution, with `%` selecting `frem` vs `irem` by element type and
  `?:` / `&&` / `||` carved out to their control-flow paths;
- the **compound `LoweredValInfo` flavors** that stay symbolic until a
  use site reads or writes them (swizzled l-value, accessor-backed
  storage);
- **generics and existentials** — specialization is deferred to a later
  IR pass, so a call site is `call specialize(%generic, T)(...)`; a
  generic interface requirement keeps its own generic parameters in the
  witness-table entry and its use site becomes
  `specialize(lookupWitness(...), ...)`; requirement keys are per-decl
  `key` insts or hoistable `builtinRequirementKey`s; associated-type
  bounds are relocated to interface-level requirement entries;
  differentiability arrives as a synthesized conformance;
- **module-level and entry-point-scoped outputs** — the `entryPoint`
  decoration, work-graph node attributes (launch mode kept as a string
  literal), the lifted shader-64-bit-indexing decoration;
- **debug-info gating** — synthesized initializers get no debug lines,
  user-written `__init`s keep theirs and name the object `this`;
- **lowering-time diagnostics** — the unreachable-code warning for
  statements ahead of a switch's first `case` label.

The primary observation mechanism is
`-target spirv-asm -dump-ir -o /dev/null` followed by FileCheck against
the IR dump, anchored on a user-named function (`func %main` or a
helper) to cut through the preamble of capability sets, core-module
imports, and differentiation glue. Almost every claim here is a
target-independent IR-shape claim, so the bundle uses a single
`-dump-ir` directive per test rather than a per-target emission
fan-out; the one exception is the work-graph node-attribute test, which
must compile for a target that admits node entry points and therefore
uses `-target hlsl`.

Cross-cutting decoration / opcode catalog coverage (`entryPoint`,
`nameHint`, the per-opcode catalog shape) lives in
[`cross-cutting/ir-instructions`](../../cross-cutting/ir-instructions/);
this bundle anchors on the AST side of the mapping ("which AST node
lowers to which IR construct"). The mandatory pass sequence that runs
after lowering — including the early-inlining / prelinking of imported
`[unsafeForceInlineEarly]` bodies — belongs to
[`pipeline/04b-pre-link-passes`](../04b-pre-link-passes/).

**`## Inputs and outputs`**

1. The input is a checked AST inside a `TranslationUnitRequest`, plus an `ASTBuilder`.
2. _(umbrella)_ The output is a fresh `IRModule` containing IR definitions for every function, type, generic, and global variable defined in that translation unit.
3. The lowering step does not link in `import`ed modules wholesale; those are linked in by a later IR pass before code generation.
4. Lowering records imported `[unsafeForceInlineEarly]` functions in `externalSymbolsToPrelink`, and `prelinkIR` clones their bodies into this module before it is returned.
5. That clone and the whole mandatory pass block run before the `LOWER-TO-IR` snapshot `-dump-ir` prints, so the first dump is not the raw output of the lowering walk.

**`## Lowering driver`**

6. The entry point is `generateIRForTranslationUnit(astBuilder, translationUnit)`.
7. `generateIRForSpecializedComponentType` produces a small IR module recording how a `SpecializedComponentType` binds specialization parameters to concrete arguments.
8. `generateIRForTypeConformance` produces an IR module that exposes a user-supplied type conformance as a public symbol so linking can keep the relevant witness table alive.
9. The lowering visitor descends the AST top-down, allocating IR instructions for decls and lowering expressions and statements into SSA value instructions and basic blocks.
10. There is one visitor family per AST family — `DeclLoweringVisitor`, `StmtLoweringVisitor`, `ExprLoweringVisitorBase`, `ValLoweringVisitor` — all sharing state through `IRGenContext` / `SharedIRGenContext`.

**`### LoweredValInfo and the lowering environment`**

11. _(umbrella)_ A lowered expression returns a `LoweredValInfo` whose `Flavor` distinguishes `None`, a `Simple` r-value, a `Ptr` l-value, and the compound forms lowering keeps symbolic until a use site decides how to read or write them.
12. `BoundMember` is produced by `obj.method` as a value before the call, or by a field whose base is itself deferred; the use site emits `get_field` / `get_field_addr` for a field and the resolved function value for a method.
13. `BoundStorage` is produced by a `property` / `__subscript` access whose accessor set is more than a lone `get`; the use site emits a `call` to the `get` accessor on a read and to `set` on a write, and a `ref` accessor instead collapses the value to a `Ptr`.
14. `SwizzledLValue` is produced by a vector swizzle in l-value position; a read emits `swizzle`, and a write emits `swizzledStore` when the base is a `Ptr` and otherwise `swizzleSet` plus a store back.
15. `SwizzledMatrixLValue` is produced by a matrix swizzle in l-value position; a read emits two nested `getElement`s per component plus a `makeVector` when more than one is selected, and a write emits `matrixSwizzleStore`.
16. `ExtractedExistential` is produced by an interface-typed value opened in l-value position; the use site yields the extracted value as it stands, and a write re-wraps the source with `makeExistential` first.
17. `ImplicitCastedLValue` is produced by an implicit conversion on an `out` / `inout` argument; a read emits whichever conversion inst `emitCast` picks, and a write applies that cast to the source followed by a store into the base.
18. `Subscript` is declared but has no construction site.
19. The right-hand column of the flavor table is what `materialize` and `getSimpleVal` produce when a flavor is forced down to a single `IRInst*`, and what the `assign` switch produces on the write side.
20. Per-environment caches sit on `IRGenEnv`: `mapDeclToValue` for decls and `mapValToValue` for `Val`s.
21. `lowerVal` and `lowerType` both route through `lowerValWithCache`, which resolves the `Val`, consults `mapValToValue`, and stores only completed results so recursive `Val` graphs are not disturbed by an in-progress entry.
22. The cache is per environment rather than global because a nested generic environment can bind the same `Val` to a different IR parameter.
23. `lowerType` still runs `lowerAssociatedVals` and `lowerRelatedTypes` after a cache hit, because those are contextual side effects on the current module rather than part of the `Val`-to-IR mapping.

**`## IRBuilder and instruction creation`**

24. `IRBuilder` owns the current insertion point inside a block / function / module.
25. It hash-conses hoistable values so two structurally equal values share one `IRInst*`; `kIROpFlag_Hoistable` tags the opcodes deduplicated this way.
26. `kIROpFlag_Global` marks opcodes that are always hoisted to module scope but are never deduplicated.
27. It exposes typed convenience emitters (`emitVar`, `emitCallInst`, `emitAdd`, ...) plus the generic `emitIntrinsicInst` / `createIntrinsicInst` pair.
28. The build-time generated header `slang-ir-insts-enum.h`, derived from `slang-ir-insts.lua`, provides the `IROp` enum used throughout lowering.

**`## Mapping AST constructs to IR`**

29. `ModuleDecl` lowers to an `IRModule` top-level container.
30. `FuncDecl` lowers to an `IRFunc` containing one or more `IRBlock`s.
31. `VarDecl` (global) lowers to an `IRGlobalVar`.
32. `VarDecl` (local) lowers to an `IRVar` allocated inside a block.
33. `StructDecl` lowers to an `IRStructType` with `IRStructField` children.
34. `InterfaceDecl` lowers to an `IRInterfaceType` whose requirement-key entries are `IRStructKey`s or hoistable `IRBuiltinRequirementKey`s.
35. `GenericDecl` lowers to an `IRGeneric`, a function-shaped instruction whose body computes type-level values.
36. `BlockStmt` lowers to a sequence of basic blocks, and locals turn into `IRVar`.
37. `IfStmt`, `ForStmt`, `WhileStmt` and `SwitchStmt` lower to structured branches whose join point is an explicit operand on the terminator.
38. `ReturnStmt` lowers to an `IRReturn` terminator.
39. `BuiltinOperatorExpr` lowers to a single pure value inst (`kIROp_Add`, `kIROp_Mul`, `kIROp_Eql`, `kIROp_BitAnd`, `kIROp_Neg`, ...) emitted directly by `lowerBuiltinOperatorExpr`.
40. `InvokeExpr` lowers to an `IRCall` after callable resolution.
41. `MemberExpr` lowers to an `IRFieldAddress` / `IRFieldExtract` for lvalue vs rvalue position.
42. `IndexExpr` lowers via `subscriptValue`, which emits `getElement` for a value base and `getElementPtr` for a pointer base; a `__subscript` arrives as an `InvokeExpr` routed through `lowerStorageReference`.
43. `AssignExpr` writes through the left side's `LoweredValInfo` — `store` for a `Ptr`, `swizzledStore` for a swizzle, a setter `call` for `BoundStorage`.
44. `BuiltinCastExpr` lowers to the one conversion inst picked by `IRBuilder::emitCast`'s style table: `intCast`, `floatCast`, `castIntToFloat`, `castFloatToInt`, ...
45. `BreakStmt` and `ContinueStmt` lower to an `unconditionalBranch` to the enclosing statement's break / continue label block.
46. `Optional<T>`, `Tuple<...>` and `ParameterBlock<T>` lower to the matching hoistable type inst — `Optional(...)`, `tuple_type(...)`, `ParameterBlock(...)`.
47. `LiteralExpr` lowers to a constant inst (`IRIntLit`, `IRFloatLit`, ...).
48. `CastOptionalExpr` lowers to an `if`/`else` diamond around a temporary: it tests `emitOptionalHasValue`, coerces the unwrapped value on the true side, and propagates `emitMakeOptionalNone` on the false side.
49. A `WitnessTable` synthesized in checking lowers to an `IRWitnessTable`, or — for a `SynthesizedModifier`-tagged conformance — to a single intrinsic inst.
50. A `(void)expr` cast reaches lowering as the builtin `__init(T)` on `void` with opcode `kIROp_CastToVoid`; lowering evaluates the operand for its side effects and yields the canonical `IRVoidLit` instead of creating a `CastToVoid` inst, so no backend has to know the opcode.
51. Phi-style joining is encoded as block parameters (`IRParam` at the start of a block) rather than explicit `phi` instructions, and branches to a block carry the parameter values as arguments.

**`### Builtin operators bypass call lowering`**

52. During checking, a recognized scalar / vector / matrix operator on builtin numeric or `bool` operands is rewritten to a `BuiltinOperatorExpr` carrying a resolved `BuiltinOperationKind`.
53. `lowerBuiltinOperatorExpr` switches on that enum and emits the matching pure IR op directly via `emitIntrinsicInst`, skipping callable resolution entirely.
54. The element type only matters for `%`, which picks `kIROp_FRem` for floating-point operands and `kIROp_IRem` otherwise, with the element type unwrapped out of a vector or matrix operand first.
55. `?:`, `&&` and `||` are still lowered through their dedicated control-flow paths, so those `BuiltinOperationKind` values are an `SLANG_UNEXPECTED` in this visitor rather than handled.
56. `visitBuiltinOperationIntVal` lowers a `BuiltinOperationIntVal` to the hoistable `constexpr*` opcode keyed on its `BuiltinOperationKind`, so equal compile-time expressions deduplicate to one inst.
57. The surface that reaches these opcodes is arithmetic on a generic value parameter whose result is needed as a type-level value: inside `int f<let N : int>()`, the extent `int a[N / 2]` lowers to `constexprDiv(%N, 2 : Int)`.
58. `+`, `-`, `*` and unary `-` never form a `BuiltinOperationIntVal`; they arrive as a `PolynomialIntVal`, which `visitPolynomialIntVal` lowers to the same opcode family emitting the constant term first, so `int b[N + 1]` lowers to `constexprAdd(1 : Int, %N)`.
59. A literal-only expression folds to a `ConstantIntVal` during checking and arrives as a plain `IRIntLit`.

**`## Generics and existentials`**

60. Generics survive lowering as ordinary IR: an `IRGeneric` is a function-shaped instruction whose body runs at IR-time to compute the specialized inner instruction.
61. Specialization is not performed during lowering; it is handled by later IR passes.
62. Witness tables become `IRWitnessTable` insts whose entries map interface requirements to the concrete implementations; `visitInheritanceDecl` creates the table and `lowerWitnessTable` fills it in.
63. When the base decl-ref from `getWitnessTableBaseDeclRef` is non-null, every requirement witness taken out of the AST requirement dictionary is `specialize`d through it before being lowered, so an entry copied from a generic interface carries the conforming type's substitutions rather than the interface's own parameters.
64. That base decl-ref is null only when the conformance's base type is not a `DeclRefType`, which an ordinary `struct S : IFoo<...>` never produces.
65. For `struct S : IFoo<int>`, the table is `witness_table_t(specialize(%IFoo, Int))(%S)`; the `zero` entry is satisfied by a member of `S`, mentions no interface parameter and stays flat, while the inherited `twice` entry reads `specialize(specialize(%twiceImpl, Int), %S, %table)`.
66. `lowerWitnessEntryValue` switches on the `RequirementWitness::Flavor`: a `declRef` witness lowers through `emitDeclRef`, a `val` witness through `lowerSimpleVal`, and a `witnessTable` witness recursively materializes a nested `IRWitnessTable`.
67. A nested witness table is materialized with its own conformance mangled name and, for an exported type, `HLSLExport` / `KeepAlive` decorations.
68. Already-materialized nested tables are memoized in `IRGenContext::mapASTWitnessTableToIRWitnessTable`, a non-owning pointer shared by copied contexts for the current insertion / generic environment.

**`### Generic interface requirements`**

69. A requirement can itself be generic — most commonly a differentiability constraint recorded by the checker as a sibling `GenericDecl` whose `inner` is a `GenericTypeConstraintDecl`.
70. `lowerWitnessTable` routes such an entry to `lowerWitnessEntryValueInGenericWitnessTable`, which opens a nested `IRGenEnv` and its own nested-witness-table cache, emits the requirement's own generic parameters with `emitGenericDecl`, lowers the satisfying witness inside that environment, and closes only the generics it opened via `stopBeforeGeneric`.
71. The result is a requirement-local `IRGeneric` stored as the witness-table entry value, so a use site becomes `specialize(lookupWitness(table, key), methodArgs...)` rather than a flat witness lookup that has dropped the method's generic arguments.
72. `canDeclLowerToAGeneric` has the matching decl-side rule: a `GenericTypeConstraintDecl` lowers to a generic exactly when it is the `inner` of a `GenericDecl`.
73. `isGenericConstraintParameterDecl` decides which constraint decls become generic parameters; `emitGenericDecl` consults it before emitting a hidden parameter, and the substitution-argument walk in `ExprLoweringContext` uses the same predicate so parameters and arguments stay in agreement.

**`### Associated-type bounds`**

74. A bound on an associated type — `associatedtype A : IBar`, `associatedtype A where A : IBar`, or `__constraint A : IBar` — is a requirement of the enclosing interface, a sibling of `A`, not something nested under it.
75. `visitAssocTypeDecl` lowers the associated type with an empty list of constraint interfaces, because the bounds are no longer its members.
76. The `IRInterfaceType` requirement loop emits exactly one entry per direct interface member and no longer walks an associated type's or a callable's nested `TypeConstraintDecl`s to synthesize extra entries.
77. A relocated non-equality subtype constraint gets a `WitnessTableType(bound)` requirement value, wrapped in an `IRGeneric` when the constraint is the `inner` of a `GenericDecl`.
78. `visitGenericTypeConstraintDecl` recognizes just two interface-requirement shapes — a constraint that is a direct member of an `InterfaceDecl`, and one that is the `inner` of a `GenericDecl` directly under an `InterfaceDecl` — plus the global-generic-parameter case.

**`### Requirement keys`**

79. `getInterfaceRequirementKey` returns an `IRInst*` cached per requirement `Decl` in `SharedIRGenContext::interfaceRequirementKeys`.
80. For an ordinary requirement (most methods, associated types), the key is a per-decl `IRStructKey` that is a distinct `global` symbol unified across modules by its `key_<mangled>` linkage name.
81. For a recognized built-in requirement tagged with `BuiltinRequirementModifier`, the key is a hoistable `IRBuiltinRequirementKey` whose identity is its `BuiltinRequirementKind` operand, so the same logical requirement deduplicates to a single key inst across decls and across the precompiled-core-module boundary.
82. The key also carries an `IRBuiltinRequirementDecoration` so role-scanning consumers can find a requirement by role rather than by position, and the witness-table entry's `lookupKey` operand is therefore typed `IRInst` rather than `IRStructKey`.

**`### Differentiability arrives as a conformance`**

83. The checker represents differentiability as an interface conformance of the function viewed as a type: a `[Differentiable]` function `f` gets a synthesized `extension __func_as_type(f) : IForwardDifferentiable<__func_as_type(f)>` and the backward analogue.
84. `visitInheritanceDecl` treats an `InheritanceDecl` carrying a `SynthesizedModifier` specially: instead of a real `IRWitnessTable` it emits one intrinsic inst whose opcode is the modifier's `op`, typed `WitnessTableType(IForwardDifferentiable<...>)`, with the conformance's `Val` operands lowered as the inst's operands.
85. Because the subtype is a callable rather than an aggregate type, the placeholder `LoweredValInfo` normally installed before `lowerType(subType)` is installed after it instead, so lowering the callable decl-ref sees the real callable.
86. A `SynthesizedFuncDecl` — the `fwd_diff` member the interface requires — is lowered by creating an `IRFunc`, replacing it with `emitIntrinsicInst` of the decl's stored `irOp` (`kIROp_ForwardDifferentiate`), and rewriting the decl-to-value mapping to that inst.
87. `lowerAssociatedVals` reads the `DifferentiableAttribute` of the function being lowered and attaches each associated value with `IRBuilder::addAnnotation`, skipping a decl for which `isInterfaceRequirement` holds and substituting a `DeclRefBase` key through its decl-ref first.
88. `_findReplacementThisParamType` and `getThisParamTypeForCallable` redirect an extension whose target type is a callable decl-ref to that callable's own this-type.

**`### Variadic pack-count witnesses`**

89. A `countof(Pack) == Count` constraint on a variadic generic is recorded during checking as a `GenericVariadicPackCountConstraintDecl` whose satisfaction is a proof-only witness carrying no runtime data.
90. `emitGenericConstraintDecl` for such a decl emits a hidden `IRParam` of `WitnessTableType(void)` on the enclosing `IRGeneric`, registered as the lowered value of the constraint.
91. `visitDeclaredVariadicPackCountWitness` lowers the use of that constraint as an `emitDeclRef` to the same `void` witness-table type.
92. `visitConcreteVariadicPackCountWitness` lowers a concrete instance through `emitConcreteVariadicPackCountWitness`, which creates one module-level proof-only `IRWitnessTable` cached on `SharedIRGenContext::concreteVariadicPackCountWitnessTable` so every specialized call site reuses a single table.
93. `visitGenericVariadicPackCountConstraintDecl` handles the global-generic-param form by emitting an `IRGlobalGenericParam` of the same witness type, and asserts up front that a pack-count constraint is never an interface requirement.
94. In the `LOWER-TO-IR` dump of `int sum<let N : int, each T>(T values) where countof(T) == N` called as `sum<2>(1, 2)`, the generic's parameter list ends with `param %w : witness_table_t(Void)`, the module holds one `witness_table %t : witness_table_t(Void)(Void);`, and the call site reads `call specialize(%sum, 2 : Int, TypePack(Int, Int), %t)(...)`.

**`## Diagnostics during lowering`**

95. _(umbrella)_ Most diagnostic-worthy issues are caught in semantic checking, but a handful of constructs become problems only when lowering tries to encode them.
96. The assignment-lowering switch emits `Diagnostics::UnsupportedAssignmentTarget` when it reaches an assignment whose left-hand side it cannot encode, recovering the nearest non-zero source location, rather than aborting via `SLANG_UNIMPLEMENTED_X`.
97. Indexing an array-valued `property` is the reachable case, because `s.v` materializes to a `call` to the getter and `[0]` then extracts an element of that temporary, giving `error[E40017]: assignment target is not supported`.
98. Lowering errors flow through the same `DiagnosticSink` used by the rest of the front-end.
99. A statement inside a `switch` body reached while no case label is active is unreachable, and lowering warns once for that leading run with `Diagnostics::UnreachableCode`, tracked by the `warnedUnreachableBeforeFirstCase` flag.
100.  `visitInvokeExprImpl` counts its recursion depth in `IRGenContext::invokeLoweringRecursionDepth` and, past `kMaxIRInvokeLoweringRecursionDepth` (128), diagnoses `Diagnostics::MaximumTypeNestingLevelExceeded` and yields `getPoison(type)` rather than overflowing the native stack.
101.  Nothing in the counter is specific to constructors: it advances once per nested `InvokeExpr`, so a chain of 128 ordinary calls `f(f(...f(x)...))` is already enough to report `fatal error[E39997]: maximum type nesting level exceeded`.

**`## Module-level outputs`**

102. _(umbrella)_ The `IRModule` that `generateIRForTranslationUnit` returns is its only separate output object.
103. When a registered entry point carries no explicit `EntryPointAttribute`, lowering creates one, fills its capability set from the entry-point profile, and calls `addModifier` on the function decl so ordinary function lowering recognizes it as an entry point.
104. The entry-point IR functions and their decorations are children of that module.
105. Layout intent on global parameters is not materialized here: no `IRLayoutDecoration` is attached during translation-unit lowering, and layout assignment happens later in IR passes.
106. The caller installs the returned module on the AST-level `Module` with `setIRModule`, and that is the whole hand-off.
107. `generateIRForTypeConformance` and `TargetProgram::createIRModuleForLayout` build their own modules and are not outputs of translation-unit lowering.
108. `_lowerTypeLayoutCommon` records the front-end's byte alignment as a `TypeAlignment` attribute whenever the layout occupies the `LayoutResourceKind::Uniform` unit at all, and `IRTypeLayout::Builder` decides whether an attribute is actually emitted.

**`### Entry-point-scoped decorations`**

109. `lowerFrontEndEntryPointToIR` attaches the decorations that are meaningful only on an entry point.
110. It lifts the `spvShader64BitIndexingEXT` capability onto the entry point as an `IRShader64BitIndexingDecoration`, scanning the `inferredCapabilityRequirements` atom sets with `getAtomSets()` rather than `implies()`.
111. The requirement is lifted onto the entry point rather than left on the attributed callee because the corresponding SPIR-V execution mode is entry-point scoped.
112. Work-graph node attributes take the same route, each source spelling lowering to its matching decoration: `[NodeLaunch(mode)]` to `nodeLaunch`, `[NodeID(name, arrayIndex)]` to `nodeID`, `[NodeMaxDispatchGrid(x, y, z)]` to `nodeMaxDispatchGrid`, `[NodeDispatchGrid(x, y, z)]` to `nodeDispatchGrid`, `[MaxRecords(count)]` to `maxRecords`, and `[NodeIsProgramEntry]` to `nodeIsProgramEntry`.
113. The launch mode is kept as an `IRStringLit` rather than an integer, so the dump reads `[nodeLaunch("broadcasting")]` and HLSL emit can re-emit the source name.
114. Those attributes are not core-language syntax: their `attribute_syntax` declarations live in the `experimental.workgraph` standard module, so the shader must `import experimental.workgraph` and the compile must pass `-experimental-feature` alongside `-stage node` and a `lib_6_8` profile; without the import, `[NodeLaunch("...")]` is only an unknown-attribute warning.

**`### Debug-info gating`**

115. `isSynthesizedConstructorDecl` makes `maybeEmitDebugLine` and `maybeAddDebugLocationDecoration` skip a Slang-synthesized initializer — a `ConstructorDecl` with the `SynthesizedDefault` or `SynthesizedMemberInit` flavor.
116. The discrimination is by constructor flavor, not by the mangled `$init` name, because a user-written `__init` mangles the same way but must keep its debug info.
117. Constructor lowering names the object under construction `this` — either the caller-provided return-destination out-parameter or the by-value local the initializer returns — and adds an `IRDebugLocationDecoration` to the by-value local.
118. `getOrEmitDebugSource` spells the emitted filename with `PathInfo::getMostUniqueIdentity()` while still looking the `SourceFile` up by the `getName()`-based path, so hoistable debug-source records collapse across modules.
119. It embeds source text when the debug level is `Standard` or above or when `shouldIncludeSourceInDebugInfo()` is set, falling back to reading the found path off disk for a `SourceFile` deserialized from a precompiled module.

**`## Adjacent pipelines`**

120. The per-translation-unit, target-agnostic mandatory pass sequence inside `generateIRForTranslationUnit` runs before the IR module is cached on the `Module` and pulled into `linkAndOptimizeIR` by `linkIR`.
121. `TargetProgram::createIRModuleForLayout` builds a separate per-target IR module that does not run those mandatory passes, but an existing layout module is considered by `linkIR` via `TargetProgram::getExistingIRModuleForLayout` so its layout-decorated global symbols participate in linking.
