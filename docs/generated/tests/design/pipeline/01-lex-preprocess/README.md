# Tests for design/pipeline/01-lex-preprocess

## Intent

This bundle exercises the first compilation stage described by
[`docs/generated/design/pipeline/01-lex-preprocess.md`](../../../../design/pipeline/01-lex-preprocess.md):
how a source buffer becomes a flat, fully expanded token list. It covers
the lexer behaviours the doc adds beyond the pure token catalog
(backslash line continuation, UTF-8 folding into identifier code points,
the scan-vs-decode split for literals and which diagnostic belongs to
which phase), the preprocessor's macro machinery (object-like and
function-style `#define`, index-based argument replay, `#`, `##`), the
conditional-compilation rules (including the exact set of directives that
stay live inside an inactive block), `#include` resolution and its
per-file input-stream state, `#pragma warning` timeline tracking, the
three source-location categories for expansion-time tokens, and the
failure modes the doc enumerates.

Coverage strategy: one functional test per positive claim, boundary
probes along the numeric / escape / suffix / nesting axes the doc names,
and one diagnostic test per "is rejected" claim with the diagnostic code
pinned. Every test is target-independent, so the directives are
`INTERPRET`, `-target cpp` text emit (for string-typed observations that
slangi `printf` cannot make), and `DIAGNOSTIC_TEST`. Pure lex-surface
claims that `syntax-reference/tokens` already exercises (the token-kind
catalog, numeric suffixes as a typing surface, comment shapes) are
intentionally not duplicated here.

## Claims

Enumeration of the doc's testable claims, grouped by heading. Every ID
appears in exactly one of the two tables above.

**`## Inputs and outputs`**

1. Raw file bytes become source text via `SourceFile::decodeContentBlob`, which strips a leading BOM and decodes non-UTF-8 encodings; BOM-free UTF-8 passes through unchanged.
2. The output is a fully expanded `TokenList` with every `#include`, macro expansion, and conditional already resolved.
3. Phase 1 runs to completion and produces a flat token list rather than streaming to the parser.

**`## Token data model` / `## Source-location encoding`**

4. Every token carries a `TokenType`, raw text, a `SourceLoc`, and a `TokenFlags` byte.
5. `SourceLoc` is one `uint32_t` decoded on demand; its copy constructor is `= default` so the type stays trivially copyable.

**`### Lexer flags and special-case rules`**

6. `kLexerFlag_SuppressDiagnostics` suppresses scan-time diagnostics by handing out a null sink from `Lexer::getDiagnosticSink`.
7. The malformed-UTF-8 diagnostic bypasses that suppression and fires even inside an inactive branch.
8. Backslash line continuations are folded out, and the resulting token still maps back to its original physical line.
9. Keywords are not classified by the lexer; every keyword arrives as `TokenType::Identifier`.
10. Numeric, string, and character literal text is kept verbatim in the token; scanning does not decode the value.
11. A valid multi-byte UTF-8 sequence is folded by `_advance` into one code point that the identifier rule accepts.
12. A malformed sequence is diagnosed as `invalidUtf8ByteSequence` and substituted with a space; `_advance` stops before the offending byte.

**`### Literal scanning and value extraction`**

13. Scanning performs only the purely syntactic checks `invalidDigitForBase`, `octalLiteral`, and `quoteCannotBeDelimiter`.
14. `_lexStringLiteralBody` takes the closing quote as a parameter, so there is no separate character-literal scanning mode.
15. Its only escape handling steps over `\'`, `\"`, and `\\`; its only diagnostics are `endOfFileInLiteral` and `newlineInLiteral`.
16. Raw string literals are scanned by `_lexRawStringLiteralBody`, which looks for the matching `)delimiter"` and performs no escape processing.
17. `getIntegerLiteralValue` optionally returns the suffix, decimal-base flag, and overflow flag.
18. `getFloatingPointLiteralValue` classifies the suffix (`h`/`hf`/`fh` -> Half, empty or `f` -> Float, `l`/`lf`/`fl` -> Double, either case) and rounds to that type's precision and range.
19. It reports the malformed cases as `BadSignificand` / `BadSuffix` with `outErrorContent`.
20. `outIsOutOfRange` means the result is `0` (underflow) or `INFINITY` (overflow above the maximum for the literal type, not for double); `outPrecisionLost` is hex-float-only and in-range-only.
21. `getStringLiteralTokenValue` decodes escapes; `getFileNameTokenValue` is the `#include`-filename variant that does not.
22. `getCharLiteralValue` owns the one-character rule, emitting `illegalCharacterLiteral` for an empty body and again when the decode leaves unconsumed input.
23. All literal-value errors are decode-time: out-of-range code units and code points, malformed escape syntax, and the character-count rule.
24. `_decodeStringEscape` diagnoses `invalidStringEscape` (unknown letter, digitless or unterminated braced form, overflowing value) and `invalidUnicodeStringEscape` (`\u` not exactly 4 hex digits, `\U` not exactly 8).
25. The escape grammar is octal `\NNN`, hex `\xNN` with any number of digits, `\uNNNN`, `\UNNNNNNNN`, and braced `\u{...}` up to 32 bits.
26. In string literals `\xNN` maps to a single byte while Unicode code-point escapes are encoded as UTF-8 byte sequences.
27. In character literals the body bytes are re-decoded with `getUnicodePointFromUTF8` and malformed UTF-8 is rejected a second time.

**`### What the lexer does *not* do`**

28. Whitespace and comments are emitted as their own token types by `lexToken`; `lexAllSemanticTokens` and the preprocessor's `ReadAllTokens` filter them so the parser never sees them.

**`### Stack of input streams`**

29. Each `#include`d file gets its own `InputFile` with its own lexer and its own stack of `Conditional` state, so conditional skipping and directive diagnostics are per-file.

**`### Macro expansion`**

30. Macro definitions store an already-lexed token sequence pre-chopped into `Op` entries that expansion replays.
31. A parameter reference compiles to `ExpandedParam`, `UnexpandedParam`, or `StringizedParam` carrying the parameter index.
32. `MacroInvocation` replays the matching argument's token range by index, wrapping it in an `ExpansionInputStream` for the `ExpandedParam` case so argument tokens are themselves expanded.
33. Inactive `#if` branches still flow through the lexer but their contents are not expanded.
34. Only `#if`, `#ifdef`, `#ifndef`, `#else`, `#elif`, and `#endif` are evaluated inside an inactive block.

**`### Preprocessor directives`**

35. Directives are looked up by name in a callback table.
36. `kDirectives` holds `#if` and friends, `#include`, `#define`, `#undef`, `#warning`, `#error`, `#line`, and `#pragma`.
37. It also holds `#language` / `#lang` and `#version` / `#extension`.

**`### #include resolution`**

38. `#include` strings are resolved by `IncludeSystem` against the `Linkage`'s search paths, and the preprocessor pushes a fresh input stream for the resolved `SourceFile`.
39. Angle-form includes concatenate the raw tokens between `OpLess` and `OpGreater` into the path and select system mode; quoted includes take the path from a single `StringLiteral` token.
40. The handler receives a `handleFileDependency` callback per resolved include.

**`### #pragma warning state across files`**

41. `#pragma warning(push/pop/disable/...)` state is tracked per diagnostic id on an absolute source-location timeline.
42. `persistedAbsoluteSourceLocCounter` keeps that timeline globally monotonic across separately preprocessed `__include`d files.
43. A `SLANG_RELEASE_ASSERT` on the handed-back counter guards monotonicity.

**`## Source-location preservation`**

44. Raw body tokens keep the macro-definition `SourceLoc`; no new `SourceView` is made, so the diagnostic points into the macro body rather than at the call site.
45. Argument tokens retain the call-site `SourceLoc`.
46. `__LINE__` / `__FILE__` are pushed by `_pushStreamForSourceLocBuiltin` with `m_macroInvocationLoc`, while the reported value derives from the initiating top-level location.
47. A stringized parameter takes the location of the `#` token in the macro definition.
48. Pasted tokens are re-lexed from a fresh `PathInfo::makeTokenPaste()` view whose origin is the `##` token location.
49. Only the pasted-token case builds an initiating-location chain, emitting a `seeTokenPasteLocation` note per hop.

**`## Failure modes`**

50. Scan-time errors cover an invalid character, malformed UTF-8, EOF or newline in a literal, an invalid digit for the base, a legacy octal literal, and a quote used as a raw-string delimiter.
51. Decode-time errors are reported through the sink passed to the value-extraction helper, and `getIntegerLiteralValue` reports `integerLiteralTooLargeForAnyType`.
52. `getFloatingPointLiteralValue` takes no sink and returns its errors as an enum value plus the offending text.
53. The file-local `diagnose` helper drops a null sink and stops forwarding past `kMaxLexErrorCount` (100).
54. Preprocessor errors emit through the sink and the preprocessor keeps going: a malformed directive is skipped to end of line, a failed `#include` returns, a bad macro invocation can expand to no tokens, and an unclosed conditional is diagnosed at its file's end of file.
55. The single `EndOfFile` token is appended by `ReadAllTokens` only after the whole input stack has been popped.
