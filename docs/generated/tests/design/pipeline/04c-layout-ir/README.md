# Tests for design/pipeline/04c-layout-ir

## Intent

This bundle exercises
[`docs/generated/design/pipeline/04c-layout-ir.md`](../../../../design/pipeline/04c-layout-ir.md),
which covers two coupled stages: the **parameter-binding pass** that
computes a target's `ProgramLayout`, and the **layout IR module** that
transcribes that `ProgramLayout` into `IRLayoutDecoration`s on stub
globals and entry-point functions.

The two halves need different observation points, so the bundle uses two
test families.

**Binding-decision tests** observe the emitted target code directly,
because a binding number, register space or descriptor set is visible in
HLSL `register(...)`, SPIR-V `OpDecorate ... Binding/DescriptorSet`, GLSL
`layout(binding=, set=)` and WGSL `@binding/@group`. These cover the
explicit-reservation ordering, the `vk::binding`-on-entry-point-parameter
target gate, the input-attachment-index space exemption, the bindless
descriptor-heap placement, and the diagnostics that abort binding.

**Layout-IR-shape tests** use
`-target <T> -dump-ir -o /dev/null -entry main -stage compute`. The layout
module is never dumped under a header of its own; its effects appear once
link merges it into the post-link IR, so these tests pin `CHECK-NOT`
patterns to the pre-link `### LOWER-TO-IR:` block and positive `CHECK`
patterns to the first post-link block. That block is matched as
<code>### AFTER &#123;&#123;[A-Za-z0-9_]+&#125;&#125;:</code> rather than
by pass name, because the claim is about the earliest post-link snapshot
and not about any particular pass: which pass runs first there changes as
passes are gated on `RequiredLoweringPassSet` flags and skipped when the
module holds nothing for them to do. Only the _structure_ of the
layout instructions is asserted (`varLayout(`, `offset(`,
`structTypeLayout(`, `parameterGroupTypeLayout(`, `EntryPointLayout(`,
`[layout(%N)]`); the numeric operands inside them are per-target by
design and are never pinned.

Target fan-out follows the claim: layout-IR construction itself is
exercised on all seven text-emit targets (`spirv-asm`, `hlsl`, `glsl`,
`metal`, `wgsl`, `cuda`, `cpp`), while a claim that is gated on the
target — such as `vk::binding` on an entry-point parameter — is split
into an honored-target test and an ignored-target test so both sides of
the gate are pinned. Claims about caches, obfuscation and internal
assertions are recorded under `## Untested claims`.

## Claims

Ground-truth enumeration of the source doc's testable claims, grouped by
its own headings. Every claim below appears in exactly one of the two
tables that follow. Because this page documents a compiler *phase*, the
list splits into two kinds of statement: **user-observable** claims — a
binding number, a descriptor set, a diagnostic code, or a layout
instruction that shows up in emitted text or in `-dump-ir` output — and
**internal-source facts** about the order of the binding stages, the C++

The second kind is not reachable from any `//TEST` directive: the stages

*effect* is observable while its *position* is not. Those claims are
classified in `## Untested claims` rather than tested.

**`## Parameter binding: producing the ProgramLayout`**

1. `createIRModuleForLayout` is a transcription step: every binding number, register space, and byte offset it writes into IR was already decided by parameter binding.
2. Stage 1 builds the `sharedContext.parameters` list and the `programLayout->entryPoints` array, treating entry points much like global parameters.
3. Stage 2 honors `register` / `vk::binding` / `layout(binding=)` on *global* parameters, recording them in the used-range sets before anything is auto-allocated.
4. Stage 3 reserves explicit `vk::binding`s that appear on entry-point parameters.
5. Stage 4 decides whether descriptor set 0 must be reserved for implicitly-placed parameters.
6. Stage 5 claims the first unused space for the default space / constant buffer.
7. Stage 6 auto-allocates every resource kind that is not already placed.
8. Stage 7 places the bindless descriptor heap only when the target implies `CapabilityName::descriptor_handle`.
9. The heap scan starts from the requested `-bindless-space-index` and moves upward to the first space not in `usedSpaces`.
10. When the chosen space is not the requested one and the option was given explicitly, binding warns `39012`, "requested bindless space index '~requested' is unavailable, using the next available index '~available'".
11. `programLayout->bindlessSpaceIndex` is set to the space actually chosen either way.
12. `usedSpaces` is populated only by `markSpaceUsed` and `allocateUnusedSpaces`, and is what the bindless-heap and default-space logic consult.
13. The per-space used-range sets track occupied index ranges *within* a space and drive overlap diagnostics; recording a range does not mark the space used.

**`### Explicit vk::binding on entry-point parameters`**

14. `[[vk::binding(binding, set)]]` on an entry-point parameter is honored exactly on the targets for which `isKhronosTarget(target) || isWGPUTarget(target)` holds, i.e. SPIR-V/GLSL and WGSL.
15. In the worked example the annotated parameter is decorated `Binding 3` / `DescriptorSet 1` for `-target spirv`.
16. For `-target hlsl` the same request is dropped and the parameter is placed positionally as `register(t0)`.
17. An entry-point `vk::binding` can position only `DescriptorTableSlot` for a plain resource, buffer or sampler, and `SubElementRegisterSpace` for a whole-space parameter such as a `ParameterBlock`.
18. The annotation positions a single resource info, preferring the descriptor slot; the register-space case applies only when there is no descriptor slot.
19. The attribute is honored only when the parameter's type actually consumes a descriptor-shaped resource.
20. A `SubpassInput` consumes two kinds at once, so the reservation covers both the descriptor slot and the `InputAttachmentIndex`.
21. Entry points carrying an honored annotation take the per-parameter completion path; all others take the ordinary aggregate path.
22. One entry point can mix explicitly- and implicitly-bound parameters: the explicit reservations are re-seeded and the implicit ones get real bindings allocated from the global context.
23. An entry point whose parameters are all explicitly bound no longer forces a default set.
24. `Diagnostics::UnhandledModOnEntryPointParameter` — warning `38010`, "modifier on entry point parameter is unsupported" — still fires for annotations binding cannot honor, for example a plain varying scalar.

**`### vk::input_attachment_index and descriptor-space occupancy`**

25. A Vulkan input-attachment index lowers to `OpDecorateInputAttachmentIndex` only, never `OpDecorateDescriptorSet`.
26. `addExplicitParameterBinding` skips `markSpaceUsed` for `InputAttachmentIndex`.
27. The index range is still recorded in the used-range set, so two parameters asking for the same attachment index still draw `Diagnostics::ParameterBindingsOverlap` — warning `39001`, "explicit binding overlap".
28. `doesEntryPointParameterResourceNeedDefaultSpace` returns `false` for `InputAttachmentIndex` alongside `PushConstantBuffer`, `RegisterSpace`, `SubElementRegisterSpace`, `VaryingInput`, `VaryingOutput`, `HitAttributes` and `RayPayload`; every other kind falls through the `default:` arm and returns `true`.
29. The observable effect is that a `SubpassInput` entry-point parameter no longer causes descriptor set 0 to be reported unavailable to the bindless descriptor heap.
30. `VaryingInput` / `VaryingOutput` (with `[[vk::location]]`) and `SpecializationConstant` (with `[[vk::constant_id]]`) reach the same branch with the same placeholder space 0 and share the latent pattern, but the guard was not widened to them.

**`### Diagnosed failures during binding`**

31. Parameter binding can fail with diagnostics rather than producing a `ProgramLayout`; `getOrCreateLayout` then returns `nullptr` and no layout IR module is built.
32. A null return from `getRayPayloadParameterRules` / `getCallablePayloadParameterRules` / `getHitAttributesParameterRules` is diagnosed as error `39032`, "the current compilation target does not support ray tracing entry point parameters for the '~stage' stage", instead of being dereferenced.
33. The Metal, CPU and LLVM layout-rules families return `nullptr` from all three accessors.
34. The CUDA family returns `nullptr` from `getCallablePayloadParameterRules` alone.
35. The SPIR-V/GLSL, HLSL/DXIL and WGSL families supply all three accessors.
36. The worked `miss` example compiles for `-target spirv` but is rejected with error `39032` for `-target metal` and `-target cpp`.
37. This is a target-limitation diagnostic, distinct from the pre-existing stage-limitation diagnostics, because callable and hit stages do support these parameters on SPIR-V, HLSL and GLSL.

**`## Why this module exists`**

38. Layout is target-specific: the same source program can have different binding numbers, register spaces, byte offsets and entry-point parameter mappings for D3D11, D3D12, Vulkan, Metal, WebGPU and CUDA.
39. Carrying layout information inside an IR module makes it queryable by the reflection API and consumable by the linker.
40. Keeping it in a separate module avoids contaminating the per-translation-unit executable IR, which is cached on the `Module` and shared across all targets.

**`## When it is built`**

41. The layout module is built together with the `ProgramLayout` inside `getOrCreateLayout`, so any caller that asks for the program layout also pays for it.
42. `getOrCreateIRModuleForLayout` is a two-line wrapper that calls `getOrCreateLayout` and then returns the now-populated field.
43. Nothing is built when binding failed, and the absence is directly observable: a `-dump-ir` run prints the `### LOWER-TO-IR:` block and then stops, with no `EntryPointLayout(`, `structTypeLayout(` or `[layout(` anywhere in the output.
44. `createIRModuleForLayout` returns the cached module immediately when one exists, asserts `m_layout` is non-null, and otherwise bails out with `nullptr`.
45. The layout module does not run the pre-link mandatory optimization sequence; it is consumed by reflection and by `linkIR`, which adds it to its module list so layout-decorated global symbols participate in linking.

**`## Per-global-parameter steps`**

46. Step 1 materializes a stub `IRGlobalVar`, producing an `[import(...)]` stub when no definition is present, and fails with `SLANG_UNEXPECTED("unhandled value flavor")` if materialize returns null.
47. Step 2 lowers the variable layout to an `IRVarLayout` encoding binding, space and byte offset.
48. Step 3 attaches the `IRLayoutDecoration` that makes the layout queryable on the stub.
49. Step 4 records the stub in the global type-layout builder, feeding the module-level `IRStructTypeLayout`.
50. The loop runs once per field of the global struct layout.

**`## Global-scope type layout`**

51. After the loop the function builds an `IRStructTypeLayout` for the whole global scope.
52. When the global scope is wrapped in a parameter group (a constant buffer or push-constant block), the module's layout decoration is an `IRParameterGroupTypeLayout` rather than the raw struct layout.
53. The parameter-group builder sets the container var layout, the element var layout and the offset element type layout.
54. The resulting global-scope var layout is attached to the module instance via `addLayoutDecoration(irModule->getModuleInst(), ...)`.

**`## Per-entry-point steps`**

55. Step 1 skips entry points with no AST, because the layout-IR module cannot synthesize a stub for a deserialized entry point.
56. Step 2 skips unspecialized generic entry points, which do not yet have a concrete layout.
57. Step 3 lowers the function type to an `IRFuncType`.
58. Step 4 materializes the stub `IRFunc` skeleton, usually `[import(...)]`.
59. Step 5 attaches an import decoration when the stub has no linkage, wiring it to its real implementation by mangled name.
60. Step 6 forwards capability atoms in `[_spirv_1_0, latestSpirvAtom]` or `[metallib_2_3, latestMetalAtom]`, so the layout module advertises the SPIR-V / Metal capability set per entry point.
61. Step 7 lowers the entry-point layout to an `IREntryPointLayout` that encodes parameter bindings and stage.
62. Step 8 attaches the `IRLayoutDecoration` that the reflection API and the linker query.

**`## Optional obfuscation pass`**

63. `shouldObfuscateCode()` gates a strip of name hints and source locations followed by a DCE run with `keepExportsAlive` and `keepLayoutsAlive` set.
64. The layout module sets `stripSourceLocs = true` where the executable-module block sets it to `false`, and sets `shouldStripNameHints = true` unconditionally inside the gate.
65. Nothing about this block is separately observable from outside the compiler; with `-obfuscate` both modules lose their name hints together.

**`## What this module is not`**

66. It is not the per-module executable IR produced by `generateIRForTranslationUnit`.
67. It is not the executable IR optimized by `linkAndOptimizeIR`, though `linkIR` does pull it into its symbol set so its layout decorations are visible during linking.
68. It has no function bodies for user-defined functions; entry-point `IRFunc` instances are stubs that only anchor layout and capability decorations.
69. No mandatory optimization passes run there: the `constructSSA` -> SCCP -> CFG-simplify -> peephole -> DCE -> early-inlining sequence does not execute on this module.

**`## Cache and reuse`**

70. The result is cached on `TargetProgram::m_irModuleForLayout`, so a second `getOrCreateIRModuleForLayout` call for the same `TargetProgram` returns the same module without re-running construction.
71. Different `TargetProgram` instances build independent layout IR modules, so a session compiling for both D3D12 and Vulkan holds two of them.
72. `createIRModuleForLayout` is `private` and its only in-tree caller is `getOrCreateLayout`.
73. `getExistingIRModuleForLayout()` peeks at the cache without forcing construction and returns `nullptr` when nothing has been built yet.

**`## Caveats and gotchas`**

74. Materialize failure is a hard error: an unhandled value flavor for a global parameter aborts with `SLANG_UNEXPECTED`.
75. `m_layout` must be set — a debug build asserts and a release build returns `nullptr`.
76. Capability decorations are SPIR-V- and Metal-only; the decoration is `IRRequireCapabilityAtomDecoration`, printed by the IR dumper as `[requireCapabilityAtom(...)]`, and there is no observation point at which it can be attributed to the *layout* module.
77. `buildMangledNameToGlobalInstMap` runs unconditionally, so consumers always get a usable mangled-name index.
78. The entry-point loop asserts that the entry-point declaration is a `FuncDecl` before reading its inferred capability requirements.

**`## Option gates`**

79. `-obfuscate` enables the strip + DCE block at the end of `createIRModuleForLayout` and is also passed to the `SharedIRGenContext` constructor.
80. `-bindless-space-index <index>` requests a specific descriptor space for the bindless descriptor heap, honored only if that space is not already in `usedSpaces`.
81. Other options in the compiler-options header, including `shouldIncludeSourceInDebugInfo()`, belong to debug information and codegen and have no effect on either parameter binding or the layout IR module.
