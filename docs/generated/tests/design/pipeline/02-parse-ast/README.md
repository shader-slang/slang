# Tests for design/pipeline/02-parse-ast

## Intent

This bundle exercises the parsing stage described in
[`docs/generated/design/pipeline/02-parse-ast.md`](../../../../design/pipeline/02-parse-ast.md):
how a flat post-preprocess token list becomes a strongly-typed AST. The
claims decomposed into tests come from the doc's own sub-sections —
two-stage parsing (decl-stage capture of `UnparsedStmt` and the
body-stage re-parse), syntax-as-declaration (keywords bound to parse
callbacks through the `SyntaxParseInfo` table rather than reserved by the
lexer), error recovery (the recovering flag, `TryRecover`'s
recover-before / recover-after sets, and balanced-group skipping), the
five user-observable AST node families, `ASTBuilder` type interning, the
`<` disambiguation strategy and every generic-constraint spelling the
doc enumerates, interface associated-type / `__constraint` requirements,
modifier and attribute parsing, and the parse-time diagnostics listed
under `## Failure modes` (keyword-used-as-name, operator-name-on-a-
non-function, and the floating-point literal classification and range
reports).

Coverage strategy: one test per claim, plus extra probes on the axes the
doc itself commits to — every constraint spelling, every declaration
kind the shared declarator path covers, and the three float-literal
range/precision edges. Parser claims are target-independent, so the
functional tests use `//TEST:INTERPRET` rather than a per-target emission
fan-out; the one matrix probe uses CPU `COMPARE_COMPUTE` because the
interpreter has no matrix precedent in the suite. Rejection claims use
`//DIAGNOSTIC_TEST:SIMPLE` in exhaustive mode, so "exactly this
diagnostic and no other" is part of the assertion — that is what makes
the cascade-suppression and not-flagged-twice claims testable at all.
Lex-surface and keyword-inventory claims stay in
`design/pipeline/01-lex-preprocess` and
`design/syntax-reference/keywords-and-builtins`; every test here fails
because of something the parser (or the checking pass the doc explicitly
hands off to) did.
