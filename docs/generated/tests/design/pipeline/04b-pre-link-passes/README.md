[`docs/generated/design/pipeline/04b-pre-link-passes.md`](../../../../design/pipeline/04b-pre-link-passes.md):

The coverage strategy is one test per documented pass or gate, observed
at the one point where that pass is visible. For the passes that change
IR shape, `-dump-ir` emits a `### LOWER-TO-IR:` block holding the

with
`//TEST:SIMPLE(filecheck=CHECK):-target spirv-asm -dump-ir -o /dev/null -entry main -stage compute`.
For the Phase D validators, which surface as diagnostics rather than as
IR shape, the tests use `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` with
caret-anchored annotations and the diagnostic code.

Every conditional gate the doc lists is covered by a paired test: the
same shader is compiled with and without the toggle in one file, using a
distinct FileCheck prefix per run, so the row being verified is the
_difference_ the gate makes rather than the pass in isolation. That

non-essential-validation toggle (D1 / D3-D9), obfuscation's
name-hint stripping (D10), and the three trace-coverage toggles.

The claims that have no observation point at all under any allowed
directive -- module-instruction decorations the dump does not print,

**`# Pre-link mandatory passes` (framing)**

1. The pre-link pass sequence runs inside `generateIRForTranslationUnit` before the per-translation-unit IR module is cached on the `Module`.
2. The pipeline is target-agnostic: the same passes run for every shader target.
3. The calls in this region are plain function calls of the form `passName(module)` / `passName(module, sink)` and do not use the `SLANG_PASS(...)` macro that wraps the post-link passes.

**`## High-level phase diagram`**

4. All four phases live in the body of `generateIRForTranslationUnit`, which is called once per translation unit.
5. The cached `IRModule` returned by Phase D is the input to `linkIR` and from there to `linkAndOptimizeIR`.
6. The exact ordering of A1-A10, B1-B6, C1-C7 and D1-D15 within the pipeline.

**`## Phase A: AST walk and IR emission`**

7. A1 `IRModule::create(session)` creates the empty module the rest of the pipeline mutates.
8. A2 `module->setName(moduleDecl->getName())` records the module's source-level name.
9. A3 attaches `kIROp_ExperimentalModuleDecoration` when the module declaration carries the `[ExperimentalModule]` attribute.
10. A4 `emitDebugSource` runs per source file whenever `debugInfoLevel != None` and embeds the most-unique-identity path for every source file.
11. A4 carries the source _text_ only when `debugInfoLevel >= Standard` **or** `shouldIncludeSourceInDebugInfo()` is set, so `-debug-info-include-source` lets a `Minimal` build carry full source text without promoting the debug-info level.
12. Every `IRDebugSource` produced in A4 is recorded in `mapSourceFileToDebugSourceInst`, which later per-decl lowering consults rather than re-emitting.
13. A5 `emitDebugCompilationUnit` runs per non-included source when `debugInfoLevel >= Standard`, making the IR the source of truth for which files are compilation units.
14. A6 `lowerFrontEndEntryPointToIR` runs per entry point, establishing the entry-point `IRFunc` skeleton before the full decl walk.
15. A7 `ensureAllDeclsRec` walks the declaration tree per direct module-decl member and lowers every public/exported symbol.
16. A8 emits a single `kIROp_GlobalHashedStringLiterals` aggregate holding every hashed string literal observed during lowering, when the string-literal count is non-zero.
17. A9 attaches the module-level NVAPI register/space binding when the module declaration carries an `NVAPISlotModifier`, which the front end attaches when `NV_SHADER_EXTN_SLOT` and `NV_SHADER_EXTN_REGISTER_SPACE` are defined.
18. A10 `validateIRModuleIfEnabled` closes Phase A with a structural sanity check that is a no-op unless validation is enabled at the compiler-option level.
19. A3 and A9 attach their decorations to the module instruction rather than to a global symbol, so neither appears in a `-dump-ir` listing.
20. The `#if 0` `dumpIR(..., "GENERATED", ...)` block is intentionally disabled in production builds.

**`## Phase B: Mandatory pre-optimization transformations`**

21. B1 `prelinkIR` imports the bodies of the cross-module `[unsafeForceInlineEarly]` functions collected in `externalSymbolsToPrelink` so later passes can inline and simplify them.
22. B2 `lowerErrorHandling` rewrites throwing functions to return `Result<T,E>` and translates `tryCall` into `call` + `ifElse`, leaving the IR free of `throw` / `tryCall`.
23. B3 `lowerDefer` lowers the `defer` statement so later passes can assume linear control flow.
24. B3 duplicates the defer's child instructions to the end of every dominated block whose terminator jumps somewhere the defer does not dominate, then removes all `IRDefer` insts.
25. B4 `synthesizeBitFieldAccessors` synthesizes get/set bodies for bit-field accessors, placed before the Phase C inlining loop so those bodies can be inlined and simplified.
26. B5 `lowerExpandType` rewrites `IRExpandType` so the pattern type is nested under `IRExpand` rather than being a same-level sibling, unifying variadic-generics specialization.
27. B6 `insertDebugValueStore` emits `DebugValue` insts binding locals to their abstract debug variables when `debugInfoLevel >= Standard`.

**`## Phase C: Mandatory optimization passes`**

28. C1 `constructSSA` promotes addressable locals to SSA temporaries module-wide.
29. C2 `applySparseConditionalConstantPropagation` runs SCCP over the freshly constructed SSA.
30. C3 `simplifyCFG` removes empty and unreachable blocks, gated on `!minimumOptimizations`.
31. C4 `peepholeOptimize` runs the pre-linking peephole subset, gated on `!minimumOptimizations`; the full peephole runs post-link.
32. C5 runs `eliminateDeadCode` once over every `IRGlobalValueWithCode`, with `keepExportsAlive`, `keepLayoutsAlive` and `useFastAnalysis` all set.
33. C5 iterates over functions but not over passes; it is one pipeline step whose effect happens to be per-function, as are A6 and A7.
34. C6 `invertLoops` runs under the `LoopInversion` toggle, moving loop condition checks to the end of the loop and wrapping the loop in an outer `if`.
35. C7 `performMandatoryEarlyInlining` honors `[unsafeForceInlineEarly]` as a hard requirement, not a hint: functions tagged with it must not survive the pre-link pipeline.

**`## Phase D: Non-essential validation, stripping, and finalization`**

36. D1 `checkForRecursiveTypes` disallows recursive type definitions, emitting `E41001` for input such as `struct Bad { Bad next; }`.
37. D2 returns early from Phase D when `sink->getErrorCount() != 0`, before propagation and the later passes.
38. D3 `propagateConstExpr` propagates `constexpr`-ness through the dataflow and call graph, retyping every value it proves constant to `@ConstExpr T`.
39. D3 diagnoses only where a `constexpr` demand cannot be met, emitting `E40012` / `E40013` when a non-constant value reaches a `constexpr` parameter.
40. D4 `checkForUsingUninitializedValues` is a dataflow check requiring SSA + SCCP from Phase C, emitting `W41016` for `int x; buf[0] = x;`.
41. D5 `checkForMissingReturns` runs with `target=None` so it is target-agnostic pre-link, emitting `W41010` for a non-void function that does not return in all cases.
42. D6 `checkAutoDiffUsages` validates the bodies of `[Differentiable]` functions, emitting `E41022` for a call a derivative cannot be propagated through.
43. D7 `checkForOperatorShiftOverflow` flags shift counts that exceed the operand width, emitting `W41030` for `a << 40` where `a` is a `uniform int`.
44. D7 sees only the shifts that survive Phase C: an all-literal shift such as `1 << 40` has already been folded by C2's `evalLsh`, so no `Lsh` is left to flag.
45. `W41034` covers the complementary case of a non-literal shift amount whose type is wider than a narrow (under 32-bit) left operand, which Slang does not promote before shifting.
46. D8 `addDecorationsForGenericsSpecializedWithExistentials` runs under `shouldRunNonEssentialValidation` and language version 2025 or later.
47. D8 does not diagnose; it only attaches `IRDisallowSpecializationWithExistentialsDecoration` to the offending `specialize` instruction.
48. The user-visible error `E33180` is raised post-link by the typeflow specialization pass, which also recognizes the shape by scanning function bodies, so turning off non-essential validation does not make the error go away.
49. D9 `checkForMeshOutputReads` rejects reading from mesh-shader outputs, emitting `E54005`.
50. D10 `stripFrontEndOnlyInstructions` always removes `IRHighLevelDeclDecoration` and `IRInParamProxyVarDecoration`.
51. D10 removes `IRNameHintDecoration` only when `options.shouldStripNameHints` is set, which the pre-link caller ties to `shouldObfuscateCode()`.
52. D10's `stripSourceLocs` is set to `false` unconditionally by the pre-link caller, so locations are never cleared here.
53. D11 `stripImportedWitnessTable` removes the _nested_ witness tables held directly as children of every imported global witness table, leaving the table's other entries in place.
54. D12 `eliminateDeadCode` cleans up everything orphaned by D10 and D11, keeping exports and layouts alive.
55. D13 `obfuscateModuleLocs` runs only when `shouldStripNameHints` and `shouldHaveSourceMap()` are both true; with obfuscation but no source map, name hints go and the original locs stay.
56. D14 `validateIRModuleIfEnabled` runs a structural sanity check after stripping.
57. D15 `module->buildMangledNameToGlobalInstMap()` is the last statement before the module is returned, building the lookup index `linkIR` consumes.
58. The `shouldDumpIR()` block between D14 and D15, tagged `"LOWER-TO-IR"`, is an optional dump and not a pipeline step; it does not mutate the module.

**`### Option-set toggles`**

59. `shouldPerformMinimumOptimizations()` gates C3, C4, and the inner per-modified-function cluster inside the Phase C inlining loop.
60. `shouldRunNonEssentialValidation()` gates D1 and D3-D9.
61. `shouldObfuscateCode()` gates the `shouldStripNameHints` flag in D10 and, with `shouldHaveSourceMap()`, D13.
62. `getBoolOption(CompilerOptionName::LoopInversion)` gates C6.
63. The three trace-coverage toggles (`-trace-coverage`, `-trace-function-coverage`, `-trace-branch-coverage`) do not gate a pass here; they set `context->trace*` fields that propagate into per-decl lowering inside A6/A7.
64. Trace-coverage lowering emits `kIROp_IncrementCoverageCounter` before every executable statement, `kIROp_IncrementFunctionCoverageCounter` at the head of each lowered function body, and `kIROp_IncrementBranchCoverageCounter` on each `if` arm, loop-condition arm and `switch` arm.
65. All three counter kinds are already present in the pre-link IR because they come from lowering; the pass that turns them into stores through `__slang_coverage` runs post-link.
66. `getDebugInfoLevel()` gates A4 (any level above `None`), A5 (`Standard` or higher) and B6 (`Standard` or higher), read once from `context->debugInfoLevel`.
67. `shouldIncludeSourceInDebugInfo()` is not a pass gate and does not enable A4 on its own; `debugInfoLevel != None` is still required.

**`### Context predicates` / `### Per-translation-unit predicates`**

68. `sink->getErrorCount() != 0` drives D2's early return.
69. `moduleDecl->findModifier<ExperimentalModuleAttribute>()` drives A3, and `moduleDecl->findModifier<NVAPISlotModifier>()` drives A9.
70. `moduleDecl->languageVersion >= SLANG_LANGUAGE_VERSION_2025` gates D8.

**`## Loops in the pipeline`**

71. The pre-link pipeline contains exactly one pass-level loop, the unbounded `for(;;)` `performMandatoryEarlyInlining` fixed point, with no iteration cap.
72. The loop reuses a single `changed` flag: inlining sets it, `peepholeOptimizeGlobalScope` overwrites it, the per-modified-function cluster OR-assigns into it, and the loop breaks once that final value is `false`.
73. If inlining reports `false` the `if (changed)` block is skipped and the loop breaks immediately.

**`### prelinkIR`**

74. `prelinkIR` is not the same as the post-link `linkIR`: it runs once per translation unit before optimization, and its entire work list is `externalSymbolsToPrelink`.
75. `externalSymbolsToPrelink` has exactly one producer, `lowerFuncDeclInContext`, which adds the imported `IRFunc` when the decl is both in a different module and force-inline-early.
76. For each entry `prelinkIR` looks up the same mangled name, strips the placeholder's `IRLinkageDecoration`, clones the imported definition in its place, and `replaceUsesWith`es the placeholder.
77. The placeholder is left parented in the module tree until after `replaceUsesWith` so insts nested inside it do not become orphaned mid-clone.
78. Cloning is shallow by default: a `kIROp_Func` is cloned with its body only when it carries `IRUnsafeForceInlineEarlyDecoration`; every other referenced symbol is cloned as a bodiless declaration marked `[Import]`.
79. `prelinkIR` calls `_ensureLinkingInfo()` on every stable input module but not on `irModule` itself, and the linking-info cache is a performance cache only that does not change which symbols are imported.
80. `IRSharedSpecContext::isFinalCodegenLink` is false for `prelinkIR` and true only for `linkIR`, feeding `canPruneAutodiffLinkArtifacts()`.
81. `cloneAnnotations` skips every module-scope `IRAnnotation` when pruning is allowed, guarded by a `static_assert` on `AnnotationKind::CountOf`.
82. `shouldDeepCloneWitnessTable` returns `!canPruneAutodiffLinkArtifacts()` for a differentiable-interface witness table, and is reached only after the unconditional keep-alive cases return `true`.
83. Even when pruning is allowed, `cloneWitnessTableImpl` still eagerly clones `IRBuiltinRequirementKey`-keyed entries; only mangled-name-keyed derivative methods are held back.
84. Because `prelinkIR` leaves `isFinalCodegenLink` false, it always clones annotations and always deep-clones differentiable-interface witness tables.
85. Neither policy changes emitted code; what differs is an intermediate module shape, and no dump isolates it because `linkIR` is called outside the pass wrapper that produces `### AFTER <pass>:` blocks.
86. `doesModuleUseAutodiff` is a full recursive walk of the module inst tree, but the `useAutodiff` value prelink computes has no observable effect on prelink's output.

**`### stripFrontEndOnlyInstructions` / `### obfuscateModuleLocs` / `### module->buildMangledNameToGlobalInstMap`**

87. "Front-end-only" is a short explicit list decided by `_shouldStripInst`, which walks the whole module inst tree.
88. The mandatory passes use `IRHighLevelDeclDecoration` to point diagnostics back at AST-level code, and it is dropped at the phase boundary so that information does not reach code generation.
89. `obfuscateModuleLocs` generates obfuscated source locations together with the matching source map.

**`## Adjacent constructs`**

90. `SpecializedComponentTypeIRGenContext::process` builds a small IR module recording how specialization arguments bind to specialization parameters and does not run the mandatory passes; the only step it shares with Phase D is `buildMangledNameToGlobalInstMap`.
91. `TargetProgram::createIRModuleForLayout` produces a separate per-target layout-metadata module that contains no executable bodies, does not copy the executable IR, and does not run the mandatory passes.
