# Tests for design/pipeline/04b-pre-link-passes

## Intent

This bundle exercises the pre-link IR-pass sequence described in
[`docs/generated/design/pipeline/04b-pre-link-passes.md`](../../../../design/pipeline/04b-pre-link-passes.md):
the Phase A / B / C / D steps that run inside
`generateIRForTranslationUnit` before the per-translation-unit IR
module is cached and later pulled into `linkAndOptimizeIR`.

The coverage strategy is one test per documented pass or gate, observed
at the one point where that pass is visible. For the passes that change
IR shape, `-dump-ir` emits a `### LOWER-TO-IR:` block holding the
snapshot taken at the end of Phase D, and the tests FileCheck that block
with
`//TEST:SIMPLE(filecheck=CHECK):-target spirv-asm -dump-ir -o /dev/null -entry main -stage compute`.
For the Phase D validators, which surface as diagnostics rather than as
IR shape, the tests use `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` with
caret-anchored annotations and the diagnostic code.

Every conditional gate the doc lists is covered by a paired test: the
same shader is compiled with and without the toggle in one file, using a
distinct FileCheck prefix per run, so the row being verified is the
_difference_ the gate makes rather than the pass in isolation. That
pattern covers the debug-info levels (A4 / A5 / B6), the
minimum-optimizations toggle (C3 / C4), loop inversion (C6), the
non-essential-validation toggle (D1 / D3-D9), obfuscation's
name-hint stripping (D10), and the three trace-coverage toggles.

The claims that have no observation point at all under any allowed
directive -- module-instruction decorations the dump does not print,
prelink's internal clone policy, the inlining loop's flag threading --
are recorded under `## Untested claims` rather than tested. This bundle
carries more files than the 12-18 range the co-located `_prompt.md`
suggests because the source doc has since grown the debug-info,
trace-coverage, and auto-diff-pruning material; the count is still well
inside the manifest's `size_cap_files`.
