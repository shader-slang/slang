# Tests for design/pipeline/06-emit

## Intent

This bundle exercises the code-emission stage described in
[`docs/generated/design/pipeline/06-emit.md`](../../../../design/pipeline/06-emit.md):
the two-level emit dispatcher that picks a path per `CodeGenTarget` and then a
`CLikeSourceEmitter` subclass per source language, the per-target backends
(HLSL, GLSL, direct SPIR-V, Metal, WGSL, C++, CUDA, Torch, VM), the
`SourceWriter` and its `LineDirectiveMode`, the precedence helper, and the
prelude table.

Emission is the one stage whose defining characteristic is per-target output,
so the bundle is deliberately multi-backend-heavy: most files carry one
`//TEST:SIMPLE` directive per text-emit target the claim is observable on, with
a distinct FileCheck prefix each, and assert the marker only that backend
produces. The coverage strategy is (a) one dispatcher smoke test across all
seven text targets plus one for the header-variant targets and one for the
`*Assembly` recursive-disassembly path; (b) one focused test per documented
backend section; (c) the backend-specific divergences the doc calls out by
name — WGSL's two switch overrides, `emitTempModifiers` on Metal/WGSL, Metal's
logging requirement, the HLSL named-constant rules for work-graph attributes,
barrier flag sets and record types, and the VM's global-parameter diagnostic;
(d) the two halves of the parenthesization rule (semantically required parens
kept, plus the deliberate extra parens on bitwise / shift / relational-equality
combinations that ordinary arithmetic does not get); (e) the `#line` behaviour
in all three line-directive modes (C-style, GLSL numeric, none); (f) the
prelude table and its complement; and (g) boundary probes on the emission of
literals and workgroup sizes that the shared C-like base is responsible for.

## Claims

Enumerated from `docs/generated/design/pipeline/06-emit.md` at
`source_doc_digest`, grouped by the doc's own headings. Every claim appears in
either `## Functional coverage` or `## Untested claims` above.

**Inputs and outputs**

1. The input is a linked, specialized, target-lowered `IRModule` for one `TargetRequest`; direct SPIR-V additionally runs `legalizeIRForSPIRV` inside `emitSPIRVFromIR` rather than before it.
2. The output is an `IArtifact` carrying the text or binary plus an optional source-map artifact, with post-emit metadata attached per path.
3. Dependency-file output is not attached to the artefact; it goes to a separately configured path.

**Emit dispatcher**

4. The outer dispatcher splits textual targets (HLSL, GLSL, Metal, WGSL, the C/C++/CUDA source and header variants, PyTorch binding) from the binary / host ones.
5. `*Assembly` targets are served by a recursive compile of the corresponding binary target followed by downstream disassembly.
6. `emitEntryPointsSource` passes user source straight through for pass-through compilation.
7. Line-directive mode is resolved per target: GLSL targets default to the GLSL mode, WGSL targets to `None`.
8. The PyTorch binding target is special-cased to the Torch emitter; every other target maps through its source language to one of the six `CLikeSourceEmitter` subclasses.
9. A target with no emitter fails with `UnableToGenerateCodeForTarget`.
10. The C / C++ / CUDA source languages clear `shouldLegalizeExistentialAndResourceTypes`.
11. Backends consult the precedence helper as they print expressions.
12. The final text is stitched as front matter, prelude, pre-module, then module body.

**HLSL**

13. The HLSL backend emits HLSL source text with HLSL entry-point and resource annotations.
14. Named constants are never emitted as raw integers: work-graph attributes are re-emitted from their decorations, including `[NodeLaunch("...")]`'s string payload.
15. Barrier flag sets are expanded into DXC's flag tokens joined with `\|`.
16. `shouldFoldInstIntoUseSites` forces the flag getters into their use site.
17. Work-graph record types are spelled by mapping the IR opcode to the HLSL type name with the element type as a generic argument.

**GLSL / SPIR-V**

18. The GLSL backend emits GLSL source text, consumed by `slang-glslang` for the SPIR-V-via-GLSL route.
19. The direct SPIR-V backend emits a complete SPIR-V module without going through GLSL.
20. `createArtifactFromIR` loads a downstream compiler only under four named conditions.

**Metal / WGSL**

21. The Metal backend emits Metal Shading Language.
22. Metal's inline builtin snippets are injected through `ensurePrelude` and compiled into the emitter.
23. The retained `MetalExtensionTracker` carries `requireMetalLanguageVersion` and `requireLogging` past emission; `requireLogging` is what the `printf` path needs.
24. The WGSL backend emits WGSL.
25. WGSL overrides `supportsSwitchFallThrough` to false.
26. WGSL overrides `shouldEmitSwitchCaseTerminatingBreak` to false; only the trailing break is dropped, early breaks are still emitted.

**C++ / CUDA / Torch / LLVM / VM / Slang round-trip**

27. The C++ backend emits C++ source paired with the C++ preludes.
28. The CUDA backend emits CUDA source with the CUDA prelude.
29. The Torch backend emits PyTorch C++ glue with the Torch prelude.
30. The LLVM backend produces assembly, object code, or a JIT library depending on the target.
31. The VM backend builds interpreter bytecode, and reports `GlobalParamNotSupportedByInterpreter` once per referenced global parameter, returning `SLANG_FAIL`.
32. `emitSlangDeclarationsForEntryPoints` is a stub producing an empty string.

**Shared C-like base**

33. The textual backends share `CLikeSourceEmitter`, which walks the IR and emits one declaration at a time behind a virtual per-target interface.
34. `SourceEmitterBase` is also the base of the SPIR-V emit and legalization contexts; LLVM and VM do not use it.
35. `CUDASourceEmitter` and `TorchCppSourceEmitter` derive from `CPPSourceEmitter`.
36. Purely syntactic divergences go through small virtual predicates, including `emitTempModifiers`, overridden by C++, Metal and WGSL, with a `PreciseQualifierUnsupportedOnTarget` diagnostic.

**Source writer**

37. `advanceToSourceLocation` emits `#line` directives so downstream compilers report errors at the user's source position.
38. `LineDirectiveMode` configures the directive style (C / GLSL / none).
39. `indent()` / `dedent()` manage indentation.
40. A `SourceMap` companion carries source-mapping debug information.

**Operator precedence**

41. Emitted code is precedence-aware rather than minimally parenthesized; semantically required parentheses are kept.
42. `maybeEmitParens` deliberately forces extra parentheses around bitwise, logical, relational, equality and shift combinations.

**Preludes**

43. The targets in the preludes table ship a `prelude/` header the emitted code includes.
44. The prelude is chosen right after the front matter: Torch prelude for the PyTorch binding, C++ host prelude for a heterogeneous target, otherwise the prelude registered for the source language.
45. GLSL, Metal, WGSL and SPIR-V have no `prelude/` header.

46. `writeDependencyFile` writes Make-style rules and is a no-op unless an output path was requested.
