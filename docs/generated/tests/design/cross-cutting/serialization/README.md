# Tests for design/cross-cutting/serialization

## Intent

This bundle exercises the claims in
[`docs/generated/design/cross-cutting/serialization.md`](../../../../design/cross-cutting/serialization.md)
that reach the `slangc` command line. The strategy is the round-trip:
write a `.slang-module` container with `-o`, read it back with
`-dump-module` or `-get-module-info`, and assert that a property the
doc says is carried across the boundary is still there. Four properties
are probed that way — the checked AST/IR of a public symbol, the
parent/child nesting the flat-module read path has to rebuild, the
string payload the flat encoding keeps in side tables, and the raw bits
of numeric and bool constants at their representable extremes. Two more
tests pair a positive and a negative on the container's composition
(`-embed-downstream-ir` adds a SPIR-V blob; without it nothing
downstream is attached), two tests read the version surfaces
(`-get-module-info`, `-get-supported-module-versions`), and four cover
source-location round-tripping, fanning `#line` emission out across
every text-emit target plus SPIR-V debug info, with a
`-line-directive-mode` counterfactual that is itself fanned out across
HLSL, GLSL, Metal and WGSL (SPIR-V ignores the option, and the
SPIR-V debug-info claim names instructions no text emitter has, so both
are recorded as `unsupported-on-target` below rather than forced). The
fourth of those is the `#line`-adjustment probe: one file that contains
a `#line` directive renders the physical path for a location before it
and the overridden path plus remapped index for a location after it, so
both halves of an `AdjustedLineInfo` are asserted in a single emit.

The bundle is small by construction: most of the source doc is about
C++ headers, template patterns, and binary chunk layouts with no CLI
observable, so the `serialize()` pattern, the Fossil memory-mapping
design, the RIFF chunk codes, the flat-table validation asserts, the
recursion budget, and the deprecated repro format all land under
`## Untested claims` instead.

### A. User-observable claims

**`#what-is-serialized`**

1. `slangc <source> -o <output>.slang-module` writes a container. — `module-roundtrip-preserves-public-symbol.slang`, `module-info-name-version.slang`
2. `-dump-module` reads a container back and prints the deserialized IR. — `module-roundtrip-preserves-public-symbol.slang`, `module-roundtrip-rebuilds-nested-children.slang`
3. `-get-module-info` reads a container back and prints the module's name, its module version, and the version of the compiler that wrote it, without deserializing the instruction graph. — `module-info-name-version.slang`
4. The serialized AST form preserves the checked AST that backs an `import`-able module. — `module-roundtrip-preserves-public-symbol.slang`

**`#riff-container-format`**

5. Container-level orchestration composes a serialized AST module, a serialized IR module and the auxiliary data into one hierarchy. — `module-roundtrip-preserves-public-symbol.slang`, `no-embed-downstream-ir-absent.slang`
6. The precompiled downstream artefact that `-embed-downstream-ir` requests is not a chunk of its own; it rides inside the IR payload as an ordinary instruction. — `embed-downstream-ir-spirv.slang`
7. Reading the file back with `-dump-module` therefore prints it inside the IR listing, as `EmbeddedDownstreamIR(<targetCode> : Int, ...)`. — `embed-downstream-ir-spirv.slang`, `no-embed-downstream-ir-absent.slang`

**`#ir-flat-module-read-path`**

8. `deserializeFromFlatModule` allocates every instruction up front and then rebuilds the parent/child links, so nested declarations survive a write/read round-trip. — `module-roundtrip-rebuilds-nested-children.slang`
9. `stringLengths` plus the concatenated `stringChars` carry string payloads, so a string literal reappears verbatim after a round-trip. — `module-roundtrip-preserves-string-literal.slang`
10. The `literals` list holds the raw bits of every bool / integer / float / pointer constant, so integer extremes reload with their exact values. — `module-roundtrip-preserves-integer-literal-bounds.slang`
11. The same list covers float and bool constants, so `0.0`, `-0.0`, the largest finite float, `+inf` and both bool values reload unchanged. — `module-roundtrip-preserves-float-and-bool-literals.slang`

**`#source-location-serialization`**

12. The serializer captures, per contributing source file, its path, its source-location range, its total line count, and one line-start record per reached line, so file path and line number survive to emit. — `source-loc-line-directives-multi-target.slang`
13. The emitted directives are the rendering of the retained locations rather than a fixed preamble: `-line-directive-mode none` drops them and the `glsl` mode renders a file number instead of a path. — `source-loc-line-directive-mode-variants.slang`
14. With debug info requested the retained path and line numbers reach SPIR-V. — `source-loc-spirv-debug-info.slang`
15. A reached line lands in exactly one of two lists, chosen by whether a `#line` directive was in effect there: a plain `LineInfo` when the view has no covering entry, an `AdjustedLineInfo` — the physical record plus the remapped line index and the overridden path — when it does. — `source-loc-line-directive-remaps-line-and-path.slang`
16. The remapping is never baked into the line table, so a location resolves to the physical line or to the remapped line and path depending on which the consumer asks for. — `source-loc-line-directive-remaps-line-and-path.slang`

**`#versioning-and-backwards-compatibility`**

17. The whole payload carries a serialization version stamped at write time. — `module-info-name-version.slang`
18. `IRModule::m_version` is a second, unrelated number, never compared to anything, and is what `-get-module-info` prints as `Module Version`. — `module-info-name-version.slang`
19. `-get-supported-module-versions` prints the inclusive `[min, max]` window that bounds that module version. — `supported-module-versions.slang`

### B. Internal-source and C++-API facts

20. Most enum-valued AST fields get their `serialize(...)` overload from a FIDDLE template driven by one `enumTypeNames` list, delegating to `serializeEnum`, which encodes the value as a `FossilUInt`. — _untested: `internal-source-fact`_
21. A single `serialize(serializer, value)` template runs in both directions, distinguished by the `SerializationMode` carried on the serializer. — _untested: `needs-unit-test`_
22. Pointer fields work because the serializer maintains a graph of already-visited objects and emits / resolves identifiers for shared and circular references. — _untested: `needs-unit-test`_
23. `ISerializerImpl` is a specification rather than a required base class, and `Serializer<Backend, Context>` makes the common case dispatch statically. — _untested: `internal-source-fact`_
24. `SLANG_SERIALIZE_FOSSIL_ENABLE_VALIDATION_CHECKS` selects between `SLANG_UNEXPECTED("invalid format encountered in serialized data")` and a plain `SLANG_ASSERT` for every fossil validation failure. — _untested: `compile-time-toggle`_
25. The fossil format is designed for memory-mapped deserialization: a serialized pointer is a 32-bit offset relative to its own address, so the graph needs no pointer-fixup pass. — _untested: `implementation-detail`_
26. `writeSerializedModuleAST` / `writeSerializedModuleIR` each build a `Fossil::SerialWriter` over a `BlobBuilder` and hand the blob to `RIFF::BuildCursor::addDataChunk`. — _untested: `internal-source-fact`_
27. The container's chunk codes are `SerialBinary::kModuleFourCC`, `PropertyKeys<IRModule>::IRModule`, `PropertyKeys<Module>::ASTModule` and `PropertyKeys<Module>::FileDependencies`. — _untested: `requires-external-tool`_
28. The RIFF wrapping lets tools inspect a `.slang-module`'s partial structure without parsing the inner serialized content. — _untested: `requires-external-tool`_
29. A separate RIFF serializer backend in `slang-serialize-riff.{h,cpp}` was deleted because its only callers were branches of a hard-coded-off `USE_RIFF` switch. — _untested: `internal-source-fact`_
30. The module is flattened into the parallel `FlatInstTable` arrays, with one `operandIndices` list whose type-use slot comes first and whose `nullptr` is encoded as `-1`; the worked example for the constant `42` gives `[-1, -1, 1]`. — _untested: `internal-source-fact`_
31. `deserializeFromFlatModule` validates the flat tables with `SLANG_RELEASE_ASSERT` before dereferencing and checks full consumption plus an `IRModuleInst` root afterwards. — _untested: `needs-unit-test`_
32. The literal/string consumption check is skipped when `_foundUnrecognizedInstructions` is set, and `readSerializedModuleIR_` then returns `SLANG_FAIL` so the container layer sees an unloadable module rather than a crash. — _untested: `needs-unit-test`_
33. The write and read sides share `kMaxIRSerializationDepth` (512), asserted at every level so a deeply-nested module fails fast. — _untested: `needs-unit-test`_
34. The reader reconstructs each contributing file into a fresh `SourceManager` with `createSourceFileWithSize`, because the file's content is not serialized. — _untested: `internal-source-fact`_
35. An opcode is never written as its `kIROp_*` enum value; `getOpcodeStableName` / `getStableNameOpcode` convert through stable names. — _untested: `needs-unit-test`_
36. `readSerializedModuleIR_` compares `IRModuleInfo::serializationVersion` against `kSupportedSerializationVersion` and returns `SLANG_FAIL` on a mismatch. — _untested: `needs-unit-test`_
37. When `getStableNameOpcode` yields `kIROp_Invalid` the reader substitutes `kIROp_Unrecognized` and sets `_foundUnrecognizedInstructions`; `Unrecognized` must never survive past deserialization. — _untested: `needs-unit-test`_
38. The repro machinery captures a single `slangc` invocation as a serialized blob, with `-dump-repro` among the options not to use. — _untested: `deprecated`_
39. The "Adding a new serialized field" walkthrough: an AST field is picked up by FIDDLE with no serializer edit, while an IR change means altering the `FlatInstTable` schema and bumping the serialization version. — _untested: `process-doc`_
