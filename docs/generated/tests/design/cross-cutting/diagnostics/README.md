# Tests for design/cross-cutting/diagnostics

## Intent

This bundle exercises the diagnostic system described in
[`docs/generated/design/cross-cutting/diagnostics.md`](../../../../design/cross-cutting/diagnostics.md):
what a catalog entry is made of and how each of its pieces reaches the user
(code, severity name, interpolated parameters, primary span, companion and
variadic notes), how the sink turns a declared severity into the one actually
reported (per-source pragma state, per-id overrides, warning-group gating,
warnings-as-errors), how the shared integer id namespace behaves including its
deliberate exemptions, how a `SourceLoc` is decoded and rendered, and the two
rendering modes the sink offers.

The strategy is one test per verifiable claim, plus boundary probes on the axes
the doc itself names: the ends of the warning-state stack (`push` with no `pop`
and vice versa), the two ends of group gating (a group that is off by default
and one that is on), the two identifier kinds `-warnings-disable` accepts and
the two ways each can fail, the shared-code exemption, the first and last source
line of a file, and a location that lives only in a synthesized token-paste view.

Every claim here is resolved before code generation, so the tests use a single
directive rather than a per-target fan-out. `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):`
is used wherever the diagnostic itself has a caret position worth pinning;
`//TEST:SIMPLE(filecheck=CHECK):-target hlsl` is used where the observation is an
_absence_ (`CHECK-NOT`), where the diagnostic is locationless, or where the claim
hangs on a command-line option rather than on source text.
