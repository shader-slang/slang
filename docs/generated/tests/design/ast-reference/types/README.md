# Tests for design/ast-reference/types

## Intent

This bundle exercises the concrete `Type` subclasses catalogued in
[`docs/generated/design/ast-reference/types.md`](../../../../design/ast-reference/types.md) through their
**user-observable consequences** at type-resolution and
type-mismatch-diagnostic time. Slang never exposes its AST, so a claim
about a type class is testable only when program text would behave
differently if the claim were false: a `float4` value's four components
are readable, a `const int` refuses assignment, an `IA & IB` bound
rejects a type that conforms to only one of the two interfaces, a type
name written in value position reports `typeof(float)`, an undefined
identifier produces exactly one diagnostic instead of a cascade.

Coverage strategy is one observation per **user-spellable** type
family, plus a negative / diagnostic probe for every family with a
natural failure mode (vector and matrix shape mismatch, const write,
missing half of a conjunction, out parameter read before assignment,
ambiguous overload, cascade suppression), plus the numeric boundary
axes the arithmetic leaves imply (int MIN/MAX, unsigned wrap at 2^32,
a literal past every integer type, the smallest vector arity, the
unsized array extent). Type claims are resolved before any back end
runs, so `//TEST:INTERPRET` carries the value observations and
`//DIAGNOSTIC_TEST:SIMPLE` the rejection claims;
`//TEST:COMPARE_COMPUTE -cpu` stands in where the interpreter cannot
model the claim (unsigned wrap through a buffer, raw pointers,
`try` / `catch`, unsized-array counts). Emission directives are used
only for the type families whose surface form is target-specific: the
resource / buffer / texture families, `Atomic<T>`,
`DescriptorHandle<T>`, `SubpassInput<T>` and `String`.
[`rwstructuredbuffertype-multi-target.slang`](rwstructuredbuffertype-multi-target.slang)
is the bundle's canonical per-target lowering observation and fans out
across hlsl / glsl / spirv-asm / metal / wgsl / cuda / cpp.

## Sibling-bundle overlap

The `Decl` side that a decl-ref type references (`StructDecl`,
`InterfaceDecl`, `EnumDecl`, `TypeDefDecl`) belongs to
`design/ast-reference/declarations`; the type-expression **spellings**
(`PointerTypeExpr`, `FuncTypeExpr`, `TupleTypeExpr`, `AndTypeExpr`,
`ThisTypeExpr`, `ModifiedTypeExpr`) belong to
`design/ast-reference/expressions`; the IR-level type catalogue belongs
to `design/ir-reference/types`; and overload-resolution / implicit-cast
mechanics belong to `design/pipeline/03-semantic-check`. This bundle
stays at the AST type-checker surface — interpreter values, buffer
values and diagnostics — and cites those bundles rather than
duplicating their claims.
