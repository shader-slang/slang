# Tests for design/ast-reference/types

## Intent

This bundle exercises the concrete `Type` subclasses catalogued in
[`docs/generated/design/ast-reference/types.md`](../../../../design/ast-reference/types.md) through their
**user-observable consequences** at type-resolution and
type-mismatch-diagnostic time. Slang never exposes its AST, so a claim
about a type class is testable only when program text would behave
differently if the claim were false: a `float4` value's four components
are readable, a `const int` refuses assignment, an `IA & IB` bound
rejects a type that conforms to only one of the two interfaces, a type
name written in value position reports `typeof(float)`, an undefined
identifier produces exactly one diagnostic instead of a cascade.

Coverage strategy is one observation per **user-spellable** type
family, plus a negative / diagnostic probe for every family with a
natural failure mode (vector and matrix shape mismatch, const write,
missing half of a conjunction, out parameter read before assignment,
ambiguous overload, cascade suppression), plus the numeric boundary
axes the arithmetic leaves imply (int MIN/MAX, unsigned wrap at 2^32,
a literal past every integer type, the smallest vector arity, the
unsized array extent). Type claims are resolved before any back end
runs, so `//TEST:INTERPRET` carries the value observations and
`//DIAGNOSTIC_TEST:SIMPLE` the rejection claims;
`//TEST:COMPARE_COMPUTE -cpu` stands in where the interpreter cannot
model the claim (unsigned wrap through a buffer, raw pointers,
`try` / `catch`, unsized-array counts). Emission directives are used
only for the type families whose surface form is target-specific: the
resource / buffer / texture families, `Atomic<T>`,
`DescriptorHandle<T>`, `SubpassInput<T>` and `String`.
[`rwstructuredbuffertype-multi-target.slang`](rwstructuredbuffertype-multi-target.slang)
is the bundle's canonical per-target lowering observation and fans out
across hlsl / glsl / spirv-asm / metal / wgsl / cuda / cpp.

## Claims

Enumerated per [`_claims.md` §1](../../../_meta/prompts/_claims.md), grouped by
the document's own headings. The page is a catalogue of the compiler's own
`Type` classes, so the enumeration is split into the statements a compiled
program can reveal and the statements that are properties of the compiler's
headers only; the second group is carried in `## Untested claims` with reason
`internal-source-fact`.

**User-observable**

_`#nodes` (the class table, one claim per user-spellable row)_

1. `OverloadGroupType` is the pseudo-type of a reference to an overloaded name that lookup resolved to several candidates, and checking collapses it.
2. `InitializerListType` is the pseudo-type of an initializer-list expression such as `{ a, b }`, before it has been coerced to a target type.
3. `ErrorType` is the type of an expression that was erroneous, such as a use of an undeclared name.
4. `BottomType` is the bottom/empty type that has no values: the result type of a function that can never return and the error type of one that cannot fail.
5. `DeclRefType` is a type defined by reference to a declaration.
6. `TypeType` is the type _of_ a type expression: `float` in `float(2)` has type `TypeType(float)`.
7. `NamedExpressionType` is a `typedef` / `typealias` alias; it prints under the alias name, but `getCanonicalType()` resolves it away to the aliased type.
8. `FuncType` carries parameter types, then a result type, then an error type.
9. `BasicExpressionType` is a scalar built-in type — `int`, `uint`, `float`, `bool`, `void`.
10. `VectorExpressionType` carries an element type and an element count.
11. `MatrixExpressionType` carries an element type, a row count, a column count and a layout.
12. `ArrayExpressionType` is a sized or unsized array of elements.
13. `TupleType` is a `(T1, T2, ...)` tuple with a per-position member list.
14. `AtomicType` is `Atomic<T>`, the user-spellable wrapper over an `IAtomicable` element; its members are atomic intrinsics, so an update lowers to the target's atomic instruction rather than a load / modify / store.
15. `OptionalType` is `Optional<T>`.
16. `EnumTypeType` is the type of an `enum` type itself.
17. `PtrType` is the `T*` raw pointer.
18. `OutParamType`, `BorrowInOutParamType` and `RefParamType` are the `out T`, `inout T` and `ref T` parameter types.
19. `BorrowInParamType` is written `__constref` and printed as `borrow T`; it is an input-only counterpart of `inout`, not a `ref` mode.
20. `NullPtrType` is the type of `nullptr` and `NoneType` is the type of `none`.
21. `TextureType` is the HLSL-flavour sampled `Texture*<T>` and `SamplerStateType` is `SamplerState` / `SamplerComparisonState`.
22. `SubpassInputType` is the Vulkan subpass-input texture.
23. `DescriptorHandleType` is the bindless `DescriptorHandle<T>`.
24. The structured-buffer family (`StructuredBuffer`, `RWStructuredBuffer`, append / consume / rasterizer-ordered) and the byte-address family are separate types.
25. `ConstantBufferType`, `TextureBufferType` and `ParameterBlockType` are the uniform parameter groups, and the common base carries the data-layout argument.
26. The data-layout policy types name block-layout policies, and `ScalarDataLayoutType`'s GLSL emit requires `GL_EXT_scalar_block_layout`.
27. `StringType` is the Slang `String` type.
28. `ModifiedType` is a base type with modifiers applied.
29. `AndType` is the `T & U` conformance-conjunction type.
30. `ThisType` is synthesized by checking to represent the `This` self type of an interface or extension.

_`#declreftype`_

31. Almost every user-declared type the front end sees is a `DeclRefType`, carrying whatever generic substitutions the decl-ref itself encodes.
32. A core-module builtin declared with `__intrinsic_type(...)` alone gets no `Type` subclass and is simply a `DeclRefType` naming the core-module `struct`.

_`#basicexpressiontype-vectorexpressiontype-matrixexpressiontype`_

33. The arithmetic leaves are `DeclRefType` descendants because each is canonically introduced as a declaration in the core module.
34. Arithmetic is the target's native arithmetic at that width, so an unsigned add past the top of the range wraps: a `uint` holding `0xFFFFFFFF` plus `1u` is `0`.
35. For an unsuffixed decimal literal the front end picks the narrowest type that holds the value — `int`, then `int64`.
36. A decimal literal past the range of `int64` is diagnosed `IntegerLiteralTooLarge` instead of being truncated.

_`#errortype-and-bottomtype`_

37. `ErrorType` is the type of any expression that failed to check, so that downstream checking does not cascade.
38. Neither `ErrorType` nor `BottomType` declares operands, so hash-consing gives each exactly one instance per `ASTBuilder`.

_`#thistype-and-assoctypedecl`_

39. `ThisType` is a `DeclRefType` referencing the interface's synthetic `ThisTypeDecl`, which is what lets specialization treat `This` uniformly with concrete substitution.
40. An `AssocTypeDecl` has no dedicated `Type` class either, so `This.Foo` is an ordinary `DeclRefType` whose decl-ref reaches the `AssocTypeDecl` through the conformance witness.

_`#functype`_

41. The operand list is the parameter types followed by the result type and then the error type.
42. A parameter's qualifier is not stored beside its type — it _is_ part of the type, because each parameter operand is the user-perceived type wrapped in a parameter-mode type.
43. The error-type slot is always present rather than optional: a callable that cannot fail records the bottom type `Never` there.

_`#andtype`_

44. `T : IFoo & IBar` yields an `AndType` of the two interface types, so the checker tracks conjunctive conformance without a named composite interface.

_`#resource-and-texture-type-families`_

45. Each resource family is a first-class type because each requires distinct IR lowering and binding semantics on every backend.

_`#untypedresourcehandletype-and-untypedsamplerhandletype`_

46. `ResourceDescriptorHeap[i]` yields an `UntypedResourceHandle` and `SamplerDescriptorHeap[j]` yields an `UntypedSamplerHandle`; only those two result types are magic, the heap structs themselves are plain decl-ref types.
47. The surface is capability-gated on `[require(glsl_hlsl_spirv_wgsl, descriptor_handle)]`, so a heap subscript outside that target set is diagnosed, and the gate is repeated on the subscript so the diagnostic lands at the indexing site rather than inside the core module.
48. Each handle wraps a single `uint` heap index and is deliberately untyped: the concrete resource or sampler type is recovered from the target of the implicit conversion, and the resource and sampler families are kept disjoint.
49. Neither handle type survives to code emission — the handle is reduced back to its `uint` heap index during IR lowering.

_`#extractexistentialtype--existentialspecializedtype` / `#pack--variadic-type-family`_

50. `ExtractExistentialType` is the type seen after opening an existential and `ExistentialSpecializedType` is its specialized counterpart used during IR lowering.
51. The pack / variadic type family is mostly transient during checking; the specialization machinery collapses it once a pack's arity becomes known.

**Internal-source facts** (no user-observable consequence; carried in `## Untested claims`)

52. The C++ parent class of every `Type` and the abstract intermediates named under `## Family hierarchy`.
53. Types store their data in the generic `m_operands` list rather than named fields; `MatrixExpressionType`'s `rowType` and `ExtractExistentialType`'s two cached members are caches that are not part of the logical value and must not be serialized or hashed.
54. `Type` adds `getCanonicalType()` — a thin wrapper over `Val::resolve()` — and the `m_astBuilderForReflection` back-pointer that exists for the reflection API only.
55. `isDeclRefTypeOf<T>` is the helper to use rather than re-deriving the cast at a call site.
56. The parsed type grammar enters through `_parseSimpleTypeSpec`, `parsePostfixTypeSuffix`, `parseFuncTypeExpr`, `parseExpandExpr` and `parseEachExpr`.
57. Many classes are _magic types_: the C++ class carries the behaviour and the user-named declaration lives in the core module, bound by a `__magic_type(...)` attribute.
58. The GLSL-flavoured types, the geometry / tessellation / mesh IO types, the low-precision and cooperative leaves, the autodiff type family, and the marker interface types listed in the node table.

## Sibling-bundle overlap

The `Decl` side that a decl-ref type references (`StructDecl`,
`InterfaceDecl`, `EnumDecl`, `TypeDefDecl`) belongs to
`design/ast-reference/declarations`; the type-expression **spellings**
(`PointerTypeExpr`, `FuncTypeExpr`, `TupleTypeExpr`, `AndTypeExpr`,
`ThisTypeExpr`, `ModifiedTypeExpr`) belong to
`design/ast-reference/expressions`; the IR-level type catalogue belongs
to `design/ir-reference/types`; and overload-resolution / implicit-cast
mechanics belong to `design/pipeline/03-semantic-check`. This bundle
stays at the AST type-checker surface — interpreter values, buffer
values and diagnostics — and cites those bundles rather than
duplicating their claims.
