# Tests for design/ast-reference/modifiers

## Intent

This bundle exercises the concrete `Modifier` and `Attribute` subclasses
catalogued in
[`docs/generated/design/ast-reference/modifiers.md`](../../../../design/ast-reference/modifiers.md).

`slangc` never exposes its AST, so the bundle applies one translation rule
throughout: a row of the doc's node tables is testable only through the
**role** its Summary column states, never through the C++ class the parser
allocated. "`HLSLGroupSharedModifier` is the class behind `groupshared`"
becomes "a `groupshared` declaration is given workgroup-shared storage that
survives to the emitted code"; "`InOutModifier` derives from `OutModifier`"
becomes "an `inout` argument is both read and written back". Anything whose
only consequence is a C++ parent class, a private field name, or a
checker-internal marker is recorded under `## Untested claims` instead.

Coverage strategy is one representative test per modifier / attribute
**family**, plus a contrast or boundary probe wherever the doc names a pair
whose members must behave differently: `[ForceInline]` against `[noinline]`,
`[unroll]` against `[ForceUnroll]`, `row_major` against `column_major`,
`[open]` against `[sealed]`, `[Differentiable]` against
`[ForwardDifferentiable]`, and the permitted/rejected halves of `[NoDiscard]`,
`const`, `inout` and `[mutating]`. Observation style follows the claim:
`INTERPRET` for direction / mutability / visibility / enum-value semantics
that produce a runtime value, `COMPARE_COMPUTE -cpu` for the three claims the
interpreter cannot host (function-`static` storage, bitfield widths,
reverse-mode autodiff), `SIMPLE -target ...` on the target where the
modifier's spelling actually lives for emission claims, and `DIAGNOSTIC_TEST`
with a pinned `E####` code for the eight rejection claims. Per the
co-located `_prompt.md`, emission tests pick the one back end where the
documented spelling is observable rather than fanning out across all of them;
target-emit divergence is the subject of the `pipeline/06-emit` and
target-specific bundles, not this one.

Realignment notes for this revision of the source doc:

- `### Modifiers vs Attributes` gained a paragraph on the surface spellings
  `ParseSquareBracketAttributes` accepts -- the `[[a]]` group form, several
  attributes sharing one group, the optional comma, and `parseAttributeName`
  flattening a `::`-qualified name into one identifier. All of those are
  directly observable, so the bundle gained three tests for them.
- The `### Differentiable attribute family` subsection now states that plain
  `[Differentiable]` maps to `BackwardDifferentiableAttribute` and that only
  `[ForwardDifferentiable]` maps to the forward class. That asymmetry is
  observable as `bwd_diff` being available on the first and rejected on the
  second, so the bundle gained a matched positive/negative pair anchored to
  that subsection.
- `NoDiscardAttribute`, `FlagsAttribute`, `DeprecatedAttribute`,
  `UnscopedEnumAttribute` and `EnumClassModifier` rows are present in this
  revision; the first four are now covered, and the previous revision's
  "no diagnostic code can be pinned" row for `[NoDiscard]` is resolved -- the
  discarded-result error is `E30059`.
- The previous revision's `row-major-emits-on-hlsl.slang` asserted the token
  `row_major` in emitted GLSL, which the compiler prints unconditionally as
  `layout(row_major) uniform;` even with no matrix modifier in the source.
  That test passed vacuously and has been replaced by an HLSL pair that
  observes the storage-shape difference the modifier actually causes.

The bundle is 60 files, the manifest's `size_cap_files` for this key. The
doc's node tables enumerate several hundred classes, so the cap -- not the
claim list -- is what bounds the bundle; the families left over are listed
under `## Untested claims` with the reason each was deferred.
