# Tests for design/ast-reference/expressions

## Intent

This bundle exercises the concrete expression kinds catalogued in
[`docs/generated/design/ast-reference/expressions.md`](../../../../design/ast-reference/expressions.md) — the
`LiteralExpr` family, `VarExpr` / `MemberExpr` / `StaticMemberExpr` /
`DerefMemberExpr`, `InvokeExpr` and its operator and cast specializations,
`SwizzleExpr` / `MatrixSwizzleExpr`, `IndexExpr`, `AssignExpr`, `SelectExpr`,
the short-circuit logic form, `SizeOfExpr` / `AlignOfExpr` / `CountOfExpr`,
the `Is` / `As` / cast-to-supertype trio, `GenericAppExpr` and its
partially-applied form, `LambdaExpr`, the differentiate family, and the
type-expression family. Slang does not expose its AST, so each claim is
translated into the observable consequence of that expression kind: the value
it produces, the overload it selects, the emitted text it lowers to, or the
diagnostic it provokes. The strategy is one observable test per user-spellable
kind in the doc's `## Nodes` table, plus boundary probes on the axes the doc
names (integer and float literal edges, index 0 / N-1, single- and
repeated-component swizzles, zero- and many-argument calls) and one negative
test per natural rejection family. Value claims run on `INTERPRET` or
`COMPARE_COMPUTE -cpu`; the one genuinely target-divergent expression kind —
vector swizzle — plus the tuple, `new`, and matrix-swizzle forms fan out
across every feasible text-emit target. Nodes the doc marks as synthesized,
parser-internal, or without a construction site are recorded under
`## Untested claims` rather than probed.
