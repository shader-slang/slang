# Tests for design/ast-reference/values

## Intent

This bundle exercises the **non-Type** compile-time values catalogued in
[`docs/generated/design/ast-reference/values.md`](../../../../design/ast-reference/values.md):
the integer-value family (literal constants, generic value parameters,
casts between integer types, symbolic builtin operators, polynomials,
`sizeof` / `alignof` / `countof`, and the error placeholder), the
decl-ref family, the conformance-witness family, and the type-level
modifier values.

`slangc` never exposes its AST, so every test here is written against
the **observable consequence** of a claim rather than the claim's
internal shape. "This value folds once its operands are concrete"
becomes "the call type-checks against the folded array bound and the
runtime sum is what that bound implies". "This decl-ref is identified by
its argument list" becomes "two identical applications are mutually
assignable and two different ones are diagnosed". "This witness is the
proof of a conformance" becomes "the generic body can call the interface
method". Claims about hash-cons pointer identity, operand-slot indices,
abstract intermediates, and C++ parent classes are unobservable and are
recorded under `## Untested claims` instead.

The values are resolved entirely in the front end, so the coverage is
target-independent and `//TEST:INTERPRET` carries most of the bundle,
with `//DIAGNOSTIC_TEST:SIMPLE` for the rejection claims. Two claims are
exceptions and use emission directives: the resource-format modifier,
whose only user-visible surface is the emitted element-type spelling,
and the link-time integer value, which by definition is not resolved
until after semantic checking.

Realignment notes for this revision of the source doc:

- `### TypeEqualityWitness` is a new section, and it states that a
  declared equality constraint spelled `where T == U` is a _different_
  class from the identity proof, with `isEquality()` true. That is a
  user-spellable surface, so the bundle gained
  `typeequalitywitness-declared-equality-constraint.slang`.
- `### Substitution and the substitution cache` is new; the bundle
  gained `substitution-nested-generic-bound.slang` for the "rebuild the
  node from substituted operands" claim seen through a nested generic
  application.
- `### IntVal and why integer values are first-class Vals` now
  describes the link-time-value hooks and says that a polynomial
  propagates the property through its operands, which
  `linktimeintval-extern-const-polynomial-bound.slang` observes.
- The `CountOfIntVal` row now says the argument "is any `Val`, not only
  a type", and `AlignOfIntVal` and `TypeCastIntVal` are listed as
  distinct integer-value forms; each gained its own test.
- `### Subtype witnesses` now names "a `GenericTypeConstraintDecl` for a
  `where` clause" alongside `InheritanceDecl` as a source of declared
  conformance evidence, so the where-clause spelling gained a test.
- `### DeclRef family and the four shapes a decl-ref can take` states
  that a lookup decl-ref "carries a witness operand, so that
  specializing the generic value also specializes the lookup"; that is
  observable through an associated type named as `T.Elem`.

The bundle is 28 files, above the 8–15 range the co-located `_prompt.md`
names. That range was written against an earlier, terser revision of the
doc; this revision states more independently-observable claims (the
five bullets above), and the symbolic-builtin-operator section alone
commits to four operator shapes (`/`, `?:`, `&&` / `||`, enum operands)
plus a truncation boundary and a before-substitution unification case.
The count stays well under the manifest's `size_cap_files: 40`.
