# Tests for design/ast-reference/values

## Intent

This bundle exercises the **non-Type** compile-time values catalogued in
[`docs/generated/design/ast-reference/values.md`](../../../../design/ast-reference/values.md):
the integer-value family (literal constants, generic value parameters,
casts between integer types, symbolic builtin operators, polynomials,
`sizeof` / `alignof` / `countof`, and the error placeholder), the
decl-ref family, the conformance-witness family, and the type-level
modifier values.

`slangc` never exposes its AST, so every test here is written against
the **observable consequence** of a claim rather than the claim's
internal shape. "This value folds once its operands are concrete"
becomes "the call type-checks against the folded array bound and the
runtime sum is what that bound implies". "This decl-ref is identified by
its argument list" becomes "two identical applications are mutually
assignable and two different ones are diagnosed". "This witness is the
proof of a conformance" becomes "the generic body can call the interface
method". Claims about hash-cons pointer identity, operand-slot indices,
abstract intermediates, and C++ parent classes are unobservable and are
recorded under `## Untested claims` instead.

The values are resolved entirely in the front end, so the coverage is
target-independent and `//TEST:INTERPRET` carries most of the bundle,
with `//DIAGNOSTIC_TEST:SIMPLE` for the rejection claims. Two claims are
exceptions and use emission directives: the resource-format modifier,
whose only user-visible surface is the emitted texture type, and the
link-time integer value, which by definition is not resolved until
after semantic checking. Both fan out across the shader text targets.
The link-time bound is observable on all five (`hlsl`, `spirv-asm`,
`glsl`, `metal`, `wgsl`), because every one of them spells an array's
resolved extent. The modifier is observable only on the two targets
that have a syntax for a texture's format — HLSL's element spelling and
SPIR-V's image-format operand — so `glsl`, `metal` and `wgsl` are
accounted for as `unsupported-on-target` rather than pinned with a
CHECK that asserts the modifier's absence.

## Claims

Enumerated per [`_claims.md` §1](../../../_meta/prompts/_claims.md), grouped by
the document's own headings. This page is largely a catalogue of the
compiler's own `Val` class hierarchy — operand slots, parent classes,
hash-cons pointer identity — so the enumeration is split in two: the
statements a compiled program can reveal, and the statements that are
properties of the compiler's headers only. The second group is listed here
for completeness and carried in `## Untested claims` with reason
`internal-source-fact` or `implementation-detail`.

**User-observable**

_`#declref-family` / `#declref-family-and-the-four-shapes-a-decl-ref-can-take`_

1. `GenericAppDeclRef` and `LookupDeclRef` are the two shapes that add information beyond the path, and so the two that can make decl-refs to the same `Decl` denote different things.
2. A generic decl-ref is identified by its applied argument list, so two spellings with identical arguments denote one type.
3. The same generic decl applied to different arguments denotes distinct types.
4. A `LookupDeclRef` carries a witness operand, so specializing the generic value also specializes what the lookup resolves to.

_`#intval-family`_

5. `ConstantIntVal` is a literal compile-time integer.
6. `DeclRefIntVal` is an unsubstituted generic value parameter that only collapses to a constant after substitution.
7. `TypeCastIntVal` is an integer cast to a different integer type, spelled as a conversion in a compile-time position — e.g. the array bound `int[int(N)]` over a `let N : uint` parameter.
8. `BuiltinOperationIntVal` is a still-symbolic builtin operator (e.g. `N / 2`) that folds to a `ConstantIntVal` once its operands are concrete.
9. `SizeOfIntVal` is a compile-time `sizeof` of a type.
10. `AlignOfIntVal` is a compile-time `alignof` of a type.
11. `CountOfIntVal` is a compile-time `countof` whose argument is any `Val`, not only a type.
12. `WitnessLookupIntVal` is an integer resolved through a witness-table lookup, spelled `T.Name` for a `static const int` interface requirement read through a type parameter's conformance.
13. `PolynomialIntVal` is a polynomial in unsubstituted generic value parameters.
14. `ErrorIntVal` is the error placeholder that lets checking continue when an integer value cannot be computed.

_`#intval-and-why-integer-values-are-first-class-vals`_

15. Integer values appear in array sizes, generic value arguments, and `countof` / `sizeof` / `alignof` expressions, and some of those positions stay abstract until a generic is specialized.
16. A `DeclRefIntVal` whose referenced declaration carries `ExternModifier` reports itself as link-time, so it stays symbolic past semantic checking and is resolved from a mangled-name-to-value map at link time.
17. `TypeCastIntVal`, `BuiltinOperationIntVal`, and `PolynomialIntVal` propagate the link-time property through their operands.

_`#polynomialintval-and-polynomial-canonicalization`_

18. `2*N + 3` and `3 + 2*N` resolve to the same value, which is what gives dependent array types over those expressions one identity.
19. A polynomial factor's `param` is an `IntVal`, so a factor may be any compile-time integer rather than only a generic parameter.

_`#builtinoperationintval-and-the-single-representation-invariant`_

20. The same symbolic shape is used whether the expression was rewritten by the fast path or reached as a resolved operator call — `?:`, `&&`, `||`, or operators on enum / generic operands.
21. It re-evaluates on substitution and folds to a constant once its operands become concrete.
22. It is never constructed for `+`, `-`, `*`, or unary `-`: those are always a `PolynomialIntVal` so value unification can canonicalize them.

_`#witness-and-witness-table-evidence` / `#subtype-witnesses`_

23. Whenever the checker proves "`T : I`" it constructs a witness, which is what later stages consume; `DeclaredSubtypeWitness` is the proof carried by an `InheritanceDecl` on `T`.
24. A `GenericTypeConstraintDecl` for a `where` clause is the other in-scope declaration that reports declared conformance evidence.
25. `TransitiveSubtypeWitness` is the composition of two proofs along an inheritance chain.

_`#typeequalitywitness`_

26. A declared equality constraint such as `where T == U` yields a `DeclaredSubtypeWitness` whose `isEquality()` is true — a different class from the identity proof `TypeEqualityWitness`.

_`#modifier-values`_

27. Checking a `ModifiedTypeExpr` converts that expression's syntax-level modifiers into `Val`s, and the value ends up on the type, so it stays there for the rest of the compile and every later decision about that type sees it.
28. `unorm` / `snorm` mark a buffer or texture element type as backed by normalized data and do **not** change the semantics of a `float` or vector that carries the modifier.
29. How much of a `ResourceFormatModifierVal` survives into generated code is a per-target decision.
30. The modified element type is not interchangeable with the unmodified one: the core module's `__wgsl_check_texture_type` requires the texel type to be `float`, `int`, `uint` or a vector of one of them, and a `unorm`-modified element type fails that `static_assert` where the bare spelling passes.

_`#hash-consing-and-the-astbuilder` / `#substitution-and-the-substitution-cache`_

31. Two differently-spelled compile-time values compare equal exactly when they hash-cons to one node: inside a generic over `let N : int`, `int[2*N+3]` and `int[3+2*N]` are the same type and values of each are mutually assignable.
32. Substitution walks a `SubstitutionSet` and rebuilds the node from substituted operands.

**Internal-source facts** (no user-observable consequence; carried in `## Untested claims`)

33. Values carry their data as a generic `m_operands` list rather than per-class C++ fields, so the "Key fields" column names operand-slot semantics.
34. `IntVal`, `SizeOfLikeIntVal`, `ShapeTransformIntValPack`, `Witness`, `SubtypeWitness`, and `TypeCoercionWitness` are abstract intermediates.
35. The class-parent edges drawn in the family diagram.
36. `DirectDeclRef` holds a bare `Decl` operand and has nothing to substitute; `MemberDeclRef` is expressed relative to a parent decl-ref, and one whose path is known to be static folds back into a `DirectDeclRef`.
37. `SubtypeWitness` fixes operand slots 0 and 1 as `sub` and `sup`; the two differentiation witnesses are the exception.
38. `PolynomialIntValFactor` and `PolynomialIntValTerm` are `Val`s that are not `IntVal`s and appear only as operands of a `PolynomialIntVal`.
39. The pack integer values (`FirstIntVal`, `LastIntVal`, `ConcreteIntValPack`, `TrimFirstIntValPack`, `TrimLastIntValPack`, the four `Shape*IntValPack`s, `ExpandIntValPack`, `EachIntVal`) mirror the type-pack operators at the value level.
40. The pack subtype witnesses mirror the type-pack operators at the witness level, and a variadic pack's _count_ carries its own evidence (`DeclaredVariadicPackCountWitness` resolving into `ConcreteVariadicPackCountWitness`).
41. `ExtractExistentialSubtypeWitness` is manufactured when an existential value is opened.
42. `DynamicSubtypeWitness` is evidence that a `__Dynamic` type argument satisfies an existential type parameter.
43. `TypeEqualityWitness` is built through `SemanticsVisitor::createTypeEqualityWitness` for the self facet of a non-decl-ref type and for the extracted / projected types of an opened existential.
44. `BuiltinTypeCoercionWitness` and `DeclRefTypeCoercionWitness` are the coercion evidence for built-in and user-defined conversions.
45. `NoneWitness` is the "none" value of an optional constraint; `HasDiffTypeInfoWitness` is carried by a `HasDiffTypeInfoConstraintDecl`; `NonEmptyPackWitness` is evidence that a type pack is non-empty.
46. The `DifferentiateVal` family records how to differentiate a callable and is the one family on the page that is not hash-consed.
47. `UIntSetVal` is a hash-consed bitset used by the capability system.
48. Any two values built through `getOrCreate` with the same class and operand list are the same `Val*`, and `Val::equals` succeeds on identical pointers or identical `resolve()` results.
49. A `SubstitutionSet` carries a `SubstitutionCache*` that memoizes substitution results per `packExpansionIndex`.
