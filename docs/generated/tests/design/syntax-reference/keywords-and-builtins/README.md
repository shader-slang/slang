# Tests for design/syntax-reference/keywords-and-builtins

## Intent

This bundle exercises
[`docs/generated/design/syntax-reference/keywords-and-builtins.md`](../../../../design/syntax-reference/keywords-and-builtins.md),
whose central claim is that almost none of Slang's keywords are
lexer-level reserved words: they arrive as ordinary identifiers and
acquire meaning from the statement parser's direct lookahead, from a
`SyntaxParseInfo` entry in the parser's syntax table, or from a
declaration in one of the `*.meta.slang` core modules. A test here
therefore takes one documented keyword or built-in name and shows that
the identifier really is bound to the role the doc assigns it -- the
statement executes, the declaration produces a usable entity, the
modifier changes an observable outcome, the expression yields the
documented value, or the built-in name resolves to the documented type.

Coverage strategy: one functional test per keyword or keyword group the
doc names with a user-level surface; boundary probes along the axes the
doc's vocabulary implies (integer MIN / MAX, the largest documented
matrix, the `sizeof` / `alignof` / `countof` triad, the lower-edge
buffer index, `enum` values at the `int` extremes); negative tests for
the misuses the keywords' parsing rules forbid (`let` immutability
directly and through an `inout` argument, a generic built-in used
without its type argument, a type name reused as a value, a
descriptor-heap index on a target outside the availability gate); and
per-target emission fan-out wherever the keyword's consequence is only
visible in generated text. The overload-probe idiom (`int kind(int)` /
`int kind(uint)` / ...) is used throughout to prove that a name resolves
to the documented type, because a name bound to anything else changes
which overload wins. Target-independent parse and check behaviour runs
on `INTERPRET`; exception semantics run on `COMPARE_COMPUTE -cpu`
because the bytecode interpreter does not model them faithfully.

## Claims

Enumeration of the doc's testable claims, grouped by heading. Every
claim appears in the Functional coverage table or the Untested claims
table above -- and in both when the claim is an emission claim that
some text-emit target cannot express: the Functional row lists the
targets it is pinned on, and an `unsupported-on-target` Untested row
names the ones that reject or never spell the construct.

**`## Where keywords come from`**

1. Statement keywords are hardcoded in the statement parser, which inspects identifiers via `LookAheadToken("if")`, `LookAheadToken("for")`, and so on.
2. The `g_parseSyntaxEntries[]` table, registered into the default environment by `populateBaseLanguageModule()`, is the source of decl, modifier, and expression keywords.
3. The `*.meta.slang` core modules contribute built-in vocabulary rather than keywords: only a `SyntaxDecl` binding drives a parser callback, while a known type name participates in a few limited disambiguation decisions.

**`## Lexer-recognized keywords`**

4. The lexer does not recognize alphabetic keywords; only punctuation and operator spellings are lexer-level tokens.

**`## Parser-registered syntax keywords`**

5. Registered decl, modifier, and expression keywords can be redefined or extended through `syntax` / `attribute_syntax` declarations.

**`### Statement keywords`**

6. `if` and `else` are recognized by direct identifier comparison in the statement parser.
7. A second lookahead for `let` two tokens after `if` routes the statement to the `if let` binding form instead of the ordinary conditional.
8. `for` opens the counted-loop form at statement entry.
9. The compile-time `for` form is reached by reading a `$` and then checking for `for`.
10. `while` parses the head-tested loop and `do` the tail-tested loop.
11. `break` exits the enclosing loop.
12. `continue` skips to the next iteration.
13. `return` hands a value back to the caller and ends the function.
14. `switch`, `case`, and `default` form the multi-way dispatch statement.
15. `__target_switch` is dispatched at statement entry to `parseTargetSwitchStmt`.
16. `__stage_switch`, `__intrinsic_asm`, `__GPU_FOREACH`, and `__requireCapability` are compiler-internal statement keywords dispatched at statement entry.
17. `discard` is a statement keyword.
18. `defer` is a statement keyword.
19. `throw` is a statement keyword.
20. The statement-level exception handler is `do { ... } catch ( ... ) { ... }`; `catch` does not pair with `try` at statement level.
21. The `catch` error parameter is optional -- a bare `catch` catches every error type.
22. A chain of `catch` clauses nests, each `CatchStmt` becoming the `tryBody` of the next, rather than forming a flat list.
23. Control-flow keywords are not in the syntax-decl table and cannot be redefined by user code.

**`### Decl keywords`**

24. `typedef` parses a C-style type alias and `typealias` the Slang-style form.
25. `associatedtype` parses an interface associated type.
26. `__constraint` parses an interface-level constraint requirement and `__associatedfunc` an interface associated function.
27. `type_param`, `__generic`, and `__generic_value_param` parse the generic-parameter forms.
28. `extension` / `__extension` parse a type extension.
29. `__func_extension` parses the experimental custom-derivative function extension, gated by `-experimental-feature`.
30. `interface` parses an interface declaration.
31. `__init` parses a constructor and `__subscript` a subscript.
32. `property` parses a property, `semantic` an HLSL-style semantic decl, `cbuffer` a constant buffer, and `tbuffer` a texture buffer.
33. `syntax` and `attribute_syntax` parse user-defined syntax declarations.
34. `import` / `__import`, `__include`, `module`, and `implementing` parse the module-system declarations.
35. `let` parses an immutable binding and `var` a mutable one.
36. `func` parses the Slang-style function declaration.
37. `namespace` parses a namespace block and `using` a using directive.
38. `__ignored_block`, `__transparent_block`, `__file_decl`, and `__require_capability` are the remaining syntax-table decl keywords.
39. `struct`, `class`, and `enum` are not registered in `g_parseSyntaxEntries[]`; the type-specifier parser dispatches on them by direct identifier lookahead.
40. The same type-specifier parser recognizes the variadic-pack type forms `expand` and `each` by lookahead, alongside the shape utilities.
41. The same chain accepts `functype`, handing off to `parseFuncTypeExpr` to parse a function type; it too is matched by lookahead rather than registered as syntax.
42. Decl keywords beginning with `__` are intentionally namespaced as compiler-internal / non-stable.

**`### Modifier keywords` / `#### Simple modifiers`**

43. `in`, `out`, and `inout` are simple parameter-direction modifiers.
44. `static` and `const` are simple modifiers.
45. `public`, `private`, and `internal` are simple visibility modifiers.
46. `groupshared` is a simple storage modifier.
47. `dyn` is a simple modifier mapping to `DynModifier`.
48. The remaining simple-modifier rows (`__ref`, `__constref`, `__builtin`, the GLSL precision modifiers, `__global`, `inline`, `require`, `param`, `extern`, the layout modifiers, the interpolation modifiers, `uniform`, `export`, `dynamic_uniform`, `override`, the geometry-shader and mesh-shader modifiers, `__prefix` / `__postfix`, `__exported`) each map one keyword to one AST node class.

**`#### Callback-parsed modifiers (some take arguments)`**

49. `hitAttributeEXT` is parsed by `parseHitAttributeEXTModifier` for raytracing.
50. `shared`, `volatile`, `coherent`, `restrict`, `readonly`, `writeonly`, `layout`, and the `__`-prefixed target / intrinsic / magic-type modifiers are parsed by dedicated callbacks.

**`### Expression keywords`**

51. `this` is the self-reference expression.
52. `true` and `false` are the boolean literals.
53. `nullptr` is the null pointer literal.
54. `none` is `Optional`'s none literal.
55. `sizeof`, `alignof`, and `countof` are the size / alignment / element-count queries.
56. The remaining expression-keyword rows (`try`, `no_diff`, the differentiation family, `new`, `__apply`, `__return_val`, `__func_as_type`, `__dispatch_kernel`, the shape / pack utilities, `__getAddress`, `__floatAsInt`) are registered expression keywords with a named parse callback.

**`## Core-module syntax declarations`**

57. `core.meta.slang` declares the built-in scalar / vector / matrix types, `Optional` and `Tuple`, and core intrinsics.
58. `hlsl.meta.slang` layers in the HLSL-compatibility names (`Texture2D`, `RWTexture2D`, `StructuredBuffer`) and intrinsics such as `mul`, `dot`, and `length`.
59. `hlsl.meta.slang` also supplies the wave intrinsics, including `WaveGetWaveIndex` and the `SV_WaveIndex` / `SV_GroupIndex` builtins.
60. `hlsl.meta.slang` declares the descriptor-heap vocabulary -- `UntypedResourceHandle`, `UntypedSamplerHandle`, and the `__ResourceDescriptorHeapType` / `__SamplerDescriptorHeapType` types whose `__subscript` turns an index into a handle.
61. Each descriptor-heap subscript is gated by `[require(glsl_hlsl_spirv_wgsl, descriptor_handle)]`, so unsupported targets are diagnosed at the indexing site.
62. `glsl.meta.slang` provides the GLSL-flavored names (`vec3`, `mat4`, `gl_Position`).
63. `diff.meta.slang` contributes the differentiable-pair types and helpers used by the autodiff machinery.

**`## Reserved identifier prefixes`**

64. Names beginning with `__` denote compiler-internal vocabulary; a few have parser-registered public spellings without the underscores, while `__init`, `__subscript`, and `__include` have no underscore-free spelling in `g_parseSyntaxEntries[]`.
65. Names beginning with `gl_` come from the GLSL meta-module and stand for shader-stage built-ins.
66. Names beginning with `SV_` are HLSL system-value semantics recognized during semantic checking rather than as keywords.
67. The reserved set is not enforced lexically; it is policy encoded by the meta-modules.
