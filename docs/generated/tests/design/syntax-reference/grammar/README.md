# Tests for design/syntax-reference/grammar

## Intent

This bundle exercises the surface-grammar productions catalogued in
[`docs/generated/design/syntax-reference/grammar.md`](../../../../design/syntax-reference/grammar.md):
top-level/module structure, the declaration / statement / expression /
type / generic / modifier / attribute production families, the
HLSL-compatibility and user-defined-syntax declarations, the precedence
ladder, the literal-forms subsection, and the `<`-disambiguation fork.
The coverage strategy is one test per verifiable production (or per arm
of a production whose optional part changes the parse), plus a negative
test for each parse-stage or name-resolution rejection the doc names.

Grammar claims are resolved before any back-end sees the program, so
most tests are `pipeline_stage=parse` and use `//TEST:INTERPRET` — the
smallest body that prints a number distinguishing one bracketing or one
production arm from another. There is deliberately no per-target
`//TEST:SIMPLE` fan-out for those: identical pre-backend behaviour
repeated seven times adds no signal. Emission directives are used only
where the production is not observable on the interpreter: `-target
hlsl` for `cbuffer`, attribute placement and `__require_capability`,
and `-target spirv-asm` for the `vk::`-qualified attribute name.
Claims involving exceptions (`throws` / `do ... catch`), existential
`is` / `as`, pointers and `Optional` payload passing run on
`//TEST:COMPARE_COMPUTE ... -cpu`, because those features are
unreliable or unsupported under INTERPRET.

The bundle stays disjoint from
[`syntax-reference/tokens`](../tokens/) (purely lexer-level: token
kinds, literal spelling, trivia) and from `pipeline/02-parse-ast`
(parser-stage internals: two-stage parsing, speculative parse, AST node
construction). The angle here is **production shape** — which strings
the grammar names, and what shape they parse into.

## Claims

Enumerated per [`_claims.md` §1](../../../_meta/prompts/_claims.md), grouped by
the document's own headings. `D` names the source doc

**`#top-level-structure`**

1. `SourceFile ::= TopDecl* EOF`.
2. `ModuleHeader ::= 'module' (IDENT | STRING_LIT)? ';'` takes one name token, never dotted, and an omitted name means the current module.
3. `ModuleHeader` has a second alternative `'implementing' ModuleName ';'`.
4. `ModuleName ::= IDENT ('.' IDENT)* | STRING_LIT`, but only the `implementing` alternative and `ImportPath` reach the dotted form.
5. `TopDecl` covers `ImportDecl`, `ModuleHeader`, `NamespaceDecl`, `UsingDecl`, `FileDecl` and `Decl`.
6. `ImportDecl ::= ('import' | '__import') ImportPath ';'` and `'__include' ImportPath ';'`.
7. `ImportPath ::= IDENT ('.' IDENT)* | STRING_LIT`.
8. A string-literal module name or import path is not unescaped, so the backslash in `import "foo\bar";` stays literal instead of starting an escape.
9. `NamespaceDecl ::= 'namespace' IDENT (('.' | '::') IDENT)* '{' TopDecl* '}'`, looping over `.` / `::` to build a nested chain.
10. `UsingDecl ::= 'using' 'namespace'? Expr ';'`, where the entity is an arbitrary expression.
11. `FileDecl ::= '__file_decl' '{' TopDecl* '}'`.
12. `QualifiedName ::= '::'? IDENT ('::' NameOrSubscript)*`, and a leading `::` anchors lookup at module scope.
13. `NameOrSubscript` accepts `__subscript` as a static member name only when another `::` follows, rewriting it to the `SubscriptDecl`'s internal name; without the trailing `::` the identifier keeps its ordinary meaning.

**`#declarations`**

14. `Decl ::= ModifierList? CoreDecl`.
15. `CoreDecl` is dispatched by its leading keyword through `g_parseSyntaxEntries[]`, after `ParseModifiers` has consumed the modifier prefix.
16. `InternalDecl` registers the compiler-internal declaration keywords `__constraint`, `__associatedfunc`, `type_param`, `__generic_value_param`, `semantic`, `__ignored_block` and `__transparent_block` in that same dispatch table.

**`#type-defining-declarations`**

17. `TypedefDecl ::= 'typedef' Type Declarator ';'`, where the alias name is a full declarator.
18. `TypeAliasDecl ::= 'typealias' IDENT ('<' GenericParams '>')? WhereClause? '=' Type ';'`.
19. `StructDecl ::= 'struct' Attribute* IDENT? GenericParams? Inheritance? WhereClause? StructBody`.
20. `StructDecl` has a type-alias form `'struct' Attribute* IDENT? GenericParams? Inheritance? '=' Type ';'`.
21. `StructDecl` has a forward-declaration form `'struct' Attribute* IDENT? ';'` with `hasBody = false`.
22. `ClassDecl ::= 'class' IDENT Inheritance? StructBody`, with no generic params, no `where` clause and no forward form.
23. `StructBody ::= '{' StructMember* '}'`, and `StructMember` admits var, func, typedef, typealias, constructor, subscript, property and associated-type members.
24. `EnumDecl ::= 'enum' 'class'? IDENT? GenericParams? Inheritance? WhereClause? '{' (EnumCase (',' EnumCase)* ','?)? '}'`, and the body may be empty.
25. `EnumCase ::= IDENT ('=' ArgExpr)?`, the tag using `ArgExpr` so `,` stays a separator.
26. `InterfaceDecl ::= 'interface' IDENT GenericParams? Inheritance? WhereClause? '{' InterfaceMember* '}'`.
27. `ExtensionDecl ::= ('extension' | '__extension') ('<' GenericParams '>')? Type Inheritance? WhereClause? '{' StructMember* '}'`.
28. `AssocTypeDecl ::= 'associatedtype' IDENT (':' TypeList)? WhereClause? ';'`.
29. `InterfaceConstraintDecl ::= '__constraint' Type ('==' | ':') Type ';'`, where `==` is an equality constraint and `:` a subtype constraint.
30. `Inheritance ::= ':' TypeList`.
31. `struct`, `class` and `enum` are the three declaration keywords not registered in `g_parseSyntaxEntries[]`, which is why the name is optional and why the declaration can be followed by a declarator as in `struct Foo { int x; } foo;`.
32. The legacy `Attribute*` slot inside `'struct'` reports `DeprecatedBracketAttributesPlacement` from language version 2025 and `InvalidBracketAttributesPlacement` from 2026.
33. `associatedtype A : IBar`, `associatedtype A where A : IBar` and the standalone `__constraint` form all lower to the same `GenericTypeConstraintDecl` sibling requirement of the enclosing interface.
34. `__constraint` is valid only inside an interface body or a generic declaration.

**`#function-style-declarations`**

35. `FuncDecl ::= 'func' IDENT GenericParams? '(' ParamList? ')' ('throws' Type)? ('->' Type)? WhereClause? FuncBody`.
36. `FuncDecl` also has the context-sensitive C-style header `Type IDENT GenericParams? '(' ParamList? ')' ...`, where the leading `Type` is the return type.
37. `ConstructorDecl ::= '__init' GenericParams? '(' ParamList? ')' WhereClause? FuncBody`.
38. `SubscriptDecl ::= '__subscript' GenericParams? '(' ParamList? ')' '->' Type WhereClause? AccessorBlock`, routed through `parseOptGenericDecl` so it accepts inline generic params and a `where` clause.
39. `PropertyDecl ::= 'property' IDENT ':' Type AccessorBlock` in the modern form.
40. `PropertyDecl` also has the traditional C form `'property' Type Declarator AccessorBlock`.
41. `FuncExtensionDecl ::= '__func_extension' GenericParams? KeywordExprHead '(' ParamList? ')' ('throws' Type)? ('->' Type)? WhereClause? FuncBody`, gated behind `-experimental-feature`.
42. `ParamList ::= Param (',' Param)*`.
43. `ParamList ::= 'void'` is the C-compatibility spelling of an empty list, accepted only as the sole content of the parentheses.
44. `Param` has the traditional type-first form `ModifierList? Type IDENT ('=' ArgExpr)?`.
45. `Param` has the modern name-first form `ModifierList? IDENT (':' Type)? ('=' ArgExpr)?`, in which the `':' Type` is optional.
46. `FuncBody ::= ';'` for a prototype, or `'{' BodyTokens '}'` captured as an `UnparsedStmt` in stage 1.
47. `AccessorBlock ::= ';' | '{' AccessorDecl* '}'`, and an omitted block is treated as `{ get; }`.
48. `AccessorDecl ::= ModifierList? AccessorName ('(' ParamList? ')')? FuncBody`, the parameter list being parsed for any accessor because it is how `set` names the new value.
49. `AccessorName ::= 'get' | 'set' | 'ref'`, and any other accessor name is diagnosed.
50. `WhereClause ::= ('where' WhereTerm)+`, with `WhereTerm` covering the conformance list, equality, `nonempty(...)`, `countof(...) == ...`, `__hasDiffTypeInfo(...)` and type-coercion forms.

**`#variable--binding-declarations`**

51. `VarDecl ::= 'var' IDENT (':' Type)? ('=' ArgExpr)? ';'`.
52. `VarDecl` also has the context-sensitive C-style form `Type VarDeclarator (',' VarDeclarator)* ';'`.
53. `LetDecl ::= 'let' IDENT (':' Type)? ('=' ArgExpr)? ';'`, in which the `=` is parser-optional.
54. `ArraySuffix ::= '[' Expr? ']' ArraySuffix?`.
55. `Declarator ::= '*'? (DeclaratorName | '(' Declarator ')') ArraySuffix?` is the shared C-style name-plus-suffix grammar used by variables, parameters, `typedef`, `property` and functions alike.
56. `typedef int arr[2];` and `typedef int* p;` parse, with the trailing array suffix and the prefix `*` folded onto the alias type exactly as for a variable declaration.
57. `DeclaratorName ::= IDENT | 'operator' OperatorName`, where the `operator` form is legal only for a function.
58. `OperatorName ::= Operator | ',' | '=' | '(' ')' | '?' ':'` — one operator token or one of those three multi-token spellings.
59. `UnwrapDeclarator` diagnoses `OperatorNameOnNonFunction` unless the caller passes `allowOperatorName`, which only the function branch of `ParseDeclaratorDecl` does.

**`#hlsl-compatibility-declarations`**

60. `CBufferDecl ::= 'cbuffer' IDENT (':' Register)? '{' StructMember* '}'`.
61. `TBufferDecl ::= 'tbuffer' IDENT (':' Register)? '{' StructMember* '}'`.
62. `Register ::= 'register' '(' RegToken ')'`.

**`#user-defined-syntax`**

63. `SyntaxDecl ::= 'syntax' IDENT (':' IDENT)? ('=' IDENT)? ';'`, the `:` clause naming the AST node class and the `=` clause an existing keyword to alias.
64. `AttributeSyntaxDecl ::= 'attribute_syntax' '[' IDENT AttributeParams? ']' ':' IDENT ';'`, with no `=` alias form for attributes.
65. The `':'` clause of both is resolved by `astBuilder->findSyntaxClass`, so it names the compiler's own AST node classes rather than types declared in the program.
66. `RequireCapabilityDecl ::= '__require_capability' CapabilityName ';'` — no parentheses and exactly one atom.
67. A `CapabilityName` that `findCapabilityName` does not know is reported as `UnknownCapability`.
68. The single-atom restriction follows from `AdvanceIf(parser, "+")` / `AdvanceIf(parser, ",")` matching only an identifier token, so `__require_capability a + b;` fails at the following mandatory `';'`.

**`#statements`**

69. `Stmt` covers block, if, if-let, for, while, do-while, do-catch, switch/case/default, break, continue, return, discard, defer, throw, label, compile-time-for, require-capability, internal, decl, expression and empty statements.
70. `Block ::= '{' Stmt* '}'`.
71. `IfStmt ::= 'if' '(' Expr ')' Stmt ('else' Stmt)?`.
72. `IfLetStmt ::= 'if' '(' 'let' IDENT '=' Expr ')' Stmt ('else' Stmt)?`, selected when `let` is two tokens after `if`.
73. `ForStmt ::= 'for' '(' (DeclStmt | ExprStmt | ';') Expr? ';' Expr? ')' Stmt`.
74. `WhileStmt ::= 'while' '(' Expr ')' Stmt`.
75. `DoWhileStmt ::= 'do' Stmt 'while' '(' Expr ')' ';'`.
76. `DoCatchStmt ::= 'do' Stmt ('catch' ('(' Param ')')? Stmt)+`, where chained catches nest.
77. `SwitchStmt ::= 'switch' '(' Expr ')' '{' SwitchCase* '}'` with `SwitchCase ::= ('case' Expr ':' | 'default' ':') Stmt*`.
78. `BreakStmt ::= 'break' IDENT? ';'`.
79. `ContinueStmt ::= 'continue' ';'`, with no optional label unlike `BreakStmt`.
80. `ReturnStmt ::= 'return' Expr? ';'`.
81. `DiscardStmt ::= 'discard' ';'`.
82. `DeferStmt ::= 'defer' Stmt`.
83. `ThrowStmt ::= 'throw' Expr ';'`, where the `';'` is mandatory.
84. `LabelStmt ::= IDENT ':' Stmt`, chosen when an identifier is followed by `:`, and it is the label `BreakStmt` refers to.
85. `CompileTimeForStmt ::= '$' 'for' '(' IDENT 'in' 'Range' '(' Expr (',' Expr)? ')' ')' Stmt`, where `Range` is a required literal keyword and one argument means `Range(end)`.
86. `RequireCapabilityStmt ::= '__requireCapability' '(' CapabilityName (',' CapabilityName)* ')' ';'` is the only spelling that can name several atoms at once.
87. `DeclStmt ::= Decl`, `ExprStmt ::= Expr ';'` and `EmptyStmt ::= ';'`.
88. `InternalStmt` covers `__target_switch`, `__stage_switch`, `__intrinsic_asm` and `__GPU_FOREACH`, matched by direct identifier lookahead.
89. A `try` at statement position is routed to `ParseExpressionStatement` because `try` is an expression keyword; there is no `try { ... } catch { ... }` statement.

**`#expressions`**

90. The precedence ladder runs from atoms (level 0) through postfix, unary, `*` `/` `%`, `+` `-`, shifts, relational plus `is` / `as`, equality, `&`, `^`, `|`, `&&`, `||`, ternary and assignment to the comma operator (level 15).
91. Levels 2, 13 and 14 are right-associative; levels 1, 3–12 and 15 are left-associative.
92. `Parser::ParseExpression` defaults to `Precedence::Comma`, so a full expression admits the comma operator, while `ParseArgExpr` and `ParseInitExpr` pass `Precedence::Assignment` so a `,` terminates the operand instead — which is what lets `ArgList` and `InitList` use `,` as a separator.
93. The expression non-terminals `Expr`, `CommaExpr`, `ArgExpr`, `AssignExpr`, `TernaryExpr`, `LogicalOrExpr`, `LogicalAndExpr`, `BitOrExpr`, `BitXorExpr`, `BitAndExpr`, `EqualityExpr`, `RelationalExpr`, `ShiftExpr`, `AddExpr`, `MulExpr`, `UnaryExpr` and `PostfixExpr` mirror that ladder.
94. `is` and `as` are special-cased identifier operators whose right operand is parsed as a `Type`, not a general expression.
95. `UnaryOp ::= '+' | '-' | '!' | '~' | '++' | '--' | '*' | '&'`.
96. `PostfixSuffix` covers the call `'(' ArgList? ')'`, the subscript `'[' ArgList? ']'` with zero or more operands, `'.'` / `'->'` member access, `'::' NameOrSubscript`, postfix `++` / `--`, and generic specialization.
97. `AtomExpr` covers `Literal`, `QualifiedName`, a parenthesized expression, a C-style cast `'(' Type ')' UnaryExpr`, the empty tuple, the tuple form, `InitListExpr`, `KeywordExpr`, `LambdaExpr`, `NewExpr` and `SpirvAsmExpr`.
98. The empty tuple `'(' ')'` and the tuple `'(' ArgExpr (',' ArgExpr)+ ')'` are Slang 2026 and later.
99. `KeywordExpr` covers `this`, `try`, `no_diff`, `fwd_diff` / `__fwd_diff`, `bwd_diff` / `__bwd_diff`, `__apply`, `sizeof`, `alignof`, `countof`, `__dispatch_kernel`, `__getAddress` and `__floatAsInt`.
100. `sizeof` and `alignof` take `'(' ArgExpr (',' ArgExpr)? ')'`, the operand being an expression and the optional second argument selecting a data layout.
101. `LambdaExpr ::= '(' ParamList? ')' '=>' (Block | ArgExpr)`, with no bare-identifier form and traditional `ParseParameter` syntax for the parameters.
102. `NewExpr ::= 'new' Type ('(' ArgList? ')')?`.
103. `Literal ::= INT_LIT | FLOAT_LIT | STRING_LIT+ | CHAR_LIT | 'true' | 'false' | 'nullptr' | 'none'`.
104. `InitListExpr ::= '{' (ArgExpr (',' ArgExpr)* ','?)? '}'`.
105. `AssignOp ::= '=' | '+=' | '-=' | '*=' | '/=' | '%=' | '<<=' | '>>=' | '&=' | '|=' | '^='`.
106. The value a `LambdaExpr` produces is consumed through the `IFunc` interface, whose requirement is `TR operator()(expand each TP p)`.

**`#literal-forms-vs-token-kinds`**

107. `true`, `false`, `nullptr` and `none` have no dedicated token kind: the lexer emits them as `Identifier` and the parser recognises them through the keyword syntax-decl table.
108. `CHAR_LIT` lowers to an `IntegerLiteralExpr` with `suffixType` `BaseType::UInt` rather than a dedicated character-literal node.
109. `STRING_LIT+` is not a typo: adjacent string-literal tokens are concatenated into a single `StringLiteralExpr`, so `"a" "b"` is one literal.
110. A numeric literal's suffix stays part of its token text, so there is no syntactic distinction between a `half`, `float` and `double` literal.

**`#-disambiguation`**

111. `tryParseGenericApp` speculatively parses `<...>` as a generic argument list and, on success, treats the `<` as a generic application only when the token after the matching `>` is in the generic-followers set (`::`, `.`, `(`, `)`, `[`, `]`, `:`, `,`, `?`, `;`, `==`, `!=`, `>`, `>>`, end-of-file).
112. In body-parse mode the semantic visitor is the primary signal: a base that resolves to a `GenericDecl`, a function, or a type is a generic application, and anything else is a comparison.
113. While `genericDepth` is non-zero, `GetOpLevel` returns `Precedence::Invalid` for `>`, `>=` and `>>`, so those tokens cannot be consumed as operators and stay available to close the argument list.
114. `<`, `<=` and the rest keep their normal precedence inside a generic argument list, which is why a comparison such as `A<(x > y)>` needs the parentheses.

**`#modifiers`**

115. `ModifierList ::= (Modifier | Attribute)+`.
116. `Modifier` is either a `BareModifierKeyword`, which takes no further tokens, or a `TailModifierKeyword` with a `ModifierTail`.
117. The `BareModifierKeyword` inventory runs from `in` / `out` / `inout` through the interpolation, geometry, mesh, access-qualifier and `__`-prefixed keywords.
118. The `TailModifierKeyword` inventory requires a tail for most entries and leaves it optional for four.
119. `shared`, `volatile`, `coherent`, `restrict`, `readonly`, `writeonly` and `hitAttributeEXT` have a parse callback only to choose between HLSL and GLSL modifier nodes or to report a deprecation, and read nothing after the keyword.
120. A `ModifierTail` is not an `ArgList`: each modifier reads a fixed token shape of its own, such as an identifier, an integer literal, a version literal, a target name, a magic-type name or a GLSL qualifier list.

**`#attributes-and-decorations`**

121. `Attribute ::= '[' AttributeBody (','? AttributeBody)* ']'`.
122. `Attribute` also accepts the C++-style double-bracket spelling `'[[' AttributeBody (','? AttributeBody)* ']]'`.
123. `AttributeBody ::= AttributeName ('(' ArgList? ')')?` and `ArgList ::= ArgExpr (',' ArgExpr)*`.
124. `AttributeName ::= '::'? IDENT ('::' IDENT)*`.
125. The bracket form is identical to a keyword modifier in the AST representation, flowing through the same `Modifier` chain as `UncheckedAttribute` nodes.
126. Several attributes may share one bracket and the separating comma is optional, so `[a b]` and `[a, b]` parse the same way.
127. `parseAttributeName` flattens a `::`-qualified name into a single synthetic `Identifier` by replacing each `::` with `_`, and a leading `::` becomes a leading `_`, so `[vk::binding(0)]` looks up `vk_binding` and `[::foo]` looks up `_foo`.

**`#generics-and-where-clauses`**

128. `GenericDecl ::= '__generic' '<' GenericParams '>' Decl`, and the same parameter list may also appear inline on `FuncDecl`, `StructDecl`, `InterfaceDecl`, `ExtensionDecl` and `TypeAliasDecl`.
129. `GenericParams ::= GenericParam (',' GenericParam)*`.
130. `GenericParam` accepts the type-parameter form `'typename'? IDENT (':' Type)? ('=' Type)?`.
131. `GenericParam` accepts the value form `'let' IDENT (':' Type)? ('=' Expr)?`.
132. `GenericParam` accepts the value-pack form `'let' 'each' IDENT (':' Type)?`.
133. `GenericParam` accepts the type-pack form `'each' IDENT (':' Type)?`.
134. `GenericParam` accepts the traditional type-first value form `'each'? Type IDENT ('=' Expr)?`, as in `<int N>`.
135. `GenericParam` accepts the function-type form `'functype' IDENT (':' Type)?`.
136. The type-parameter and traditional value forms are distinguished by two-token lookahead — an identifier followed by `:`, `,`, `>` or `=` is a type parameter — and writing `typename` forces the type reading; the same lookahead minus `=` decides whether `each` introduces a type pack or a value pack.
137. The `:` constraint on a generic parameter takes a single supertype, unlike the where-clause `:` form which accepts a comma-separated list.
138. Each `where` keyword introduces exactly one `WhereTerm`, so several constraints repeat the keyword.
139. A leading `optional` modifier is accepted on every term except `__hasDiffTypeInfo`.
140. The `countof(Pack) == IntExpr` form is oriented: the reversed spelling `N == countof(Pack)` is recognized only to emit `VariadicPackCountConstraintRequiresCountofOnLeft`, and the rest of that `where` clause is then skipped.
141. Where-clauses appear after the parameter list — or after the result clause for function-style declarations — and are syntactically optional on every kind of generic declaration.

**`#types`**

142. `Type ::= ModifierList? CoreType`.
143. `CoreType ::= QualifiedName (GenericArgs | '.' IDENT)*`, with the suffixes interleaving.
144. `CoreType '&' CoreType` is the infix conjunction form (`AndTypeExpr`).
145. `Type '[' Expr? ']'` is the array form.
146. `Type '*'` is the pointer-to-`T` form.
147. `'functype' '(' Type (',' Type)* ')' '->' Type` is the function-type form.
148. `'__func_as_type' ...` is the function-as-type reflection form.
149. A `StructDecl`, `ClassDecl` or `EnumDecl` may appear inline as a type specifier, as in `struct Foo { int x; } foo;`.
150. `'each' Type` and `'expand' Type` are pack types, parsed as prefix expressions.
151. `GenericArgs ::= '<' GenericArg (',' GenericArg)* '>'` and `GenericArg ::= Type | Expr`, the ambiguity being resolved at check time.
152. Built-in concrete type names such as `int`, `vector<T,N>` and `Texture2D<T>` are not part of the grammar; they are identifiers brought into scope by the meta-modules.

**`#constraints-solved-at-check-time`**

153. The grammar intentionally accepts strings the parser builds into an AST that the semantic checker later rejects — the `Type Identifier` function-vs-variable ambiguity, names resolving to neither a type nor a function, and comparison-shaped generic argument lists.
