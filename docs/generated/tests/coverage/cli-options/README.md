# Tests for coverage/cli-options

White-box characterization tests targeting under-exercised command-line option
handling in `source/slang/slang-options.cpp` (61.21% line-covered by master's
hand-written suite plus the whole generated suite, measured 2026-08-05). These pin
the compiler's _current observed behaviour_ (not a spec). The bundle is
gap-selected, so the white-box target is named in each test's `//META: covers=`
field rather than by a `doc_ref`; the older tests still carry a `doc_ref` into the
LLM-derived design docs for orientation only — the authority for this tree is the
source, per [`coverage/METHODOLOGY.md`](../METHODOLOGY.md).

## Intent

Drive slangc CLI flags through `slangc` and pin the _observable difference_ each
flag makes. Wherever a flag has a delta, the test pairs a flag run against a
no-flag (default) run under distinct FileCheck prefixes so the option is the sole
cause of the observed difference, and the CHECK token is copied verbatim from a
real `slangc` run.

The first generation covered the flags visible in emitted shader text: matrix
layout, `#line` mode, `-fvk-use-entrypoint-name`, `-fvk-invert-y`,
`-fvk-bind-globals`, plus four option-parse error paths.

This generation went after the rest of `OptionsParser::_parse`, which is where
almost all of the remaining uncovered lines live — roughly a hundred and forty
`case OptionKind::` arms, most of them never entered by any shipped test. The
tests added here fall into four groups:

- **Flags with a codegen delta** — `-disable-short-circuit`, `-fvk-use-c-layout`,
  `-fvk-t-shift`, `-specialize`, `-enable-effect-annotations`, `-pass-through`,
  `-emit-spirv-via-glsl`, `-trace-coverage-binding`,
  `-trace-coverage-reserved-space`, `-source-embed-name`, `-no-codegen`.
- **Flags whose only observable is a report on stderr** — `-dump-module`,
  `-dump-warning-diagnostics`, `-get-supported-module-versions`, `-v`,
  `-<compiler>-version`.
- **Operand-validation error paths** — `-default-downstream-compiler`,
  `-source-embed-language`, `-file-system`, `-get-module-info`,
  `-diagnostic-color`.
- **Flags whose only handle is "the value parses and the compile is unaffected"**
  — the three `-file-system` hooks and the `-Wall`/`-Wpedantic` groups. These are
  weaker than a delta and are labelled as such in their test comments; they exist
  to hold the parse arm, not to assert behaviour.

Command-line diagnostics are attached to the synthetic command line (source
"line 0"), so a position/caret-anchored annotation cannot bind to them; they are
pinned by error code and message text instead.
