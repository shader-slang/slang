# Tests for coverage/type-layout

## Intent

White-box characterization tests for `source/slang/slang-type-layout.cpp`. They
pin the **current observed byte offsets, strides, register/space assignments and
layout-rule selections** that file produces, not a spec.

The bundle has two layers. The original five tests pick struct/array/matrix
shapes whose layout _diverges across layout-rule sets_ — std140
(`ConstantBuffer`) vs std430 (`RWStructuredBuffer`), the HLSL constant-buffer
tail-packing rules (`-fvk-use-dx-layout`), scalar layout
(`-force-glsl-scalar-layout`), push constant vs `ParameterBlock` — so a single
shader exercises two rule arms at once, and pin each arm's distinguishing
offset/stride/decoration verbatim.

The 2026-08-05 deepening pass targets the arms that neither the hand-written
`tests/` suite nor the rest of the generated suite reaches at all: the
AoS-to-SoA adjustment for arrays of resource-bearing structs, the
`SubElementRegisterSpace` handling for unbounded resource arrays, the
`DescriptorHandle` varying-parameter path and its four per-target overrides,
the `-fvk-*-shift` mapping from HLSL register kinds onto Vulkan bindings, the
`Optional<T>` niche-vs-tuple split, and the `_createTypeLayout` arms for
`class`, `type_param`, `__DynamicResource`, `RasterizerOrderedStructuredBuffer`
and explicit `ConstantBuffer<T, Layout>` layout arguments. That pass moves the
file from 67.10% to 75.19% line coverage (1142 -> 861 uncovered lines) as
measured against the same instrumented build.

Observation points, in order of preference: SPIR-V assembly emit
(`-target spirv-asm`) where layout materializes as `OpMemberDecorate ... Offset
N`, `OpDecorate ... ArrayStride/Binding/DescriptorSet/Location` and the emitted
`S_std140` / `S_std430` / `S_natural` type-name suffix that names the selected
rule set; HLSL emit where D3D register/space allocation is visible as
`register(tN, spaceM)`; and CUDA / Metal / C++ emit where a target-specific
object-layout arm shows up as the concrete member type of the generated
parameter struct.

All offsets, strides, registers, spaces, bindings and diagnostic texts were
copied verbatim from the local `slangc` at `source_commit`; every shader
compiles and every test passes locally. The observed layouts match the
std140 / std430 / D3D constant-buffer / scalar rules these code paths implement
and the inline source comments (notably the `float3 a[2]; float b;`
tail-packing example in `HLSLConstantBufferLayoutRulesImpl` and the `(T, bool)`
ordering note in the `OptionalType` arm), so none carry
`characterization-unverified=true`.
