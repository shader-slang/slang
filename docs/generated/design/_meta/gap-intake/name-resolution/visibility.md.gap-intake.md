# Gap-intake report for name-resolution/visibility.md

## Summary

No gap was escalated: every observation in the queue is what the
watched sources say, so all eight are documentation defects. Three of
them (`0c9178b9df46`, `583a43f2ddbc`, `a0476bc4c2a8`) are one
underlying rule — `checkVisibility`'s `PrivateModifier` arm tests
`isGlobalDecl` first and returns
(`source/slang/slang-check-modifier.cpp:2188-2216`), and `isGlobalDecl`
is true for anything whose parent is a `NamespaceDeclBase` or
`FileDecl` (`source/slang/slang-check-decl.cpp:1567-1575`) — so
`private` requires membership in a _type_, not merely a container, and
`private namespace X` never reaches the 36005 path. That rule is now
stated once in `### Per-keyword semantics` and once in the two
rewritten failure-mode bullets. The remaining five gaps were fixed
individually: function-local visibility classification, the `extern`
lookup-mask example, the `ExpectedANamespace` code and example, the
`FuncAliasDecl` surface syntax, and the extension target-type
asymmetry. All eight are `fixed`; there are no rejections, deferrals,
or escalations, and no unwatched-source blockers.
